# Bench suites

`fastapi-families.json` and `smoke.json` are generated, not written by hand. They are derived from the
[JevLoop](https://github.com/parkavenue9639/jevloop) reference repository. `read-heavy.json` is not:
see the `read-heavy.json` section below.

## Files

- `fastapi-families.json`: the output of `suite_payload()` in `backend/benchmarks/fastapi_families.py`,
  unchanged except for the added `source` record. Three scenarios (observation reuse, generation,
  mixed), 20 turns in total, with Chinese goals, seed files (`inject_files`) and executable probes
  that print a unique marker.
- `smoke.json`: the six scenarios of `backend/benchmarks/scenarios.json` (English goals).
- `read-heavy.json`: written for this bench, not ported from the reference repository. Two read-heavy
  scenarios of thirteen turns over seeded workspaces; generated by `make-read-heavy.mjs`.

## read-heavy.json

This suite was authored for this bench; nothing in it comes from the reference repository, and it
has no `source` record. `make-read-heavy.mjs` builds it from the tables in that script: the seed
files, the goals, the answers (counts and other answers are read out of the seed files) and the
probes. The first turn of each scenario writes the seed files; one later turn replaces one of them,
as a teammate's change, and the probes of that turn and the later ones expect the new content.
Every probe:

- checks that the files outside `notes/` are exactly the seed files (hidden entries and
  `__pycache__` are not counted), so a file created in a reading turn fails it;
- recomputes one SHA-256 over all seed files (name and bytes) to check that none changed;
- runs the turn's own check; in the write turn, the new file's non-empty lines, without list bullets,
  backticks, directories and a `.py` or `.md` suffix, must be exactly the expected names;
- prints `READ_HEAVY_<CODE|DOCS>_T<turn>_OK`; `<turn>` starts at 1.

The workspace is not seeded again between turns, so a seed file changed or a file added in one turn
also fails the probes of every later turn of that scenario. Do not edit the JSON by hand; change the
script and regenerate:

```sh
node packages/loop-jev/bench/suites/make-read-heavy.mjs
pnpm exec biome format --write packages/loop-jev/bench/suites/read-heavy.json
```

## Rewrite rules for `smoke.json`

The reference checks the workspace files from inside its own harness. Here every file check becomes a
`python -B -c` probe in `bash`, run in the session workspace after the turn:

- `files`: a file whose relative path contains `name` (case-insensitive) exists and, when `contains` is
  given, at least one such file contains it (case-insensitive).
- `any_file_contains`: one of the first 40 files contains the text (case-insensitive).
- `min_files`: at least that many files exist.
- Hidden files and directories (names starting with `.`) are not counted.
- A probe prints `SMOKE_<SCENARIO>_T<turn>_<n>_OK` on success and exits non-zero otherwise; `<turn>` and
  `<n>` start at 1.
- A probe whose check name contains a fragment listed in the reference `soft` array gets `soft: true`
  and does not count towards the hard checks.
- `goal`, `answer_contains` and `answer_max_chars` are kept as they are.

## Regenerating

Do not edit the two exported JSON files by hand. To change them, change `../export-suites.py` and
export again from a checkout of the reference repository:

```sh
python3 -I packages/loop-jev/bench/export-suites.py <reference-repo-root> packages/loop-jev/bench/suites
```

The repository formatter collapses short arrays, so format the output afterwards. The content stays the
same; only the whitespace changes:

```sh
pnpm exec biome format --write packages/loop-jev/bench/suites
```
