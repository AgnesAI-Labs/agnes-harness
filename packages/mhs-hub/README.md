# Agnes MHS Hub (preview)

[简体中文](README.zh-CN.md)

`@agnes/mhs-hub` owns device connectivity and physical integration semantics. `South` is a loopback device listener with separate command/Nerve channels. `North` is an in-process service facade, not a public control socket. `Hub` owns device views, maps, bounded observations, health, manual leases, stop, durable operations, watches and notification outbox.

Construct the Hub with an owner/profile-bound transactional store, bound wake producer and trusted authority adapter. No production permissive adapter is provided. Test fakes are under `test/` only. The adapter must check current activation and consume native admission bound to the exact operation, action, device description revision and effective input. Browser actor/role/approval fields are never proof. Managed-service supervision must own one Hub per profile; session plugins only connect to it.

Operation acceptance is committed before dispatch. Matching operation ids return the same receipt; changed subjects conflict. Device results commit terminal state and a stable outbox entry in one transaction. After restart, a nonterminal action becomes `unknown` and is never dispatched again. Bound notifications retry the same idempotency key. Store version 1 is a fresh format; unsupported versions refuse startup. Durable receipts, watches and outbox are separate from display activity. Activity retains at most seven days and 10,000 records, whichever is reached first, and reports the earliest readable timestamp and cursor.

Manual leases last at most 30 seconds, do not renew through duplicate operation ids, and never survive restart. Stop invalidates pending control and existing leases before sending zero/manual and command Stop to every selected device. An unavailable device or missing acknowledgement produces `unknown`; the latest stop result remains persisted outside the activity window. Shutdown denies new work, stops devices, closes streams and records unconfirmed in-flight operations. Local device deadman remains required.

Observations retain one latest sample per source, plus bounded values history. Binary retention across the profile is capped at 16 MiB. Telemetry and video frames do not become durable activity rows. Video never enters model input. The model adapter passes stills through the session request-media API. Gateway media frames contain a length-prefixed JSON header and bytes in one frame, capped at 1 MiB; loss requests a keyframe. The device protocol's two-frame pairing stays confined to one Nerve socket.

Real Harness admission, managed-service lifecycle and browser gateway integration require the corresponding public author APIs. This package does not substitute a local role field, raw Node socket or arbitrary jobs/admin access for those APIs. Synthetic unit/socket tests establish local software behavior only; physical hardware and Windows service acceptance remain deployment checks.

Browser queries expose optional `DeviceView.sourceStates` (true/false, or null until confirmed) and operation `startedAt`/`endedAt`, `phase` and `progress`. Only device observations and acknowledged configure replies confirm source state. Device progress can refine an existing live operation from that device; it cannot reopen a terminal receipt. Paused progress is emitted by SDK checkpoints after motion reaches rest. These are additive MHS projections, independent of native admission and generic Harness wire schemas.

`DeviceView.jobs` is an optional, bounded projection of up to eight recent action receipts per device. It is rebuilt from the canonical journal on recovery and publishes changes through the events lane. Summaries contain labels, state, timing, numeric progress and terminal status/reason; arguments, result payloads and session/wake identity stay in their owning records. The in-memory index retains at most 512 device entries.

Reads accept `{since, history, cursor, limit, timeoutMs, signal}` as a third argument. `since` and history cursors use Hub receive time in milliseconds. A `since` read returns only a strictly newer sample, waits at most 2 seconds by default (maximum 10 seconds), and honors cancellation. A timed-out item reports `data.state: "timeout"`. Values history samples at 1 Hz for up to 120 seconds/120 entries; `limit` defaults to 32, and `nextCursor` pages the retained window. Latest media is separate from values history; total JSON retention is capped at 8 MiB. Event replay uses opaque generation-scoped cursors, a 10-minute/512-event/1-MiB ring, and an explicit `gap` when a cursor expired or the Hub restarted. It is separate from seven-day activity. Completion wakes coalesce over a one-second window and persist their batch identity before enqueueing, preserving original session/lane bindings through retries.

Reads, source watches and media subscriptions share demand. Subscriptions can request `hz`; the producer receives the maximum requested rate within its declaration. Pose remains at 1 Hz without consumers; other sources switch off when unused. An approved manual source-off always wins. Video subscriptions request a first keyframe and suppress deltas until it arrives; dropped streams request another keyframe. Model reads still refuse video.

Native `pause`, `resume` and `cancel` target an existing live operation on the admitted device. Pause projects only after device acknowledgement of rest. Call acceptance deadlines are 2 seconds; execution deadlines include the declared timeout and a 5-second result grace. Timeout cleanup attempts Cancel (500 ms), then Stop (1500 ms); an unacknowledged Stop closes the connection. Unknown actions are never replayed.

Fixed placement is trusted while available. Dynamic fixes become uncertain after 3 seconds and lost after 10 seconds; `ok`, covariance error (default threshold 0.5 m) and odometry disagreement can reduce trust sooner. World entities report fixed placement and the smallest containing polygon. Valid map declarations replace the frame and merge places by id; validation still rejects malformed bounds and places. Maps persist after disconnect.

Clip sending requires a separate native-approved `mhs.clip` capability bound to device revision, clip id, PCM16 rate/channels, byte count and SHA-256. The one-use binary stream accepts at most 1 MiB, expires after 30 seconds, and is revoked by Stop, disconnect or replacement. South sends the Nerve header and payload in order and waits up to 2 seconds for the SDK's `mhs/clip-received` notification. A `sent` receipt confirms caching, not playback or tool completion. Reviewed producer bridges without clip support refuse the operation.

Clip uploads use ordered 2 KiB binary chunks on the existing 4 KiB/30-frame-per-second control contract. The browser paces chunks at 40 ms, and the Hub assembles at most 1 MiB under the approved hash before sending it to the device. Partial, excess, expired or repeated uploads cannot trigger a device tool.

Resource refusal receipts expose the holding operation as `holder.job`, alongside the device call id, tool and descriptive caller label; unavailable declared source needs remain a typed refusal.

`Hub.summarizeRead(read, since?)` and `Hub.summarizeDevices(views)` provide presentation-only text within 6000 UTF-8 bytes, using Hub receive times and localization age with declared roles, units, alerts and map zones. Pass the original `since` when summarizing a conditional read. `resultSummary(receipt)` describes operation and Stop receipts without serializing arbitrary payloads. These helpers preserve the input data and do not authorize, dispatch, stop or replay operations; North query payloads remain unchanged.
