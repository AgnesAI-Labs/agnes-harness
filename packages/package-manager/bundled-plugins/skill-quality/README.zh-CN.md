# 技能质量

[English](README.md) | 简体中文

可选插件 `@agnes/skill-quality` 为人审技能候选提供参考性的质量证据。在设置 → 插件 → 目录中安装“技能质量”，审核权限后显式启用；离线发行包包含它，但默认不启用。在记录证据的会话中打开“技能质量”工作台面板。

`skill_quality_candidate` 支持 `create`、`read`、`write`、`test`、`submit`。创建和修改传完整文本文件列表；修改、测试和提交须传 `candidateId` 与 `expectedHash`，读取传 `candidateId`。全部操作通过已有 Host 候选授权路径执行。`submit` 仅请求人审，发布和拒绝仍在设置 → 插件中完成。导入证据不修改审批、测试状态、信任或启用状态。

`skill_quality_import` 接收 `candidateId`、`evidenceJson` 和可选的 `currentInstalledHash`（显式 `null` 表示尚未安装）。后者是**人工查询当前安装清单后提供的观察值**，不代表实时状态；无法查询则省略。导入时会向 Host 重新读取候选。普通候选操作会清除安装观察值，需重新观察，否则显示未知。候选内容或安装基线哈希不一致时显示过期。失败或拒绝后应在原候选界面检查状态，不自动重试结果未知的操作。

使用 [src/fixtures/eval.json](src/fixtures/eval.json) 作为 P01 评测产物的人工转换格式。将模拟哈希换成原报告对应的候选、安装基线及环境哈希。`artifact.sha256` 指原始导出报告的哈希（不是包装 JSON 的哈希），`skillRevision` 标识被测技能修订。将原报告通过、失败、跳过案例及实际执行数、预期和实际输出、环境哈希及运行环境/模型/执行器/模式/预算说明填写到包装中，保留原产物供复核。此转换不依赖 eval-studio，也不验证报告身份。`kind: "self-assessment"` 明确显示为自评。不能导入 Host 测试收据或审核人身份；未实际执行的案例不能通过，全跳过报告被拒绝。未知字段、重复案例 ID、过大输入均被拒绝。仅导入模拟或脱敏样例。

对于 eval-studio v1 导出，以 `datasetHash` 绑定数据集，`dataset.hashes` 绑定七项组件；原始十六进制哈希加 `sha256-` 前缀，`fixture` 改为 `fixtures`。复制 `dataset.seed`，按实际运行填写运行环境、模型、回放模式与预算。逐例复制 `executed`、数据集预期输出和实际 `output`。只有确实执行、structure/effects/budget 检查全部通过且 judge 为 pass 或 skipped 时才标通过；未知检查不得转为通过。未执行项标跳过。候选/基线哈希和技能修订取自被测候选，因为评测报告不证明这些绑定。包装最多 24 例；若仅选取部分案例，在 `artifact.label` 标明并保留完整原报告。

可选 `skill-quality.review` Loop 依次创建/读取/修改候选 → 导入（如提供）→ Host 测试 → 确认后提交人审。通过已有 Loop provider 配置显式选择它，在工作流行的 `workflow` 配置中提供 `candidateId`（创建时提供 `files`）、修改时的 `expectedHash`、`evidenceJson` 和可选安装观察值（配置总大小上限 128 KiB）。新建候选哈希尚未知时先不提供证据，之后用工具附加。工作流使用已配置的模型解释固定步骤，可能产生模型费用；导入和候选工具本身不调用模型，工具授权与精确哈希测试确认仍然生效。

每个记录会话在 56 KiB 总状态预算内保留最近更新的八个候选，存入插件自有存储和事件投影。profile 查询 `quality.read` 必须显式声明且获准读取请求的 `sessionReads` 会话，不扫描会话。服务缺失或后台响应不兼容时面板显示不可用；旧会话缺少候选工具时应新建会话，卸载时释放注册。后端新代码用于新会话固定版本，旧会话保留代码；技能属于实时资源，人审发布后旧会话也可能读到新版技能。升级失败仍只是候选，不改变已安装代码。

不提供评分发布门禁或自动评测。实时候选/安装状态与签发评测来源须另行评审通用合同。哈希一致只表示与所提供的观察值对应，不证明评测准确或实时安装状态。

操作步骤及限制参见[指南](../../../../docs/guide/skill-quality.zh-CN.md)。
