# Skill quality

English | [简体中文](README.zh-CN.md)

Optional `@agnes/skill-quality` provides advisory quality evidence for human-reviewed Skill candidates. Install **Skill quality** from Settings → Plugins → catalogue, review its capabilities and enable it explicitly. It is shipped offline and is never enabled by default. Open the **Skill quality** workbench panel in the session that recorded the evidence.

`skill_quality_candidate` accepts `create`, `read`, `write`, `test`, `submit`. Creation/writes use the complete candidate text file list; writes/tests/submission require `candidateId` and `expectedHash`. Read uses `candidateId`. These operations delegate to the existing authorized Host candidate path. `submit` only requests human review. Publication/rejection stays in Settings → Plugins; imported evidence never changes approval, test status, trust or activation.

`skill_quality_import` takes `candidateId`, `evidenceJson` and optionally `currentInstalledHash` (`null` explicitly means not installed). The latter is a **manual current inventory observation**, not a live assertion. Omit it when unavailable. Imports refresh the candidate receipt from Host. Ordinary candidate actions clear this observation, so freshness returns to unknown until re-observed. Content/base mismatches are stale. Failure or denial must be inspected in the original candidate UI; never retry an unknown effect automatically.

Use [src/fixtures/eval.json](src/fixtures/eval.json) as the manual bridge format for a P01 eval artifact. Replace synthetic hashes with the artifact's actual candidate/base and environment hashes. `artifact.sha256` identifies the original exported report (not the envelope); `skillRevision` identifies the tested Skill. Carry the original report's pass/fail/skipped cases, execution counts, expected/actual outputs and environment hashes plus runtime/model/runner/mode/budget labels into the envelope. Keep the original artifact for review. This normalization requires no eval-studio dependency and does not authenticate the imported report. `kind: "self-assessment"` is explicitly labelled self-assessment. No caller may import Host test receipts or reviewer identity. Cases with no actual execution cannot pass; all-skipped reports are rejected. Unknown extra fields, duplicate case IDs and oversized inputs are refused. Import synthetic or redacted examples only.

For eval-studio v1 exports, use `datasetHash` for the dataset binding and `dataset.hashes` for the seven component bindings; prefix raw hexadecimal hashes with `sha256-` and rename `fixture` to `fixtures`. Copy `dataset.seed`; describe the runtime, model, replay mode and budget from the actual run. For each selected case copy `executed`, its dataset expected output and actual `output`. Mark passed only when execution occurred, every structure/effects/budget check passed and judge status is pass or skipped; unknown checks must not become passed. Unexecuted cases are skipped. Candidate/base hashes and Skill revision come from the tested candidate, since the eval report does not attest them. The envelope holds at most 24 cases; label subsets in `artifact.label` and retain the full original report.

The optional `skill-quality.review` Loop runs candidate create/read/write → import (if supplied) → Host tests → confirmed submit. Select it explicitly with the existing Loop provider configuration. Configure the workflow row's `workflow` settings with `candidateId` (or `files` for creation), `expectedHash` for edits, `evidenceJson` and optional `currentInstalledHash` (128 KiB settings limit). For a newly created candidate whose hash is not yet known, omit evidence; attach it afterward using the tools. The workflow uses the configured model for fixed step explanations and may incur model charges; imports and candidate tools do not call models. Tool permission and the exact-hash test confirmation still apply.

Evidence is bounded to eight most recently updated candidates per recording session, within a 56 KiB session state budget, in the plugin's owned store and event projection. The profile query `quality.read` requires an explicit authorized `sessionReads` entry for exactly the requested session; it never scans sessions. The panel handles missing services or incompatible backend responses as unavailable and releases registrations on uninstall. Use a new session if an older pinned session lacks the candidate tools. Backend code upgrades affect new pins, while existing sessions retain code. Skills are live resources; reviewed Skill publication can change their content for existing sessions too. A failed upgrade is only a candidate and cannot change installed code.

There is no score-based publication gate or automatic eval runner. Live candidate/inventory freshness and signed eval provenance require separately reviewed generic contracts. A matching hash proves only correspondence with supplied observations, never evaluation accuracy or current installation state.
