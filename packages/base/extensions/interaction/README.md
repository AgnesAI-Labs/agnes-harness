# Interaction

`ask_user_question` preserves its single/multiple/free-text parameters and durable `timeoutMs` deadline (0–60000 ms). It invokes the ordinary `ui_render` tool to publish a preset form, inline only. The form data carries a `question` marker (`{ kind: 'ask_user_question', deadline, labels? }`); Web shows a marked form as a step card above the composer (one question at a time, number keys, one submit for all answers), never in the workbench, and shows the submitted answers in the conversation from the delivered action result. Each question takes an optional short `label` for its step and answer summary; without one the client shortens the question. The title is localized through `titleKey`. While a question is open the tool result tells the model the questions are shown in the UI and must not be restated; it does not list them. Answers use authenticated `ui.action` and the ordinary deferred `ui_submit` tool; direct model calls cannot produce a human reply. The successful action closes the form. Late answers are delivered through the existing SC1 queued-input path with the authenticated actor and untrusted content. An answer never grants tool permission.

The question projection records durable requests and successful surface actions. Text clients use numbered choices with the same action request, or the authenticated Web link when their transport cannot submit actions. No special slot payload or answer-message prefix is involved. See [default tools](../../../../docs/reference/default-tools.md).
