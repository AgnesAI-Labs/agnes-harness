# Detached assembly and maintenance publication

These modules validate immutable assembly plans and prepare Cordis candidates without changing the running route. Client bundle rows bind `bundleId`, `target` (`web`, `tui`, `im`, or `sdk`), `schemas`, `packageId`, `version`, `entry`, and the raw entry `digest`. Renderer `viewSchemaRanges` must match the locked schema catalog. Bundles do not carry recovery codecs.

The optional maintenance ports use the public `MaintenanceStore.commit/query` interfaces. They are currently qualified only for persistent synthetic fixtures. Production credentials, tenant routing, deployment anchors, and authorization adapters are required before startup registration can be added.

The detached private release producer reads owner-protected POSIX deployment files and locked local packages, runs the official configuration and package algorithms, verifies selected descriptors and package snapshots, and constructs a complete `RunBinding`. The configuration result remains a candidate. Applied configuration is decoded through its original selected author's schema source; the producer no longer issues a provisional configuration or publication-source schema.

`installReleaseProducer` takes the original selected factory, descriptor, binding, complete scope, verified package metadata/snapshot/code, original Context and the original installer's opaque Context evidence. Its one-time installation handshake retains the actual resolving configuration/package instances and their original outputs. The native installer must authenticate the factory and C14 evidence. The capture API alone does not prove authorization or native generation.

`captureOriginalContents(originalContext)` returns every protected file's raw bytes, original request/result roots, manifests, schema sources, package files and archives. The mapping preserves each DataRef occurrence's escaped JSON pointer, complete schema ref, digest and byte length; archive references retain binary bytes. Duplicate bodies share a content pool while their logical positions remain distinct. Returned byte copies cannot mutate the private capture.

The request path uses the four official Host publication codecs. A factory occurrence is lexically branded, bound to the original request and Context and consumed once by the injected `InstalledPublicationIssuer.prepare` port. The commit and `acceptOriginalReceipt` calls preserve the original request/Context and successful receipt pointer. This path remains incomplete: the current complete release exceeds the release-snapshot text budget, and the full retained mapping exceeds the applied-source row budget. The composite decoder also needs support for the package source's binary archive and current manifest/schema-source formats. No original content is truncated or replaced to pass these gates.

Production readiness refuses with `producer_native_issuer_missing`. No production issuer or startup registration is installed here, and no commit timestamp or final native Clock is supplied. Cold recovery requires the original reader's persisted source, complete content pool, three members and original receipt; it never opens deployment files, resolves or repairs history. The existing fixture-only maintenance journal remains separate.

Preparation records the fixed plan identity, immutable release, operation checkpoints, and package pins. Publication recomputes the plan fingerprint and checks current directory, route, joint domains, migration prerequisites, authorization, and pins. One multi-mutation commit guards the current head and route revision, writes the cutover and committed operation, preserves the pins, and enqueues the publication outbox event. Local activation follows that commit. A failed commit preserves the old route; a lost response can be replayed from committed facts.

Records are Host-private `MaintenanceEnvelope` payloads. Their schema status explicitly awaits confirmation from the protocol owner. The private `assembly.records` query returns an ID index for a null selector and record envelopes for an explicit selector; readers request individual records to respect public JSON limits. Plan and cutover records refer to the separately stored immutable release by record ID and content digest. The private release snapshot stores its complete canonical JSON text and content digest. Publication compares the exact fixed text; ticket and pin consumers decode it through the public ReleaseSet validator and reject noncanonical text or a mismatched digest. This query convention and the payload schemas are provisional, not new public wire types.

Admission support only issues a durable ticket and package pin receipt, fixing the run key and complete `RunAdmission` fingerprint. The state decision helper returns advice and always retains the pin. Runtime run creation, confirmation, cancellation, probing, owner proof verification, pin release, persistent drain, and runtime recovery remain unavailable. Maintenance replay does not start or recover a Runtime State process.

`createMaintenancePackagePins` retains package and entry digests for maintenance-authorized owners and exposes persisted pins after restart. It does not retain source resource instances, enforce their GC, or supply Runtime owner exit proofs. Consumers must keep refusing resource operations until those additional ports are available.

The independent reference provider uses the same public interfaces and private record convention. Testkit publication cases cover selection, normal publication, commit refusal, cancellation, cold replay, and disposal with isolated SQLite fixtures. Host process tests kill real maintenance fixture processes before and after publication and ticket commits.
