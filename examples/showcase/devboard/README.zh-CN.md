# DevBoard 研发全流程工作台

[English](README.md) | 简体中文

面向轨交装备企业的研发全流程工作台演示：需求分析 → 架构设计 → 开发实现 → 测试验收。**企业「宁川交通装备股份有限公司」（宁川装备）、客户、线路与人员均为虚构，所有数据都是模拟数据**，不连接任何外部系统（PLM、ERP、QIS、MES 等）。涉及安全完整性的内容均按 EN 50126 / EN 50716（原 EN 50128）假设。

看板每 10 秒轮询一次。页面顶部的「演示角色」只用于审批署名，不是登录或权限边界。首件检验、现场验收、独立安全评估与 FMEA/FTA 由外部/硬件环节完成，不建模。

## 规则

所有写入都走 `domain.mjs` 的同一组函数，页面和智能体工具共用。

- **阶段**：NOT_STARTED → IN_PROGRESS → IN_REVIEW → PASSED；IN_REVIEW → REWORK → IN_PROGRESS。前一阶段通过后，后一阶段才能开始。
- **评审门**（违反时提示「评审门不满足：…」）：只有评审中的阶段能决议；审批角色不能是该阶段的编写角色；所有评审意见关闭后才能批准。批准后阶段通过、交付物基线化并生成基线；驳回需填写意见，阶段进入返工。开发实现阶段没有人工门，代码评审意见全部关闭后自动通过。
- **追溯**：CUS→SYS、SYS→SWR、SWR→TC 三段覆盖率；需求阶段提交评审时，CUS→SWR 不到 100% 会自动加一条评审意见。
- **变更**：SUBMITTED → ANALYZED（需有影响分析）→ CCB_REVIEW → APPROVED / REJECTED → IMPLEMENTED → CLOSED。批准后受影响需求标记为已变更，已通过的受影响阶段自动返工。
- **缺陷**：NEW → CONFIRMED → FIXING → RETEST → CLOSED，可延期处理。
- 第一版的需求、任务、人工介入状态机与联动保持不变。

## 智能体与现场项目

`coordinator`（研发协调员）带全部 15 个 `devboard_*` 工具、读写与 shell、`tool_search` / `tool_describe`、`subagent_spawn` / `subagent_collect`，以及技能 `devboard-playbook`（全流程、角色提示词、文件约定、门的规则）。预设 `devboard` 允许在工作区内编辑与写入；所有 shell 命令（含 `node --test`、`node server.js`）都会请人确认，因为它们运行的是智能体自己写的代码；五个声明式可委派角色（`requirements`、`architect`、`developer`、`reviewer`、`tester`）在新鲜子会话中共用父工作目录，权限取角色与父快照交集。代码评审员只读，其余角色可编辑项目文件；均没有 shell、看板或审批/签署能力，命令交回协调员执行。所有角色全过程中文叙述（用户明确选其他语言时遵从用户），业务状态用中文。

预设显式申请经审阅的 `sandbox.loopback_serve`：强制 L1、`on_unavailable: deny`、外网白名单为空，命令仍需审批。受支持的 macOS Host 先绑定 loopback socket，再传入 `AGH_LOOPBACK_FD` 与 `AGH_LOOPBACK_URL`；生成的 Node 服务必须用 `server.listen({ fd: Number(process.env.AGH_LOOPBACK_FD) })` 接管，并在就绪后输出该 URL。无 activation 的普通部署才使用 `127.0.0.1` / `--port` 分支。命令自行 bind 或主动连接仍被拒绝；不支持的沙箱后端拒绝该能力，不降级。现场演示须使用支持此能力的平台构建。

现场项目「车门健康监测看板」是无依赖的 Node 网页应用，文件写在工作区的 `devboard-projects/<项目编号>/`。角色子智能体只处理工作区文件，看板只由研发协调员登记。每过一道门，研发协调员提交评审后结束本轮；人在看板审批，再点「继续推进」，草稿里带上门编号，由人点发送。

### 演示脚本与检查点

1. 总览：三个项目，待决议评审门 1 个，PRJ-2025-042 显示超期。
2. 评审待办 → GATE-PRJ-2026-008-DESIGN-1：以「技术负责人」批准，被拒「还有 2 条评审意见未关闭」；切到「软件架构师」批准，被拒「审批人角色…是该阶段的编写角色」；打开一个已决议的门再批准，被拒「不在评审中」。填写两条关闭说明后以技术负责人批准，阶段通过并生成基线 BL-008-SAD-V1.0。
3. 需求与追溯：PRJ-2025-042 的 SWR→TC 为 96%，SWR-025、TC-038 高亮。
4. 变更：CR-2026-031 由 CCB 批准后，PRJ-2025-042 的需求与设计阶段转为返工。
5. 现场项目：工作台快捷操作「新建并启动一个研发项目」。每道门提交后，看板显示该阶段「评审中」和新交付物，工作区有对应文件；审批后点「继续推进」。
   - 门 1 立项（研发总监）：`docs/PROJECT-PLAN.md`。
   - 门 2 需求（项目经理）：出现 typed `requirements` 任务卡与子角色编写的 `docs/SRS.md`、`docs/RTM.md`，追溯页出现 CUS/SYS/SWR。
   - 门 3 设计（技术负责人）：typed `architect` 子角色；`docs/SAD.md`，DES 挂到 SWR。
   - 开发实现：typed `developer` 与独立只读 `reviewer` 子角色；`src/`、`server.js`、`test/`；修复并经独立复核后关闭意见，自动通过。
   - 门 4 测试（质量负责人）：typed `tester` 只依据 SRS 与公开 HTTP 合同编写验收测试；协调员运行单元测试，演示者在命令沙箱外的真实浏览器执行测试角色的公开 HTTP/页面检查，通过 activation listener 验收；在「缺陷与测试」和 `docs/TEST-REPORT.md` 记录命令、cwd、计数与缺口。内部处理函数调用不算验收通过。
   - 门 5 发布验收（质量负责人）：`docs/RELEASE-NOTE.md`；真实 HTTP 就绪检查与浏览器线路→车辆→车门、故障排行检查通过后按实际 `AGH_LOOPBACK_URL` 登记应用，项目页出现「打开应用」。保留后台 job 编号，演示后停止。

真实模型跑完全流程可能需要几十分钟。

命令需要正确的工作目录：shell 默认 cwd 是工作区根目录，传真实存在的测试文件，如 `node --test devboard-projects/<项目编号>/test/unit.test.js`；或把 shell `cwd` 设为 `devboard-projects/<项目编号>/` 后用 `node --test` 自动发现。不要把 `test/` 目录作为位置参数。启动 `node server.js --port <空闲端口>` 同样设项目 cwd；AGH 中接管 Host listener 并读取实际 URL，普通部署才绑定 `127.0.0.1`。`--port` 不能指定 Host 分配的端口。禁止使用 4177/4178，无需外网或安装依赖。命令内 `curl` / `fetch` 不能主动连接此 listener，公开 HTTP 验收由真实浏览器执行，结果与 `node --test` 单元测试分别计数。

委派失败时标注「角色独立性未满足」，保留质量意见；协调员自审不能替代独立角色。监听或浏览器失败仍是验收阻断项。不得仅因移交后续阶段关闭意见，也不得登记未经验证的 URL。

### 演示者检查表

- 使用隔离 home、工作区、已配置的真实模型、空闲应用端口；浏览器保留一两个标签。采用应用前核对安装版本和权限。
- 预演全部五门，检查 typed 角色任务卡与父子文件可见性，检查全过程中文叙述及业务状态中文标签。
- 批准前核对命令和 cwd，避免 `node --version` 等无必要探测。命令运行生成代码；污染输入也可能让后续文件/看板操作需要审批，逐项阅读动作标题和证据。
- 门 4–5 前检查真实 HTTP 日志、浏览器证据、未关闭意见和已登记 URL；记录各门耗时，确认后台服务的停止方式。

## 目录

- `domain.mjs`：阶段、评审门、追溯、变更、缺陷、测试与第一版状态机；指标；存储（按 64 KiB 分块）。
- `seed-data.mjs`、`seed-docs/`：虚构项目组合的种子数据与文档正文。
- `index.mjs`：档案服务 `devboard.snapshot`、`devboard.artifact`、`devboard.transition`、`devboard.create`、`devboard.gate`、`devboard.reset`，智能体工具与技能。
- `skills/devboard-playbook.md`：研发协调员技能。
- `client/`：七个页面，使用 `@agnes/web-ui` 组件。
- `test/`：领域规则与种子数据测试。

```sh
pnpm exec vitest run examples/showcase/devboard/test --maxWorkers=1
```

从 1.0.0 升级：store 中的旧数据（schema 1）读作种子数据，首次写入时替换。从源码试用请按[安装](../../../docs/guide/install.zh-CN.md)准备环境，打开智能体页安装 DevBoard 后采纳。
