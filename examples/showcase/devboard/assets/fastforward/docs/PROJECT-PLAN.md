# 车门健康监测看板 项目计划

> 虚构企业与模拟数据：宁川交通装备股份有限公司（宁川装备）及文中的人员、线路、数值均为虚构，仅用于 DevBoard 演示。

## 1 目标

为运维事业部做一个小切片：按「线路 → 车辆 → 车门」三级展示车门健康评分，并列出最需要关注的车门（预警排行）。数据是程序生成的模拟 PHM 信号，不接入真实车辆。

## 2 范围

| 范围内 | 范围外 |
|---|---|
| 健康评分与等级（健康、关注、告警） | 接入真实车辆或 PHM 平台 |
| 三级钻取页面与预警排行 | 登录、权限、数据持久化 |
| 只读 HTTP 接口，参数校验 | 工单派发、短信通知 |
| 单元测试、接口检查、浏览器验收 | 性能压测 |

## 3 里程碑

| 门 | 内容 | 编写角色 | 审批角色 |
|---|---|---|---|
| CDCP | 概念决策评审：目标与范围确认 | 产品经理 | IPMT |
| TR1 | 需求评审：SRS 与 RTM，客户条款全覆盖 | 系统设计师 | 技术负责人 |
| TR3 | 详细设计评审：SAD 与设计条目 | 软件设计师 | 技术负责人 |
| TR4 | 代码与集成评审：评审意见全部关闭后自动通过 | 软件设计师 | 自动 |
| TR5 | 系统验证评审：单元、接口、浏览器验收的证据 | 验证工程师 | 质量工程师 |
| ADCP | 可获得性决策评审：发布说明与可运行应用 | 产品经理 | IPMT |

按小版本软件项目的裁剪指南，TR2、TR6、PDCP 已合并到上述评审中。

## 4 角色

产品经理 · 系统设计师 · 软件设计师 · 验证工程师 · 质量工程师 · 技术负责人 · IPMT。

## 5 风险

| 编号 | 风险 | 应对 |
|---|---|---|
| R1 | 模拟数据与真实信号口径不一致 | 信号口径沿用在役项目，评分权重集中在一个文件，便于调整 |
| R2 | 浏览器验收证据不足 | 验收记录逐步骤写明结果，失败项登记缺陷并保持开放 |
