## 1 引言

### 1.1 目的

本说明书规定宁川地铁 9 号线客室侧门门控器（DCU）应用软件的功能、性能、接口与安全需求，是软件设计、测试与验收的依据。

### 1.2 范围

适用于 DCU 应用软件 V2.3 系列。门机构、DCU 硬件与整车电路不在本说明书范围内，相关约束以接口需求形式给出。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| DCU | 门控器，每套门一台 |
| TCMS | 列车控制与管理系统 |
| MVB | 多功能车辆总线 |
| TRDP | 列车实时数据协议（以太网） |
| S1 / S2 | 关到位开关 / 锁闭开关 |
| 零速信号 | 列车速度低于 5 km/h 时有效 |
| 门使能 | 允许某一侧开门的硬线信号 |
| 门安全回路 | 全车门关闭锁闭状态的串联回路 |
| 安全相关 | 按 SIL2 开发的功能（按 EN 50126 / EN 50716（原 EN 50128）假设） |

## 2 总体描述

### 2.1 系统上下文

DCU 接收 TCMS 经 MVB 下发的集控开关门指令、司机室硬线开关门指令、零速与门使能硬线信号，控制门电机，采集 S1、S2、紧急解锁、隔离开关等信号，驱动门安全回路继电器，并向 TCMS 上报门状态与故障。

### 2.2 运行环境

- 处理器：主处理器 + 安全监控协处理器（双通道）；
- 运行温度：-25 ℃～+45 ℃（车内环境）；
- 供电：DC 110 V（DC 77 V～137.5 V）；
- 环境试验：淋雨、冲击振动（IEC 61373 1 类 B 级）、EMC（EN 50121-3-2）。

### 2.3 安全完整性假设

零速联锁、门关好判定与安全回路、障碍物检测、紧急解锁处理、防拖拽检测为安全相关功能，按 SIL2 开发（假设）。安全功能失效时软件应导向安全状态：不开门、不输出门关好。

## 3 需求

### 3.1 客户需求

|---|---|---|

### 3.3 软件需求

#### 3.3.1 SWR-001 开门指令处理

- 需求：MVB 集控开门与硬线开门指令取“或”，且须零速有效、门使能有效方可执行。
- 来源：SYS-001、SYS-005
- 安全相关：否
- 验证方法：测试

#### 3.3.2 SWR-002 关门指令处理

- 需求：执行关门指令；关门过程中收到开门指令应在 200 ms 内反向开门。
- 来源：SYS-002
- 安全相关：否
- 验证方法：测试

#### 3.3.3 SWR-003 电机速度闭环

- 需求：电机速度闭环控制周期 1 ms，稳态跟随误差不大于 5%。
- 来源：SYS-003
- 安全相关：否
- 验证方法：测试

#### 3.3.4 SWR-004 开关门曲线参数

- 需求：开门 3.0 s、关门 3.5 s 为默认值，参数可在 ±0.5 s 范围内调整并做范围校验。
- 来源：SYS-003
- 安全相关：否
- 验证方法：测试

#### 3.3.5 SWR-005 零速双通道采集

- 需求：零速信号双通道采集并逐周期比较，不一致持续 50 ms 判零速无效。
- 来源：SYS-004
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.6 SWR-006 零速无效屏蔽开门

- 需求：零速无效时屏蔽全部开门输出，包括维护模式下的本地开门。
- 来源：SYS-004、SYS-018
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.7 SWR-007 门使能侧判别

- 需求：按左/右门使能信号判别允许开门侧，非使能侧开门指令丢弃并记录。
- 来源：SYS-005
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.8 SWR-008 障碍物检测

- 需求：关门行程中电流超自适应阈值或速度偏差超限判为障碍物，检出后 200 ms 内反向。
- 来源：SYS-006
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.9 SWR-009 重开计数与报警

- 需求：连续重开计数，第 3 次后门保持开启并置 MVB 报警位。
- 来源：SYS-007
- 安全相关：否
- 验证方法：测试

#### 3.3.10 SWR-010 最终关闭区力限制

- 需求：关门行程最后 30 mm 不反向，改为限制电机电流使夹紧力不大于 150 N。
- 来源：SYS-006
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.11 SWR-011 S1/S2 信号校验

- 需求：采集 S1、S2 信号并做合理性校验，不一致超过 300 ms 报门开关故障。
- 来源：SYS-008
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.12 SWR-012 门关好判定与安全回路

- 需求：S1、S2 均有效且电机静止时判门关好锁闭，驱动安全回路继电器。
- 来源：SYS-009
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.13 SWR-013 紧急解锁处理

- 需求：紧急解锁动作后 20 ms 内切断电机驱动，置 MVB 紧急解锁状态位。
- 来源：SYS-010
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.14 SWR-014 隔离处理

- 需求：隔离状态下屏蔽集控指令，安全回路按隔离旁路处理并上报隔离状态。
- 来源：SYS-011
- 安全相关：否
- 验证方法：测试

#### 3.3.15 SWR-015 MVB 过程数据

- 需求：按端口分配表以 64 ms 周期收发过程数据。
- 来源：SYS-012
- 安全相关：否
- 验证方法：测试

#### 3.3.16 SWR-016 MVB 通信超时

- 需求：连续 3 个周期未收到有效报文判通信故障，保持当前门状态并记录。
- 来源：SYS-012、SYS-018
- 安全相关：否
- 验证方法：测试

#### 3.3.17 SWR-017 TRDP 报文框架

- 需求：实现 TRDP 过程数据收发框架与报文映射，本期不承载控制指令。
- 来源：SYS-013
- 安全相关：否
- 验证方法：测试

#### 3.3.18 SWR-018 故障诊断

- 需求：检测电机过流、编码器断线、门开关故障，故障码符合故障码表。
- 来源：SYS-014
- 安全相关：否
- 验证方法：测试

#### 3.3.19 SWR-019 故障记录

- 需求：故障记录环形存储 1000 条，含时间戳与工况快照，掉电不丢失。
- 来源：SYS-015
- 安全相关：否
- 验证方法：测试

#### 3.3.20 SWR-020 维护下载

- 需求：经以太网维护口导出故障记录与运行日志，文件名含车号与门号。
- 来源：SYS-015
- 安全相关：否
- 验证方法：测试

#### 3.3.21 SWR-021 声光提示时序

- 需求：关门前 1.0 s 起蜂鸣，门指示灯按 2 Hz 闪烁至门关好。
- 来源：SYS-016
- 安全相关：否
- 验证方法：测试

#### 3.3.22 SWR-022 防拖拽检测

- 需求：门关闭锁闭后 2 s 检测窗口内比较锁闭行程与电机电流特征，识别薄型物体并撤销门关好。
- 来源：SYS-017
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.23 SWR-023 输入消抖与看门狗

- 需求：数字输入 20 ms 消抖；硬件看门狗超时复位后进入安全状态。
- 来源：SYS-019、SYS-018
- 安全相关：是
- 验证方法：测试 + 分析

#### 3.3.24 SWR-024 开关门次数统计

- 需求：记录开关门次数并掉电保存，超过寿命预警阈值时上报。
- 来源：SYS-020
- 安全相关：否
- 验证方法：测试

#### 3.3.25 SWR-025 版本与参数校验和

- 需求：上电计算软件版本与参数区 CRC32，并经 MVB 上报。
- 来源：SYS-020
- 安全相关：否
- 验证方法：测试

## 4 接口需求

### 4.1 MVB 过程数据

| 端口 | 方向 | 周期 | 内容 |
|---|---|---|---|
| 0x2A0 | TCMS → DCU | 64 ms | 集控开/关门指令、门使能镜像、时间同步 |
| 0x2A4 | DCU → TCMS | 64 ms | 门状态字（开到位、关到位、锁闭、隔离、紧急解锁） |
| 0x2A6 | DCU → TCMS | 64 ms | 故障与报警字（障碍物报警、通信故障、门开关故障） |
| 0x2A8 | DCU → TCMS | 512 ms | 诊断数据：开关门次数、软件版本、参数校验和 |

### 4.2 硬线接口

| 信号 | 方向 | 说明 |
|---|---|---|
| 零速（双通道） | 输入 | SWR-005 |
| 左/右门使能 | 输入 | SWR-007 |
| 硬线开/关门 | 输入 | SWR-001、SWR-002 |
| S1、S2 | 输入 | SWR-011 |
| 紧急解锁、隔离 | 输入 | SWR-013、SWR-014 |
| 安全回路继电器 | 输出 | SWR-012 |

## 5 非功能需求

1. 实时性：主控制周期 1 ms，安全比较周期 10 ms，MVB 周期 64 ms；
2. 资源：CPU 负载峰值不大于 70%，Flash、RAM 余量不小于 30%；
3. 编码：C 语言，遵循 MISRA C:2012；
4. 可维护性：参数与软件版本分区存储，可在车升级。

## 6 评审结论

TR1/TR2 评审结论：通过。评审意见 2 条，已在 V1.0 关闭：

1. SWR-010 最终关闭区的行程范围未量化 → 明确为关门行程最后 30 mm；
2. SWR-016 通信超时周期 → 与华东某车辆厂确认为 3 个周期（192 ms）。
