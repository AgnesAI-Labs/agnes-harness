# Review Skill quality evidence

English | [简体中文](skill-quality.zh-CN.md)

Install the optional **Skill quality** plugin from Settings → Plugins → catalogue, review permissions and enable it. It adds two deferred tools and a separate session workbench panel. It is disabled by default and does not replace candidate approval/rejection.

1. Create a candidate through the existing Skill/plugin authoring flow, or call `skill_quality_candidate` with `action: "create"` and a complete `files` list. Keep drafts in the private candidate area.
2. Read its current receipt with `skill_quality_candidate({action: "read", candidateId})`. Note the candidate hash and installed base. Source session comes from Host provenance.
3. Export a P01 eval report or prepare an offline report. Normalize the results using the [package fixture](../../packages/package-manager/bundled-plugins/skill-quality/src/fixtures/eval.json). Fill `candidateHash`, `baseHash`, `skillRevision`, original report digest, environment hashes, runtime/model/runner/mode/budget labels, examples and actual execution counts. Supply JSON as `evidenceJson` to `skill_quality_import`. This is a **manual, unverified import**, even if the original report says “runner” or “approved”. Self-assessments use `kind: "self-assessment"`. Host author tests and human review are separate facts that cannot be imported.
4. If authorized to inspect current package inventory, supply its current integrity as `currentInstalledHash`; use `null` when absent or omit when unknown. Matching observations do not establish live freshness. The plugin never reads the global inventory implicitly.
5. Open **Skill quality** in this session's workbench, then Refresh. Review successful and failing examples, execution counts and environment hashes. Candidate edits, baseline changes or a differing installed observation make old evidence stale. Refreshing the candidate clears the installation observation; missing information displays unknown. Re-import the appropriate report and current observation after changes.
6. Run `skill_quality_candidate` with `action: "test"`, `candidateId`, `expectedHash`. Host owns the exact-hash execution confirmation and isolated author-test result. Submit the tested hash with `action: "submit"`. The optional `skill-quality.review` Loop automates these stages with normal approval and a separate confirmation before submission; see the [package README](../../packages/package-manager/bundled-plugins/skill-quality/README.md) for configuration.
7. Publish or reject through Settings → Plugins → candidate review. Rejection never installs or enables the candidate. A failed candidate upgrade leaves installed code and old session pins untouched. New sessions use published backend code; Skills remain live and can update for existing sessions.

Imports are bounded (48 KiB, 24 cases, eight retained candidates per recording session, within a 56 KiB total state budget), reject zero-execution/all-skipped reports, and never execute report content, fetch artifact URLs or call models. The panel only queries the explicitly authorized selected session. Missing services or incompatible backend responses show an unavailable state. If an older pinned session lacks the candidate tools, start a new session for authoring actions. Refresh after checking installation or permissions. Uninstall removes frontend registrations.

Quality is advisory. No score can grant human approval, trust or activation. A publication quality gate needs a separately reviewed generic evidence issuance/validation contract. Automatic eval execution and live inventory freshness are future integrations. These examples exercise synthetic offline evidence; they make no real-model quality or platform claim.
