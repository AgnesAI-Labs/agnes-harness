# 任务经验（RSI）

[English](refinement.md) | 简体中文

[文档导航](../README.zh-CN.md) · [CLI 与 TUI](cli.zh-CN.md) · [Web 工作台](web.zh-CN.md) · [会话与恢复](sessions.zh-CN.md) · [学习记忆](memory.zh-CN.md)

任务经验让 AGH 在后台复盘一个会话，把简短的经验（称为**条目**）留给这个会话后面的轮次：某个命令必须带的参数、某个文件放在意想不到的位置、用户说过的一条规则。同一会话之后的轮次会以注记的形式收到这些条目。记忆类和提示类条目还可以保存到工作区记忆，工作区之后的会话都会读到（见[保存到工作区](#保存到工作区)）。

它**默认关闭**。每次复盘都是记在你账户上的一次单独模型调用。目前还没有证据表明它能改善结果。

## 开启

在 Web 工作台打开**设置 → 通用 → 任务经验**。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 从完成的工作中学习 | 关闭 | 当前 profile 的开关 |
| 复盘如何开始 | 仅手动 | **仅手动**或**手动和自动** |

- **开启**要等 AGH 下次启动才生效。使用前请重启 AGH（daemon，或运行它的 TUI）。在此之前，`/refine` 会提示尚未生效。
- **关闭**立即生效，已打开的会话也一样。
- 设置按 profile 保存。预设里的任何键或旧的 `auto_refine` 设置都不能把它打开。
- 再次保存设置（即使值没变）会取消仍在等待或尚未应用的复盘。

### 开启即表示允许

设置面板列出了开启后允许的事项：

1. 把已证实的技能安装到工作区：复盘写下的技能条目一通过检查，就会省去那一次安装确认，直接安装到工作区，并设为受信与启用。见[保存的技能](#保存的技能)。
2. 允许模型不等第二次证实，直接把技能存到工作区；前提是引用本会话的证据并通过静态检查。
3. 允许模型把记忆存到工作区：复盘写下的经验、你自己的保存和模型的保存都会写进工作区记忆；写不写仍由工作区记忆设置（关闭 / 询问 / 自动）决定。
4. 把处处适用的经验写入用户记忆：适用于所有工作区的经验会**自动写入**用户记忆，**不再询问**（见[保存到用户记忆](#保存到用户记忆)）。

以上几条都不会恢复你已卸载、回滚或删除的内容。

如果本版本之前任务经验就已开启，设置面板会显示一次说明：保存到工作区记忆和工作区技能现在会直接生效，这里不会再次询问；适用于所有工作区的经验会自动写入用户记忆；关闭**从完成的工作中学习**即可停止。关闭这条说明只记在当前浏览器里，不会写进 profile。

## 手动复盘与自动复盘

**手动**复盘由你发起：

- 在 TUI 或 Web 输入框中输入 `/refine [关注点]`。可选的关注点（最多 512 个字符）告诉复盘要看什么。回复会说明复盘已排队，结果显示在对话里。
- `/refine --workspace [关注点]` 排队同样的复盘，复盘留下的条目还会作为你自己的保存存到工作区（见下文）。
- `/refine --user [关注点]` 排队同样的复盘，复盘留下的条目还会作为你自己的保存存到用户记忆，不必等第二次证实（见[保存到用户记忆](#保存到用户记忆)）。`--workspace` 和 `--user` 只能选一个。
- `/refine --unpriced [关注点]`（可与 `--workspace` 或 `--user` 一起用）在没有已知价格的模型上运行复盘。不加它时，在这类模型上用 `/refine` 会被拒绝并说明原因；见[费用](#费用)。

选择**手动和自动**后，复盘还会自行开始：

- 一次用模型摘要替换历史的压缩之后（不包括不生成摘要、直接裁剪历史的兜底方式）；
- 同一个工具在一个会话里以同一种错误失败两次时（同一工具和错误只提示一次）。比较错误时忽略数字、路径和长十六进制串。拒绝类结果不计入：审批被拒、权限、凭据或预算错误、暂停、取消；
- 模型用 `harness_refine` 工具请求时。这在手动模式下也可以，因为是模型自己选择调用的；开启任务经验后这个工具始终可用。

自动复盘有限额。手动复盘不计入这些限额，只会等正在运行的复盘结束。模型自己的请求只受每个会话 40 次的上限约束（没有保存任何内容的复盘不计），没有冷却或其他限制；下表的限额针对压缩之后和连续失败之后的复盘。

| 限额 | 值 |
| --- | --- |
| 任意一次复盘结束后的等待 | 120 秒 |
| 每个会话的自动复盘次数 | 最多 40 次（没有保存任何内容的复盘不计） |
| 一个会话所有复盘的 token（输入加输出） | 524,288（含手动复盘和模型自己的请求） |

每个会话同时只运行一次复盘。新的请求会取代仍在等待的请求，但自动请求永远不会取代等待中的手动请求。复盘在后台进行，你可以继续工作。它的结果只在两轮之间应用：如果有一轮正在运行，就等这一轮结束。

复盘读取会话最近 5 轮：你的请求、模型的回复、工具调用和结果，以及压缩摘要（最多约 24,000 token，回答最多 4,096）。模型自己的话和工具输出一样标为不可信。它使用会话当前的主模型，给模型最多 60 秒（手动复盘 90 秒）。

## 复盘保存什么

一个**条目**有种类、id、标题和正文。种类有四种：

| 种类 | 内容 |
| --- | --- |
| Prompt | 一条范围很窄的行为规则 |
| Memory | 本会话里的一个事实或偏好 |
| Skill | 值得重复的步骤，写成说明 |
| Subagent | 如何把一类重复的工作交给子智能体 |

skill 或 subagent 条目是模型可以阅读并照做的文字，不会安装技能，也不会启动子智能体；把 skill 条目保存到工作区才会安装它（见[保存的技能](#保存的技能)）。

一次复盘最多改动 5 个条目，每个最多 2,000 个字符。违反规则的改动会被单独略去，其余照常保留：第六个改动被忽略，过长的文字被截断，引用了复盘没看到的证据、改写了只以引用形式看到的条目、在复盘读取之后被改过、或绑定了现在无法使用的技能或角色的改动会被丢弃。只有没有任何有效改动时，复盘才会被拒绝。每个种类最多保留 200 个条目；会超出的复盘不会被应用。

### 会话级与任务级条目

每个条目都有一个级别：

- **会话级**条目一直有效，直到会话结束，或被修改、删除、撤回。复盘标为会话级的经验，只要引用了至少一条你自己的请求或一次已完成的工具结果就会得到这个级别，不需要引用原话。只引用网页或文件文字、模型自己的话或摘要的经验会改为任务级。模型用 `harness_propose` 直接提交的经验也是会话级。
- **任务级**条目用于只和这个任务有关、任务结束后就不再有意义的经验，复盘只在这种情况下使用它，默认是会话级。任务级条目属于当前目标（见[持久目标](sessions.zh-CN.md#持久目标)）。目标完成、清除或被新目标取代时，它就失效。暂停、恢复或编辑目标都不影响它。没有目标时，任务级经验不会保存。目标暂时读不到时，它的任务级条目先保留不发，能读到后再发。

任务级条目失效时，会告诉模型。

## 保存到工作区

条目留在各自的会话里。把记忆类或提示类条目保存到工作区，就是把它作为一个**已保存段落**写进工作区记忆的索引（`MEMORY.md`，见[学习记忆](memory.zh-CN.md#已保存的任务经验)）：标题、换行、正文。之后工作区的每个会话都会随工作区记忆一起读到它。把技能类条目保存到工作区，就是把它安装为工作区技能（见[保存的技能](#保存的技能)）。

### 谁能保存什么

有四个入口，都经过同样的检查：

| 入口 | 记作谁发起 | 条件 |
| --- | --- | --- |
| 自动：复盘写下或证实的条目 | 自动 | **手动和自动**模式；复盘第一次应用它时就保存，条目的每个版本只保存一次 |
| 在 TUI 或 Web 输入框中输入 `/refine --workspace [关注点]` | 你 | 复盘结果已应用；它写入的每个条目都会保存 |
| 在 TUI 或 Web 输入框中输入 `/refine --user [关注点]` | 你 | 复盘结果已应用；它写入的每个记忆类或提示类条目都会保存到用户记忆 |
| Web 对话中已应用复盘那一行上的**把 … 保存到工作区**或**把 … 保存到用户记忆** | 你 | 没有其他条件，不调用模型 |
| 模型在 `harness_propose` 或 `harness_refine` 上带 `target: 'workspace'` 或 `target: 'user'` | 模型 | **手动和自动**模式；有本会话的证据 |

只保存**会话级**的**记忆**类、**提示**类和**技能**类条目。任务级条目留在会话里，子智能体类条目不会保存到工作区。分叉出的子会话不保存任何内容。条目必须基于本会话中发生的事；没有本会话证据的模型保存会被拒绝。

每次保存按固定顺序判定，第一项不通过就结束：

1. 任务经验已开启。
2. 你没有收回过这段内容（见下文）；只有你自己的保存能越过这一步。
3. 自动保存的条目是复盘已应用的条目（模型直接提交的经验要等之后的复盘证实）。
4. 条目符合来源和安全规则（会话级、有证据、长度、不像密钥）。
5. 记忆类和提示类条目看工作区记忆模式：**关闭**拒绝；**询问**把保存放进决策列表；**自动**直接写入。技能类条目改为通过下文的技能检查。
6. 工作区记忆还有空间，或技能已安装。

### 审批

**询问**模式下，保存会在 Web 工作台的**待处理**里等你确认，归在**任务经验**下（不在插件请求里）。请求会显示 `MEMORY.md` 的确切改动（改动很长时卡片上会截断并注明，完整改动见请求详情），以及改动前后文件的 hash。**允许一次**只写入这一处改动，而且只写到它所针对的那个文件版本上：如果文件在此期间变了，会针对新文件重新询问。**拒绝**会拒掉这次保存，并算作你收回了这段内容。请求 **7 天**内有效，过期后以 `approval-expired` 结束。后台发起的保存从不自动批准，完全访问权限下也一样。

### 记忆写满时

工作区记忆放不下这个段落时，任何模式下保存都以**记忆已满**结束。不会自动合并或删除任何内容。请你自己腾出空间（在记忆页面撤回或修改段落，或者编辑文件），然后再保存。

### 复核日期与续期

每个已保存段落都有一个**保存后 30 天**的复核日期。从这一天起智能体就看不到它：下一次请求的记忆注记会略去它，系统提示不变。文字仍留在文件里。

- 在到期之前，工作区任一会话中的后续复盘如果用新的证据证实了这个段落，会再续 30 天。促成这次保存的证据不会再算一次。
- 在记忆页面上可以随时**续期**，过期后也可以。

### 收回

你收回的内容优先于自动保存和模型保存：

- 从文件中删除已保存段落（下次打开会话时记录）、在记忆页面**撤回**，或者拒绝一次审批，都会记下你收回了它。此后，同一条目或换了条目 id 的同样内容，自动保存和模型保存都会被拒绝（`user-revoked`）。只在空白或大小写上不同的内容算作相同。
- 对保存的技能，卸载、回滚或删除它的文件夹也是一样，并且同名的任何技能条目都会被拒绝。
- 你自己的保存（`/refine --workspace` 或单条按钮）会重新保存它，并清除这条记录。

### 被人改过的段落

保存不会替换被人原地修改过的段落：条目新版本的自动保存或模型保存会以 `conflict` 被拒绝，人的文字保留。只有你自己的保存或批准过的请求才会替换它。只改了空白或大小写的修改算作未改动，下一个版本可以替换它。如果一次原地更新段落的保存被崩溃打断，且在结算前文件又变了，那么在你自己保存这个条目或撤回这个段落之前，它之后的自动保存和模型保存也会以 `conflict` 被拒绝。

### 对话中的保存记录

每次保存在对话中都有一行：谁发起的（自动、你或模型）、写到哪里（写入用户记忆的会写明**用户记忆（所有工作区）**、在哪里撤回，以及本工作区不读取用户记忆时的说明）、结果如何（已保存、等待你批准、未保存、结果未知），以及被拒绝时的原因，例如记忆已满、审批过期、你已收回（`user-revoked`）、被人改过或文件已变（`conflict`）、暂时无法保存（`unavailable`）。这一行从不显示条目的文字或写入的位置。TUI 以文字显示同样的内容。

被崩溃打断的保存会在下次使用这个工作区时结算。如果文件在此期间变了、无法判断发生了什么，结果是**未知**：段落如果已经写入，在你于记忆页面把它转为普通记忆或撤回之前，智能体看不到它。

## 保存的技能

保存到工作区的技能条目会成为一个工作区技能。它由宿主在后台安装，不占用一轮对话，也不要求安装确认：开启任务经验就是许可（见上面第 1、2 条）。它和其他保存一样按顺序检查，然后：

- **技能里有什么。** 一个 `SKILL.md`：条目 id 是技能名（小写字母、数字、`.`、`_`、`-`），条目标题是描述（最多 200 个字符），条目正文是指令。保存的技能**只有指令**：没有脚本，没有可执行文件或二进制文件。需要脚本时，技能正文会让智能体用自己的文件工具、按它原有的权限和审批去写。绑定到你已批准的某个技能的条目，只是指向那个技能，不会被安装成单独的技能。
- **装到哪里。** 只装到工作区自己的技能文件夹（`.agh/skills/<名称>`），不会装到你的用户技能里。安装后即受信并启用。已经被人写的技能（工作区里的，或用户技能）占用的名称不会被拿走：改动改为草稿保留。
- **交接。** 安装后，会话条目交接给这个技能：它不再作为条目交给模型，也不再计入每类 200 个的上限，模型会收到一次说明，改用这个工作区技能。条目仍留在会话记录里。下一个会话会像其他技能一样在技能目录里看到它。
- **30 天复核。** 每个保存的技能都有一个 30 天后的复核日期。之后的复盘用新证据证实它，就会续期。到期仍未被证实的技能，会在之后打开会话或开启任务经验时被停用（不会卸载），显示为**待复核**。在技能页重新启用即续期 30 天。复核停用不算你收回。
- **更新。** 技能条目的新版本（由复盘写下，或由你、由模型保存）会更新**同名**的保存的技能，不论来自哪个会话，前提是技能保存之后没有人改过。最多保留 5 个旧版本，可以回滚到上一版。被复核停用的技能，更新后仍保持停用。
- **人写的技能永远不会被覆盖。** 技能是人写的，或者有人改过保存的技能（哪怕是在决定和写入之间），改动都只作为**草稿**留给你，这次保存以 `conflict` 拒绝。草稿列在任务经验设置的**保存的技能**下，以纯文本和整份文件的差异显示；需要的部分请手动复制。每个工作区最多保留 20 份草稿。
- **收回。** 在任务经验设置的**保存的技能**下点**卸载**或**回滚到上一版**、在技能页移除这个技能，或删除它的文件夹，都会记下你收回了它。删除文件夹要等这个工作区下一次保存技能时才会被发现；在那之前**保存的技能**仍显示它已启用。此后，同一条目、同名的任何技能条目、或换了名称的同样内容，自动保存和模型保存都会被拒绝（`user-revoked`）。只有你自己的保存（`/refine --workspace`，或复盘记录上的**把 … 保存到工作区**）能重新安装它，并清除这条记录。

安装、更新、停用或移除保存的技能会改变技能目录，从而改变下一次请求的系统提示。这是预期中的变化，会记为一次经验前缀变化（`skill-catalog`）。

## 保存到用户记忆

有些经验在每个工作区都成立：例如你自己说过的偏好“用简短的句子回答”。这样的经验可以写进**用户记忆**（`$AGH_HOME/memory/user/MEMORY.md`，每个工作区都可能读取），而不只是某一个工作区的记忆。满足下面所有条件时，它会像助手自己的记忆一样**自动写入，不再询问**：

- 复盘建议它适用于所有工作区。复盘模型只能建议（`"reach": "user"`）；AGH 只为这样的条目保留这个建议：**记忆类**或**提示类**、为会话级并引用了**你自己的请求**、来自模型没有发起的复盘（你发起的、压缩之后或连续失败之后的复盘），而且不是你要求保存到工作区的那次复盘。只靠工具输出作证据的经验永远不会适用于所有工作区。
- 文字不提任何工作区：没有绝对路径（`/a/b`、`~/…`、`C:\…`），也没有工作区的路径或文件夹名。提到的经验改为作为自动保存存到它的工作区。这项检查只看结构，不判断经验的含义。
- 写下它的复盘已应用它，且处于**手动和自动**模式。不必等第二次证实。
- 通过与保存到工作区相同的检查（会话级、本会话的证据、没有像密钥的文字），并且你没有从用户记忆或本工作区收回过同样的内容。
- 放得下：用户记忆大约只有 **512 字节**（智能体最多看到 `userTokenBudget`，默认 512，按 UTF-8 字节计）。你自己写的内容优先；只有你的文字、已生效的经验与新经验合在一起放得下时才写入。否则不写入（`user-memory-budget`），也不会截断、合并或删除任何内容。

**自己保存。** `/refine --user [关注点]`（TUI 或 Web 输入框）和 Web 对话中复盘那一行上的**把 … 保存到用户记忆**，会把经验作为你自己的保存写入用户记忆。它们不需要第二次证实，也不需要复盘的建议；上面其他检查仍然适用：文字不能提任何工作区（提到的会改为保存到工作区，并在记录中说明），必须放得进用户记忆的预算，通过与保存到工作区相同的检查，并且不是你从用户记忆或本工作区收回过的内容（已撤回的经验不会再保存，你自己保存也一样）。只有**记忆类**和**提示类**条目可以写入用户记忆。对话中的记录会写明它是按你的要求保存到用户记忆的，以及本工作区是否读取用户记忆。

**模型。** 模型也可以在 `harness_refine` 或 `harness_propose` 上带 `target: 'user'` 请求，且只在**手动和自动**模式下（与 `target: 'workspace'` 相同）。它作为模型的保存写入，检查相同，也不必等第二次证实。会话级的**记忆类**或**提示类**经验，只有引用了至少一条你自己的请求或一次已完成的工具结果，才会写入用户记忆；否则最多保存到工作区。它只应该用于对你所有工作区都成立的长期事实或偏好。

**谁会读到。** 只有开启了记忆、并且开启了用户记忆（`userEnabled`）的工作区，智能体才会读到用户记忆。即使经验来自一个不读取用户记忆的工作区，它仍会写入：读取用户记忆的其他工作区会看到它。保存记录会写明这一点。任务经验从不替你打开这些设置。

**智能体看到什么。** 先是你自己写的内容，然后是仍有效的经验，不带标记行。每条经验与工作区段落一样有 **30 天**复核日期；过期后智能体看不到，直到你续期，注记会说明略去了几条。

**收回。** 在记忆页面（**记忆文件**）中，**用户记忆中的任务经验**列出每条经验及其复核日期。**续期**开始新的 30 天；**撤回**把它从用户记忆中删除，并记下你收回了它，同样的内容不会再被写入。在文件里手动删除它，或去掉、损坏它的标记行，同样算作收回。被人原地修改过的经验不会被之后的新版本覆盖。

**关闭开关**会立即停止写入，包括正在进行的那一次：写文件之前会再核对一次开关。

## 条目如何交给模型

条目从不改动系统提示词，而是以注记的形式加进对话：

- 会话开始时和每次压缩之后，发一份**快照**：一段固定的简短说明，然后是条目。Prompt 和 Memory 条目给出全文；Skill 和 Subagent 条目每条只给一行元信息，每类只给最相关的 3 条，并注明还保存了多少条。
- 一次复盘应用之后，发一份**更新**，列出它新增或修改的条目。
- 撤回、删除和失效的通知最先发出，排在任何新条目正文之前。

条目正文标为不受信任的数据而非指令，优先级低于系统规则、项目规则和你最新的指示。其余的条目由模型用 `harness_inspect` 工具读取：搜索（最多 10 条结果）、列出（每页 20 条）或读取一个条目（最多 2,000 个字符）。模型要直接修改已保存的条目，必须先完整读过它。

开关打开时，即使会话里还没有任何条目，也会加上那段说明。

### 模型的工具

开关打开时，模型有三个工具：

- `harness_refine` 请求一次复盘（手动模式下也可以；带 `target` 时需要自动模式）。带 `target: 'workspace'` 或 `'user'` 时，结果还会保存到工作区或用户记忆。
- `harness_propose` 不经复盘调用，直接保存一项改动。它可以新建条目，也可以修改或删除一个已完整读过的条目；`target` 的用法与 `harness_refine` 相同。
- `harness_inspect` 读取已保存的条目，见上文。

## 撤回复盘

在 Web 对话中，每次复盘都有一行记录，显示由什么发起、结果如何，以及它保存或移除的条目名称（从不显示正文）。已应用的复盘有一个**撤回**操作：

- 条目恢复到这次复盘之前的样子。模型会在下一次请求中得知这些条目已撤回。
- 如果之后有条目被改动过，就什么都不撤回，记录行会写明哪些条目改过，需要手动处理。
- 任务经验关闭时也能撤回，任何时候都可以，包括一轮正在运行时。
- 撤回后记录行显示“之后已撤回”。

TUI 以文字显示同样的记录行，但没有撤回操作。客户端可以调用 `_agnes/v1/session.refine.rollback`（[API 与 Schema](../reference/api.zh-CN.md)）。

## 费用

- 每次复盘都是记在你账户上的一次模型调用，使用单独的 token 预算：一个会话的所有复盘共用 524,288 个 token，从不占用轮次的预算。
- 价格为零的模型（免费或本地模型）价格已知：可以在它上面复盘，包括自动复盘；费用为零，只受 token 预算限制。
- 没有已知价格的模型不做自动复盘。你发起的复盘只有在你用 `/refine --unpriced` 同意未知费用后才会运行；token 预算仍然限制它，费用显示为未知。
- TUI 中，底栏、`/status` 和 `/usage` 的数字不含复盘花费，`/usage` 单列一行 **RSI 费用**（免费模型显示零费用，没有已知价格的模型显示“价格未知”）。
- Web 把复盘花费计入会话的用量合计。
- 开启任务经验的会话中，说明和条目注记会给每次请求增加 token。

## 关闭

关闭开关后，新的复盘、等待中结果的应用和条目的发送都会立即停止。模型会收到一条“任务经验已关闭”的注记。三个工具在 AGH 重启前仍会列出，但会回复功能已关闭。已保存的条目仍留在会话记录中，等功能重新开启并生效后会再次发送。如果 AGH 启动时它是开着的，再打开立即生效；否则需要重启。关闭期间仍可撤回。

关闭期间不会向工作区或用户记忆保存任何内容，等待审批的请求会被撤销。之前保存的段落仍留在工作区记忆和用户记忆里，复核日期不变。你仍可在记忆页面续期、撤回或转为普通记忆。保存的技能仍然安装着；关闭期间不会安装、更新或复核任何技能，你仍可卸载或回滚。

## 与 Prime Agent 的比较

- Prime Agent 保存会话条目，也保存对所有会话有效的全局条目（`/refine --global`）。AGH 把条目留在会话中，只保存到当前工作区：记忆类和提示类条目作为工作区记忆的段落，技能类条目作为工作区技能，都带 30 天复核日期；由你发起（`/refine --workspace`、单条保存）或由模型发起，在**手动和自动**模式下复盘应用经验时也会自动保存。
- Prime Agent 的全局库由你发起写入（`/refine --global`），模型也可以写入。AGH 写入用户记忆（开启了它的每个工作区都会读取）的方式是：你发起（`/refine --user` 或**把 … 保存到用户记忆**）、模型发起（`target: 'user'`），或在复盘应用了来自你自己的话、且适用于所有工作区的经验时自动写入；始终限制在约 512 字节以内，并带 30 天复核日期。
- Prime Agent 自写的技能可以是在它自己的内核里运行的 Python 函数。AGH 保存的技能只有指令；需要脚本时由智能体按它原有的权限自己写、自己运行。
- Prime Agent 逐条应用一次复盘的改动，AGH 也是：违反规则的改动被略去，其余照常应用。
- Prime Agent 只在压缩之后自动复盘，冷却 20 分钟。AGH 还会在连续失败之后和模型请求时自动复盘，受上文限额约束（模型自己的请求只有一个较高的上限）。
- AGH 把条目作为不受信任的数据交给模型，在你打开所在 profile 的开关之前，功能一直关闭。

## 已知限制

- 分叉是子会话。分叉、回退（rewind）和子智能体都不做复盘、收不到条目注记，也不能撤回。
- 条目按会话保存，新会话开始时没有条目；保存到工作区的内容经工作区记忆交给它。
- 保存的技能按名称更新：任何会话里同名的技能条目都会更新它（自动保存时，在复盘应用它时更新）。
- 绑定到已批准技能或角色的条目，一旦交给模型，在下一次快照（新会话或压缩）之前，它在条目注记里的那一行不会变，即使技能其间被停用；模型调用 `skill_read` 和 `subagent_spawn` 时会再检查一次。
- 保存的技能经由与其他技能安装相同的发布步骤写入工作区的 `.agh/skills` 文件夹。发布进行时，能改写 `.agh` 的进程可能替换这个文件夹；`.agh` 是配置路径，智能体自己写入那里需要你的批准。
- 草稿和保存的技能的旧版本保存在 profile 的数据目录里，不在工作区里。
- 一条经验是否适用于所有工作区、是否提到某个工作区，都只按结构判断：它是会话级的记忆类或提示类经验，引用了你自己的请求（自动写入如此；模型自己的请求引用一次已完成的工具结果即可），文字里没有路径、工作区路径或文件夹名。只有网页或文件文字、模型自己的话，不能作为一条经验的依据。AGH 不判断经验的含义。请在记忆页面检查写进用户记忆的内容。
- 工具输出以及网页或文件文字会影响保存的内容：复盘把它们当作证据来读，经验可能复述其中的话，尽管它们被标为不可信数据，凭据也会被遮蔽。保存的内容你都看得到，也可以收回：在记忆页面撤回一条经验（工作区记忆中的一个段落，或用户记忆中的一个部分），同样的内容之后不会再被保存。
- 用户记忆中过了复核日期的经验仍留在文件里，只是智能体看不到，直到你撤回或删除它；不会替你删除。它的记录放在文件旁边（`$AGH_HOME/memory/user/refinement.json`），由这台机器上的所有 profile 共用。
- 对保存的检查只看结构：来源、长度、像密钥的文字、记忆大小。它们不判断一条经验对不对。请在记忆页面检查保存了什么。
- 在没有系统沙箱的平台上（例如 Windows，或完全访问权限下没有 bubblewrap 的容器），智能体的 shell 可以直接读取和修改记忆文件，包括不给它看的段落。shell 去掉某个段落的两行标记后，下次打开会话时它会变成普通记忆。见[学习记忆](memory.zh-CN.md#审批与隐私)。
- 用 `--standalone` 启动的终端运行自己的内嵌宿主，不提供 `/refine`：它会回复不支持这个命令。自动复盘在那里照常运行。
- 规划模型没有已知价格时，自动复盘不会开始，你发起的复盘需要 `/refine --unpriced`。价格为零算作已知价格。在模型设置中添加时没有填写价格的模型按零价格记录，因此算作免费。
- 带有条目注记的轮次可能会要求你批准更多命令。注记是不受信任的内容，所以在干净轮次中能放行命令的审批规则可能不再适用。用 `harness_inspect` 读取条目的轮次也一样。
- 交给复盘模型之前，工具输出中明显的凭据会被遮盖，但遮盖并不完整。

## 诊断与导出

诊断包、诊断事件导出和会话导出都包含原样的对话，包括模型收到的条目注记和经验工具的文字。分享之前请先检查。保存记录和工作区的保存记录不含条目文字，但它们周围的对话含有。保存的技能的文字和其他技能一样，在工作区里它的 `SKILL.md` 中。
