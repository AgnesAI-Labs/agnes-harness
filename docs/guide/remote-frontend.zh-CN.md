A、B 使用同一套完整标准 Harness。A 托管自己的页面，普通连接由浏览器直接访问 B 的 HTTP/WebSocket 服务，不使用 SSH；LLMSG 沙箱使用下述隔离入口转发。普通直连的本地 BFF 只用于凭证交换。B 启用已安装的云端插件，A 不需要安装该插件。

## LLMSG 沙箱入口

用户先在 LLMSG 开通沙箱，再在 A 选择保存 AGH Key 的本地凭证，点击“保存并连接”。连接设置只展示凭证与连接状态，不展示沙箱地址或手动地址入口；地址由既有接口按 Key 自动获取。此连接只查询已开通的实例，不自动开机、续期或计费。旧的显式 `?remote=` 链接与内部地址校验继续兼容。

A 的 daemon 使用所选 `agh_sk_` Key 请求 `POST /llmsg/api/agh/connection`，携带 `Authorization: Bearer <Key>` 和 `{}`。LLMSG 按 Key 返回当前绑定的 HTTPS `8443-<实例>.<地域>.tencentags.com` 来源及业务 Token；旧调用传入 `sandbox_url` 时仍要求地址完全一致。需要部署支持空请求体的 LLMSG 版本。原始 Key 和平台 Token 不保存在浏览器中。

A 的 daemon 优先读取环境变量 `AGH_LLMSG_API_BASE_URL`；不存在时默认使用 `https://api.llm.sg`，请求 `POST https://api.llm.sg/llmsg/api/agh/connection`。已配置的变量始终优先：空值、无效地址、鉴权失败、超时或其他连接失败均保持原有错误处理，不会降级请求默认服务。自定义变量必须是 LLMSG API 的**来源地址**，不要附 `/v1` 或接口路径，修改后按原有启动流程重启该 daemon。必须使用 HTTPS；隔离测试允许显式指定本机回环 HTTP 服务。这是 A 侧部署配置，不属于 B 云端插件原有三个变量。

自动连接只保存凭证引用和已发现地址；重新连接或恢复自动连接时重新查询绑定。断开会取消查询，迟到响应不覆盖新连接；显式 `?remote=` 仍优先。普通 API Key 不会发送到自动发现接口。平台 Token 刷新继续绑定首次解析的实例，不会将旧连接迁移到其他实例。

daemon 取得平台业务 Token，在 B 原有 Key 认证时携带。该 Token 仅经过私有 daemon 到 launcher 的 RPC，由 launcher 在 A 的隔离云端监听上注册数量有界、会过期的授权。浏览器只收到既有 AGH 临时能力凭据及 `proxied` 标识。HTTP、WebSocket 和插件资源通过隔离来源访问，每次出站请求为固定的授权沙箱添加 `e2b-traffic-access-token`。不转发浏览器的 Cookie、Authorization 或伪造业务 Token 头，不跟随重定向；该监听仍不能访问 A 的管理 API，不转发 49983 管理入口。

新连接查询当前凭据。已建立的 WebSocket 断线或上游拒绝访问后，下次请求/握手通过同一本地凭证引用刷新；并发刷新合并为一次，刷新失败退避 30 秒，不延长浏览器能力凭据原有有效期。失败的业务写请求直接返回，不自动重放。缺失配置、地址错误、Key 被拒绝、实例不可用（409）和限流（429）都有本地化提示，不将上游响应细节或 Token 投射到界面。

普通 IP/域名连接仍走原有直连。此次入口适配不改变 B 的云端模型、工具审批、计费插件、工作区隔离或模型网关出网规则，这些能力须在目标沙箱中单独验收。

## Key 与发布合同

环境 Key 部署使用云端插件 0.9.0 的回退模式，不下发 `cloud-key` 文件。`AGH_CLOUD_KEY` 或 `AGH_API_KEY` 必须进入 B 的 daemon／Worker 启动环境；环境模式更换 Key 仍需按 B 流程重启相关进程。0.9.0 的文件优先读取与轮换规则见部署方提供的插件 0.9.0 对接文档；启用文件下发前仍需补齐 Core 私有路径保护，本次不开放 Key 重置。

已安装、受信任、已启用的插件注册 profile 级查询服务 `frontend.publish`，并在客户端描述符中声明。服务接收 `{}`，返回如下结构；其中 `keySha256` 是部署 Key 的 SHA-256 校验值，实际必须为 64 位小写十六进制字符串，原始 Key 不进入服务返回值：

```json
{"enabled":true,"access":"key-owner","host":"0.0.0.0","port":8443,"auth":{"keySha256":"<64 位校验值>"}}
```

普通自定义服务在“设置 → 高级 → 云端连接”的手动配置中填写地址；LLMSG 连接自动获取地址。用户从**本地凭证下拉列表**选择已保存在 A 凭证管理中的通用凭证。此页不输入原始 Key，也不自动创建或修改凭证；“管理本地凭证”会定位到 A 的“设置 → 权限 → 凭据”，新建时将与 B 相同的 Key 保存到凭证值中，返回云端连接后可直接选择，“刷新凭证列表”可更新选项。即使从云端会话打开设置，列表和管理入口也始终来自 A，不使用 B 的凭证库。重名凭证会附加引用尾号以区分。

凭据列表会将当前绑定的凭据标为“此浏览器的云端连接”，与后端保存的配置引用一起显示；断开连接后清除这一浏览器标记。此标记只表示本浏览器的连接配置，不代表其他设备的使用记录，也不改变后端凭据管理接口。

云端插件提供可用模型列表时，同一 `route`、同一模型 ID 会保留沙箱后端已声明的上下文容量及思考档位。只有后端声明了相应能力，界面才开放设置；不支持思考档位的模型显示“此模型不支持”。上下文预算仍由原有会话模型接口保存并校验，不从其他模型或本地账户借用容量。

浏览器只保存地址和 `secret://generic/...` 引用，不把原始 Key 放进 localStorage、sessionStorage、URL、会话 journal 或侧栏状态。更换选择只更新绑定，不替换凭证值；断开云端不会删除凭证，旧版已保存的绑定会自动选中。同一浏览器重开页面可自动重连，换浏览器需重新选择已有凭证。该浏览器绑定尚不计入凭证管理的后端配置引用列表；删除凭证后，下次认证提示重新配置。

连接流程：

1. 浏览器向 **A 本地** `/_agnes/cloud-connection/authorize` 提交凭证引用（手动配置时同时提交 B 的地址）；此入口检查同源请求，并经私有连接调用 admin 级 `admin.cloud.authorize`，要求凭证读写和插件激活管理权限。
2. A 的 daemon 从自身凭证库读取 Key，向 B 的 `POST /_agnes/remote-frontend/auth` 提交 `{key}`。B 对比部署 Key，大小写及内容必须完全一致；不调用第三方平台验证其购买状态。
3. B 验证成功后签发有效期 8 小时的临时连接凭证。浏览器只收到该临时凭证，再直接连接 B 的 HTTP／WebSocket，不经 A 转发会话流量。
4. HTTP、插件资源及 WebSocket 路径均位于 `/_agnes/remote-access/<临时凭证>/...`，相对模块资源继承该路径。B 校验有效性后剥离前缀，转发到固定本机服务。裸 API、文件／插件资源及 WebSocket 均拒绝未认证访问，不能只靠通过首次握手绕过后续校验。临时凭证也是 bearer 凭证，应避免记录完整资源 URL；服务使用 `no-store` 和 `no-referrer`。到期断开 socket，重新认证获得新凭证。

`key-owner` 仍授予当前 profile 的完整工作台权限，包括工作区、工具、设置和插件管理；原有工具审批继续适用。它不建立多用户身份或租户隔离。拥有 Key 的调用者仍可停用／卸载云端插件，专门的防断链保护尚未实现。历史 `public-owner` 合同在标准服务端保留兼容，**新版 A 的云端连接不降级为免认证连接**；本插件 0.9.0 固定使用 `key-owner`，不能通过配置关闭校验。

`agh serve` 读取当前就绪的已安装 roster，通过私有连接调用声明服务，持有云端监听器，仅转发到固定的本机 Web／daemon 端点。默认本地监听仍执行原有 Host／Origin 检查；daemon 原有的多用户远程 WSS 保持独立。

同一时刻只允许一个发布 owner。插件缺失、停用、阻塞、声明冲突或查询失败时不发布。每个 HTTP 请求和 WebSocket 升级均检查当前声明；500 毫秒协调循环在撤权或配置变化后关闭入口和已有连接，Worker RPC 失败时可能额外等待其有界超时。关闭 Web launcher 同样停止发布，在途任务不隐式取消。

可选 `tls: {"certFile":"...","keyFile":"..."}` 指向 B 的证书和私钥，同时提供两项后使用 HTTPS／WSS，缺省 HTTP／WS。HTTP 只适合可信测试网络；实际部署应使用 HTTPS／WSS 或沙箱平台的 HTTPS 网关保护 Key 及连接凭证传输。HTTP API 和 WebSocket 共用端口。

## 双机操作

1. A、B 更新并构建配套标准 Harness，通过仓库工具链入口执行 `--filter @agnes/cli build:local`，并重启各自 daemon 以加载新代码；B 更新为配套云端插件 0.9.0。
2. B 的部署环境注入 `AGH_CLOUD_KEY`。已有 daemon 必须按 B 部署流程停止并在新环境下重新启动，让 daemon／Worker 继承变量。通过 `agh plugins add /绝对路径/agh-cloud-plugin-0.9.0.tgz` 安装并确认信任，保持相同 home／profile 的 `agh serve` 运行。
3. 激活后 launcher 输出 `key-owner frontend: ...`。通过标准插件设置修改 host、端口或 TLS 文件，并让 B 的防火墙允许选定端口。不要将 Key 写入插件设置文件。
4. 打开 A 自己的页面，进入“设置 → 高级 → 云端连接”，输入例如 `http://192.168.1.20:8443`，从列表选择值与 B 的 Key 一致的本地凭证，点击“保存并连接”。使用 B 实际可达的地址，不使用监听地址 `0.0.0.0`。
5. 在会话搜索下方使用“本地／云端”标签切换环境。本地保留原有项目、临时会话等分区，云端就绪后从云端列表加号创建会话。云端工作区、工具和当前模型执行仍归 B。直接打开 B 的裸云端地址不会显示免认证工作台，请从 A 配置 Key 连接。

浏览器的私有网络许可、混合内容和证书规则仍然适用；HTTPS 页面需要兼容的安全远程端点。

## 客户端路由与状态

页面 `remote` 参数选择 B。在加载控制器前，完成 Key 认证后，浏览器通过受保护的 `/_agnes/remote-frontend` 检查发布版本、访问模式、实例身份和固定 WebSocket 路径。A 提供自己的前端代码及共享 vendor 模块；后端 HTTP、插件资源和 socket 使用 B。CSP 只增加明确选择的来源及其 WS(S) 来源，不向 B 发送 A 的 Cookie，后端 HTTP 不跟随重定向到其他目标。

A 的统一侧栏通过“本地／云端”标签切换，每次显示一个环境的会话列表，以“环境 + 会话 ID”定位会话。云端地址保存在 A 的当前浏览器中，刷新后自动恢复连接。“加载更多”逐步读取云端历史记录，最多 5,000 条。侧栏复用标准 Logo、新对话、折叠、搜索和设置组件；新对话、搜索入口和快捷键跟随当前标签。会话行沿用原来的时间、运行状态与操作菜单，重命名、置顶、归档等交给该环境原有控制器执行。

“云端”标签以红绿灯显示“未配置、连接中、已就绪、连接中断、连接失败”之一：就绪为绿灯，中断或失败为红灯，连接中为黄灯，未配置为灰灯；悬停可查看说明，选中本地标签时仍可见。只有对应前端完成启动并成功读取后端会话和运行状态才显示已就绪，填写地址不代表连接成功。云端断线时从本地设置修复连接；未配置时点击云端列表加号会打开设置中的云端连接页。旧的 `?connection=1` 入口也打开此设置页。

A 为本地与云端各保留一个前端运行上下文，均加载 A 的前端代码；云端上下文直接请求 B 或经过 LLMSG 入口转发。切换标签不会重载上下文，也不会取消另一端的任务；草稿和进行中的对话分别保留。统一侧栏只接收会话列表、运行状态投影并发送导航请求；会话事实、工作区访问、执行和审批仍由各自后端决定。

命令 journal、输入草稿和模型／权限记忆按后端来源与实例身份隔离。无论当前选中本地还是云端会话，统一侧栏的插件、智能体、自动化、MHS 和设置均打开 **A 的本地管理页面**；云端对话内的管理快捷入口也转到 A。直接打开 B 自己的 Web 时，管理页面仍属于 B。此规则只改变界面导航，不缩减部署 Key 原有的后端管理权限。

云端会话的工作区目录选择、输入框 `@` 文件搜索和 `$` 技能引用仍读取 **B**；执行时使用的插件、MCP、技能和模型凭证也属于 B，修改 A 的管理配置不会替换它们。会话搜索、新建及会话行操作仍使用对应环境。云端连接配置始终属于 A 的浏览器，保存连接时可留在设置中观察状态，再从云端组新建或选择会话。云端断线不影响本地会话，恢复服务后可重新连接。主动断开云端或更改云端地址会释放旧云端页面上下文，重连后从 B 恢复记录；未提交草稿不保证跨主动断开保留。B 上已启动的任务遵循其后端生命周期。

本分支需要配套 A、B 标准 Harness 与 B 的云端插件 0.9.0。当前支持一个本地环境和一个云端连接；源码同步不代表现有 B 已部署新版。

云端插件 0.6.0 启动时必须读取两个部署环境变量，模型列表和推理共用同一个 API Base URL 和授权 Key：

```sh
export AGH_CLOUD_KEY='第三方平台授权 Key'
export AGH_CLOUD_API_BASE_URL='https://api-llmsg-dev.agnes-dev.com/v1/'
```

B 的 `cloud.models.list` 在统一地址后拼接 `models`，使用 GET；云端适配器在相同地址后拼接 `chat/completions`，使用兼容 OpenAI 的 POST／SSE。两者均使用 `Authorization: Bearer <AGH_CLOUD_KEY>`。上述配置对应 `https://api-llmsg-dev.agnes-dev.com/v1/models` 和 `https://api-llmsg-dev.agnes-dev.com/v1/chat/completions`。[New API 模型列表合同](https://docs.newapi.pro/zh/docs/api/ai-model/models/list/listmodels)和[聊天协议示例](https://www.agnes-ai.cn/zh-Hans/docs/quickstart)仅说明请求协议，实际目的地址由部署环境配置。

Base URL 可带部署路径，自动规范末尾斜杠，必须是 HTTP(S)，不得包含账号密码、查询参数或 fragment；缺失或非法时拒绝启动。0.4 版的 `AGH_CLOUD_MODELS_BASE_URL` 和 `AGH_CLOUD_INFERENCE_BASE_URL` 不再读取，请移除它们，设置 `AGH_CLOUD_API_BASE_URL` 后重启 B 的 daemon／Workers。旧地址不作回退。现有 `AGH_CLOUD_KEY` 及 A 对应的凭证绑定继续使用。已有会话固定插件 generation，请新建云端会话验证升级，或在运行时设置中将符合条件的旧会话迁移到当前插件。

A 的云端 frame 通过 `conversation.input.model.catalog` 使用云端模型下拉。B 自己的 Web 打开已有会话时，也会按会话记录的 `agnes-cloud-primary` 路由识别云端模型；本地草稿及其他路由的会话通过 `actions.renderDefault` 使用原生模型控件，B 的本地模型记忆只接纳本地配置目录中的模型，查看插件贡献的模型不会覆盖原有偏好，因此 B 需更新配套标准前端。离开云端模型会话会清理前端目录贡献，过期目录响应不能污染本地会话。云端控件从 B 查询目录，支持搜索、刷新以及草稿／已有会话的模型选择。选择走标准会话接口，由 B 校验后保存。已有会话保留当前模型，直到用户手动切换；新云端草稿使用云端目录。B 在内存中装配插件专属路由 `agnes-cloud-primary`，不改写原有本地模型账号、凭证、路由或默认模型；A 的本地会话及 B 的普通本地会话继续使用原生模型控件。此 profile 插槽通过 `value` 提供模型栏状态，通过 `actions.select`／`actions.setCatalog` 选择模型和发布当前前端上下文的目录；卸载或清理后恢复该上下文的原生目录。

插件复用 Host 提供的公开入口 `@agnes/ai/model-adapter`（`PiAdapter`、`isChatModelId`）。新增可选的 `ModelAdapterDefinition.contributeRoutes(signal)`，已有适配器无需修改。已安装的提供方可在装配时贡献自己的运行时路由，不写入 profile；路由 API 必须等于适配器注册 ID，与已配置或其他插件路由重名时拒绝。贡献及实例遵循插件生命周期清理。切换到新出现的模型时，Worker 先刷新运行时模型快照，再执行原有严格校验。流式回复、工具往返、取消、请求记录和模型错误沿用 Core／Worker 标准链路；云端失败不会回退为本地模型。

上游列表只有 ID，未提供完整能力及价格。本版将聊天模型按仅文本、原生工具调用、不提供思考强度控制接入；部署默认上下文 32,768、输出 4,096 tokens，可用插件设置 `modelContextWindow`／`modelMaxTokens` 调整，输出必须小于上下文。价格字段为 0 代表**尚未接入价格信息**，不代表服务免费；工具计费与上报遵循下文合同。已知 Agnes 图片／视频生成 ID 使用已有聊天模型判定过滤，未知供应方 ID 需由部署方确认；扩展能力前应验证供应方支持情况。

## 工具调用用量上报

0.9.0 需要配套 Harness Extension API 5.23.0；旧版底座会拒绝安装。已有会话固定插件 generation，请新建会话，或通过现有运行时设置迁移到当前插件；部署及进程重启需按批准的 B 升级流程执行。

模型请求使用 `AGH_CLOUD_KEY`，也接受平台注入的 `AGH_API_KEY`；模型网关读取 `AGH_CLOUD_API_BASE_URL`，也接受 `OPENAI_BASE_URL`。新旧变量同时存在时必须一致。插件不修改环境变量和本地模型凭证，也不使用普通 `OPENAI_API_KEY` 替代云端授权。

```sh
export LLMSG_TRACK_URL='https://api-llmsg-dev.agnes-dev.com/llmsg/api/track/tool_calls'
```

该变量是完整上报地址，不追加 `/v1/`；未配置时使用模型网关同源的 `/llmsg/api/track/tool_calls`。上报以 HTTP POST 和调用模型时同一个 Bearer Key 发送，仅含 `request_id` 及工具名到次数的 `tool_calls`。

仅统计云端主模型路由产生的工具：复用 `request/sent`、`tool/call`、`effect/intent`、`tool/result` 和 `cost/ledger`；读取响应头 `X-Oneapi-Request-Id`，不使用响应体 ID 或自行生成 ID。仅成功完成的调用计一次；明确未发送、审批拒绝、未执行、HTTP 非 2xx 响应及超时失败均不计；成功空结果仍计一次；同一调用内部重试去重。异步工具受理后保持待定，仅在收到同 lane、system 来源且精确关联原调用的最终成功结果后计一次；最终失败、取消及结果未知不计，重复结果不重复计数。父子会话独立计数，不累计复制子会话记录。

派发阶段写入独立的 `x/core/tool-dispatch` 附注，标记 `ignorable: true`，不再写入新的 `tool/result`。附注与结果在同一事务中提交，并先于结果，数据为 `{version: 1, toolUseId, phase}`；`phase` 仍为 `not_sent`、`may_have_sent` 或 `responded`，通过 `sourceEventSeqs` 关联原工具调用。Core 内部恢复状态保持原样。旧客户端可跳过附注，工具结果继续使用原格式；协议仍接受历史 `tool/result.dispatchPhase`，不能直接删除历史读取能力。

配套 `0.9.2-successful-tools.20261119.1` 计费插件只接受同一调用、同一 lane 的 Core 可信附注，不再采用旧结果中的阶段；投影缓存版本为 6，按新规则回放历史，既有入队请求体、收据和上报幂等标识保持不变，不追溯改写历史请求。`web_fetch` 非 2xx 响应保留正文并标记 `isError: true`；普通调用仅在可信 `responded` 且 `isError` 不为 `true` 时计数。Core 与插件须配套升级，不能用旧 0.7.0 插件读取新 Core，也不能用没有新证据的旧账本验证新版计数。此调整不改变 LLMSG 上报参数、价格、数据库结构或 Key 重置策略。

恢复或关闭中断会话时，仅在调用策略及 effect 绑定校验通过后复用已落盘的派发阶段，附注仍与合成结果同事务提交。没有可信阶段的旧记录、尚未校验的嵌套中断和 Host `dispatch_pending` 不根据错误码推算为已派发；本次不保证补齐全部历史费用。

按 turn 结束触发发送，按每次模型请求分别一次报全；没有工具不提交空记录。有未结算工具的请求继续等待，不能先提交部分次数。接口限制为最多 50 种工具、名称 1～64 字符、每种次数 1～1000；超限、缺失请求 ID 或 Key 身份不一致会保留为异常，不能拆分、截断或换新 ID。

队列使用 Host 提供的 profile 级插件持久化存储。投影只做纯汇总，完成 hook 只入队及记录收据；后台发送不占用 hook 时限。已入队记录在重启后自动恢复；落盘与入队之间发生进程崩溃时，重开原会话通过投影补采。尚未重开的历史会话不由插件主动遍历。持久化目录必须部署在沙箱可保留的存储上，删除整个沙箱磁盘不在恢复保证内。

HTTP 成功（含重复确认）标记完成；超时、429、5xx 使用相同 ID 和内容退避重试；其余状态保留异常并停止自动重试。Key 变更后旧队列不能用新 Key 补报。插件停用停止发送并保留存储，不改变已完成对话结果。`cloudusage.check` 提供 queued、blocked、sent 数量；读取状态不返回 Key 或上游错误原文。持久化仅含计费标识和次数，不保存原始 Key、工具参数、对话内容或工作区文件。

### 前端隔离与原生导航

A 的可信工作台和本地管理保持在 `http://127.0.0.1:<端口>`。云端会话从独立来源 `http://127.0.0.1:<隔离端口>` 加载标准前端静态资源；此来源提供允许清单内的构建资源，LLMSG 模式还转发已授权的 B 能力路径；不能访问 A 的 BFF、本地插件资源、凭证、daemon socket 或上传处理器。A 的主文档不会允许 B 执行脚本，只有隔离的云端文档在 CSP 中允许已选 B 的来源。

消息桥同时校验来源和窗口，只为 A 当前配置的 B 返回临时连接凭证。云端不能选择凭证引用或授权目标、读取 A 的凭证列表、修改连接配置。展示偏好仅同步语言、主题和字号。隔离监听器在 Web 服务启动时分配临时端口；重启 A 会创建新的云端页面上下文，未发送草稿可能丢失，B 已保存的会话仍然保留。本地、云端标签在 A 的原生侧栏内渲染，保留品牌、应用导航、插件首页入口和侧栏插槽。设置保持模态行为；关闭设置后再选择侧栏会话。

云端模型插槽除 `owner.draft` 外，还获得仅用于展示的 `owner.remote` 提示，并通过 `actions.setCatalog` 提供目录数据。插件调用 `actions.renderDefault()` 复用原生模型选择器及其键盘操作。
