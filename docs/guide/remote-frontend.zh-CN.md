# 本地前端连接另一台电脑的后端

[English](remote-frontend.md) | 简体中文

[部署](deployment.zh-CN.md) · [插件](packages.zh-CN.md) · [Web 工作台](web.zh-CN.md)

A、B 使用同一套完整标准 Harness。A 托管自己的页面，浏览器直接连接 B 的 HTTP/WebSocket 服务，不使用 SSH。A 的本地 BFF 只用于凭证交换，会话流量不经 A 转发。B 启用已安装的云端插件，A 不需要安装该插件。

## Key 与发布合同

云端插件 0.2.0 启动时读取环境变量 `AGH_CLOUD_KEY`。缺失、空值或纯空白会导致插件启动失败，不发布云端端口。Key 由第三方启动 B 的沙箱时注入，必须进入 daemon／Worker 的进程环境；只给已运行的 `agh serve` 设置变量不会改变旧 daemon 的环境。插件保留启动时的值，更新 Key 后需要重启 B 的相关进程。

已安装、受信任、已启用的插件注册 profile 级查询服务 `frontend.publish`，并在客户端描述符中声明。服务接收 `{}`，返回如下结构；其中 `keySha256` 是部署 Key 的 SHA-256 校验值，实际必须为 64 位小写十六进制字符串，原始 Key 不进入服务返回值：

```json
{"enabled":true,"access":"key-owner","host":"0.0.0.0","port":8443,"auth":{"keySha256":"<64 位校验值>"}}
```

A 在“设置 → 高级 → 云端连接”输入地址和 Key。保存时通过 A 本地标准凭证管理 API 创建或更新通用凭证，凭证标签为 `Cloud · <服务地址>`，可在 A 的凭证管理中查看元数据、改名、更换或删除。浏览器只保存地址和 `secret://generic/...` 引用，不把原始 Key 放进 localStorage、sessionStorage、URL、会话 journal 或侧栏状态。更换 Key 更新同一条凭证；断开云端不会自动删除凭证。地址与引用的绑定属于当前浏览器，换浏览器需重新配置绑定；同一浏览器重开页面可自动重连。该浏览器绑定尚不计入凭证管理的后端配置引用列表；删除凭证后，下次认证提示重新配置。

连接流程：

1. 浏览器向 **A 本地** `/_agnes/cloud-connection/authorize` 提交 B 的地址和凭证引用；此入口检查同源请求，并经私有连接调用 admin 级 `admin.cloud.authorize`，要求凭证读写和插件激活管理权限。
2. A 的 daemon 从自身凭证库读取 Key，向 B 的 `POST /_agnes/remote-frontend/auth` 提交 `{key}`。B 对比部署 Key，大小写及内容必须完全一致；不调用第三方平台验证其购买状态。
3. B 验证成功后签发有效期 8 小时的临时连接凭证。浏览器只收到该临时凭证，再直接连接 B 的 HTTP／WebSocket，不经 A 转发会话流量。
4. HTTP、插件资源及 WebSocket 路径均位于 `/_agnes/remote-access/<临时凭证>/...`，相对模块资源继承该路径。B 校验有效性后剥离前缀，转发到固定本机服务。裸 API、文件／插件资源及 WebSocket 均拒绝未认证访问，不能只靠通过首次握手绕过后续校验。临时凭证也是 bearer 凭证，应避免记录完整资源 URL；服务使用 `no-store` 和 `no-referrer`。到期断开 socket，重新认证获得新凭证。

`key-owner` 仍授予当前 profile 的完整工作台权限，包括工作区、工具、设置和插件管理；原有工具审批继续适用。它不建立多用户身份或租户隔离。拥有 Key 的调用者仍可停用／卸载云端插件，专门的防断链保护尚未实现。历史 `public-owner` 合同在标准服务端保留兼容，**新版 A 的云端连接不降级为免认证连接**；本插件 0.2.0 固定使用 `key-owner`，不能通过配置关闭校验。

`agh serve` 读取当前就绪的已安装 roster，通过私有连接调用声明服务，持有云端监听器，仅转发到固定的本机 Web／daemon 端点。默认本地监听仍执行原有 Host／Origin 检查；daemon 原有的多用户远程 WSS 保持独立。

同一时刻只允许一个发布 owner。插件缺失、停用、阻塞、声明冲突或查询失败时不发布。每个 HTTP 请求和 WebSocket 升级均检查当前声明；500 毫秒协调循环在撤权或配置变化后关闭入口和已有连接，Worker RPC 失败时可能额外等待其有界超时。关闭 Web launcher 同样停止发布，在途任务不隐式取消。

可选 `tls: {"certFile":"...","keyFile":"..."}` 指向 B 的证书和私钥，同时提供两项后使用 HTTPS／WSS，缺省 HTTP／WS。HTTP 只适合可信测试网络；实际部署应使用 HTTPS／WSS 或沙箱平台的 HTTPS 网关保护 Key 及连接凭证传输。HTTP API 和 WebSocket 共用端口。

## 双机操作

1. A、B 更新并构建配套标准 Harness，通过仓库工具链入口执行 `--filter @agnes/cli build:local`，并重启各自 daemon 以加载新代码；B 更新为云端插件 0.2.0。
2. B 的部署环境注入 `AGH_CLOUD_KEY`。已有 daemon 必须按 B 部署流程停止并在新环境下重新启动，让 daemon／Worker 继承变量。通过 `agh plugins add /绝对路径/agh-cloud-plugin-0.2.0.tgz` 安装并确认信任，保持相同 home／profile 的 `agh serve` 运行。
3. 激活后 launcher 输出 `key-owner frontend: ...`。通过标准插件设置修改 host、端口或 TLS 文件，并让 B 的防火墙允许选定端口。不要将 Key 写入插件设置文件。
4. 打开 A 自己的页面，进入“设置 → 高级 → 云端连接”，输入例如 `http://192.168.1.20:8443` 和相同 Key，点击“保存并连接”。使用 B 实际可达的地址，不使用监听地址 `0.0.0.0`。
5. 侧栏“项目”下同时显示“本地会话”和“云端会话”，均可展开／收起，云端就绪后从云端组加号创建会话。云端工作区、工具和当前模型执行仍归 B。直接打开 B 的裸云端地址不会显示免认证工作台，请从 A 配置 Key 连接。

浏览器的私有网络许可、混合内容和证书规则仍然适用；HTTPS 页面需要兼容的安全远程端点。

## 客户端路由与状态

页面 `remote` 参数选择 B。在加载控制器前，完成 Key 认证后，浏览器通过受保护的 `/_agnes/remote-frontend` 检查发布版本、访问模式、实例身份和固定 WebSocket 路径。A 提供自己的前端代码及共享 vendor 模块；后端 HTTP、插件资源和 socket 使用 B。CSP 只增加明确选择的来源及其 WS(S) 来源，不向 B 发送 A 的 Cookie，后端 HTTP 不跟随重定向到其他目标。

A 的统一侧栏按环境分组，以“环境 + 会话 ID”定位会话。云端地址保存在 A 的当前浏览器中，刷新后自动恢复连接。“加载更多”逐步读取历史记录，最多每组 5,000 条。侧栏复用标准 Logo、新对话、折叠、搜索和设置组件；搜索入口和快捷键打开当前环境原有的会话搜索面板。会话行沿用原来的时间、运行状态与操作菜单，重命名、置顶、归档等交给该环境原有控制器执行。

“云端会话”分组标题以红绿灯显示“未配置、连接中、已就绪、连接中断、连接失败”之一：就绪为绿灯，中断或失败为红灯，连接中为黄灯，未配置为灰灯；悬停可查看说明，收起分组后仍可见。只有对应前端完成启动并成功读取后端会话和运行状态才显示已就绪，填写地址不代表连接成功。云端断线时从本地设置修复连接；未配置时点击云端组加号会打开设置中的云端连接页。旧的 `?connection=1` 入口也打开此设置页。

A 为本地与云端各保留一个前端运行上下文，均加载 A 的前端代码；云端上下文直接请求 B。切换或收起分组不会重载上下文，也不会取消另一端的任务；草稿和进行中的对话分别保留。统一侧栏只接收会话列表、运行状态投影并发送导航请求；会话事实、工作区访问、执行和审批仍由各自后端决定。

命令 journal、输入草稿和模型／权限记忆按后端来源与实例身份隔离。文件引用、目录选择、插件、MCP 和模型凭证归属各自环境。设置、插件等入口作用于顶部显示的当前环境；云端不可用时设置入口回退本地，云端连接配置始终属于 A 的浏览器。保存连接时可留在设置中观察状态，再从云端组新建或选择会话。云端断线不影响本地会话，恢复服务后可重新连接。主动断开云端或更改云端地址会释放旧云端页面上下文，重连后从 B 恢复记录；未提交草稿不保证跨主动断开保留。B 上已启动的任务遵循其后端生命周期。

本版需要同时更新 A、B 的标准 Harness，以及 B 的云端插件 0.2.0。当前支持一个本地环境和一个云端连接。

本阶段只实现部署 Key 读取、A 的凭证管理和连接校验。第三方分发、购买、模型目录、推理及用量上报均未接入。后续由 B 的云端插件使用同一个部署 Key 加载第三方云端模型目录并执行模型请求，A 读取 B 提供的目录；B 原有本地模型配置保持独立。

远端插件界面代码沿用现有受信任插件模型，在 A 的工作台页面中执行。本阶段按环境隔离后端执行与存储，不为这类浏览器代码提供脱离 A 页面权限的沙箱。连接同时选择 B 的后端及其受信任前端贡献。
