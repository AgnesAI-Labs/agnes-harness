# 检查执行证据

[English](fact-chain.md) | 简体中文

[文档导航](../README.zh-CN.md) · [请求轨迹](system-prompt-trace.zh-CN.md) · [恢复](sessions.zh-CN.md)

核对回答或交付物时，沿已有事实检查，不只依赖 Agent 对自己工作的描述。

## 打开证据面板

在模型轨迹选择**查看执行证据**，在工具上选择**查看执行记录**，在交付物上选择**查看来源**，或在插件来源中选择**查看起草会话**。这些入口打开同一个工作区面板。核对请求、返回结果及关联的产物或候选，展开**技术详情**查看身份与摘要。Escape 关闭面板并返回入口焦点。

面板只读，不运行工具、导入旧代码、改变信任或迁移会话。读取校验已认证的会话所有者与精确锚点；即使会话后来迁移，请求仍使用捕获时的插件版本。见[捕获隐私与保留](system-prompt-trace.zh-CN.md)。

## 如实理解缺口

| 证据 | 能证明什么 |
| --- | --- |
| 请求记录 | 保留的逻辑请求或受支持的最终传输正文；无传输捕获端口时明确显示不可用 |
| 工具结果 | 实际返回、拒绝/恢复记录，或接收了后台作业；这些结果不同 |
| 产物引用 | 调用返回过该引用，不能证明谁创建了可变工作区文件 |
| 候选来源 | 记录的起草会话、测试/审阅摘要与发布状态 |
| 外部完成 | 没有真实外部回执时为未知，模型的自述不够 |

缺失历史、过期捕获、不可得的代码版本与无法证明的模型—工具关联会显示缺口。读取固定账本水位并受上限约束；不完整图会标注，不补造连接。事实图不构成外部恰好一次执行保证。

SDK 使用 `client.factChain(params)` 或 `session.factChain(anchor, laneId)`。精确上限、所有权校验与前端关联合同维护在[请求轨迹的执行证据说明](system-prompt-trace.zh-CN.md)和 [App Server schema](../reference/app-server.zh-CN.md)。
