# CLI and TUI

English | [简体中文](cli.zh-CN.md)

<a id="cli-与-tui"></a>

[Documentation](../README.md) · [Full command reference](../reference/cli.md)

Use the CLI in terminals and scripts, and the TUI for ongoing conversations, context inspection, and approvals. Begin with a one-shot task, then use an interactive session when needed.

Examples assume the repository root as the working directory. From another directory, use an absolute path to the built entry point. Put a subcommand before the options that belong to it.

<a id="一次性输出"></a>

## One-shot output

```sh
node agnes.mjs -p "Explain this project"
printf '%s\n' 'Summarize this text' | node agnes.mjs -p
node agnes.mjs --mode json "Explain this project"
node agnes.mjs --mode stream-json "Explain this project"
```

`--mode json` and `--mode stream-json` automatically select print mode. `--mode stream-json` writes one `{"schema":"agnes-cli-event/v1","event":{…}}` line per session event as it arrives (the event is the session event envelope), and the last line is always the same `agnes-cli-result/v1` result line that `--mode json` writes; exit codes and stderr do not change. Both formats are `v1`: fields may be added, but existing ones keep their meaning. JSON output is suitable for programmatic consumption, but stderr may still contain runtime warnings. Check the exit code: partial text is not proof of success. A one-shot call parks for approval only when the profile sets `limits."approval.park"`; a parked call prints `parked ticket=… session=…` and exits with code 3. The `--park` flag is refused. A script without an available approval interaction cannot approve dangerous actions on its own.

`agh -p --output-schema FILE` asks the model for a final reply that is one JSON value matching the JSON Schema (2020-12, up to 64 KiB) in `FILE`: the CLI appends a fixed instruction with the schema to your prompt, then checks the final assistant text. The reply may be wrapped in one ```json fence; nothing else is unwrapped, and there is no retry. On a match, text mode prints only the compact JSON on one line, `--mode json` and `--mode stream-json` add a `structured` field to the result line, and the exit code is 0. On a mismatch (not JSON, or it breaks the schema) stdout keeps the reply as written, stderr shows the first five problems, and the exit code is 6. A turn that did not complete keeps its own exit code and is not checked. A missing, oversized or non-JSON file, or a schema that does not compile (including a `$ref` to another document, which is never fetched), exits 2 before any session starts. `format` is not asserted. The flag is for `-p` only; the TUI refuses it.

By default, the CLI connects to or starts the shared local daemon. `--connect TARGET` selects an explicit target and does not fall back on failure. `--standalone` uses an embedded runtime; `--ephemeral` selects temporary execution. ACP is available through `acp` or `--mode acp`; do not assume it shares the ordinary daemon mode's lifecycle.

`agh --continue` resumes the most recent unarchived session in the working directory. When the terminal identifies its pane (`ZELLIJ_PANE_ID`, `TMUX_PANE`, `KITTY_WINDOW_ID`, `WEZTERM_PANE`, `ITERM_SESSION_ID`, `TERM_SESSION_ID` or `WT_SESSION`, the first one set), it resumes the session last used in that pane instead, as long as it is for the same directory, still exists and is not archived; otherwise it falls back to the directory's most recent session. So two tmux panes in one directory each get their own session back. The memory is one small private file per pane under `<AGH_HOME>/terminal-sessions/`, written when the TUI opens or switches a session and when `-p` uses one; a write failure is ignored. Without a pane identifier, over `--connect` and with `--ephemeral` nothing is read or written and the behaviour is unchanged.

`--safe-mode` and `--ignore-rules` start a session with less loaded, for troubleshooting. They work only on a private host that this command starts itself, so `--ephemeral` or `--standalone` is required; with the shared daemon (the default attach, or any `--connect`, even beside `--standalone`) they are refused with exit code 2, because other sessions on that daemon use the same configuration. `--ignore-rules` skips the personal and project custom slash commands. `--safe-mode` includes that and switches off every plugin that is not built in; the built-in `@agnes/base` and your credentials stay available. In the TUI a `safe mode` marker stays on the status bar. Not supported yet: skipping instruction files (`AGENTS.md`, `CLAUDE.md`, `<AGH_HOME>/AGENTS.md`), hooks and MCP servers. The Host has no startup option for them, and the only existing switch for instruction files is the installation's `context.json`, which a run cannot override without changing the process environment. The command says so on stderr each time, so a flag never reads as a guarantee it does not give.

A mistyped name is answered with the closest known one, and nothing is run on its behalf. An unknown flag exits 2 and, when a long flag is close, adds `did you mean --json?`. A TUI slash command that does not exist says `unknown command /modl; did you mean /model?` (built-in and custom commands are both candidates). A lone first word one typo from a subcommand, as in `agh sesions`, still goes to the model as a prompt, since one-word prompts are allowed, but stderr first says `note: sesions is sent as a prompt; did you mean the command sessions?`; `-p` silences it.

Ordinary automatic connections reuse a ready daemon after checking the canonical home/profile/data path, owner identity, private socket permissions, protocol and CLI version, and authenticated readiness. They do not prepare local plugin snapshots or verify installed packages again; the daemon still authorizes RPCs and verifies code before execution. Missing or unhealthy daemons use full startup preparation. A version mismatch requires stopping and restarting the daemon with the current CLI. Doctor, recovery, embedded execution and Web launchers retain their preparation paths.

<a id="交互式终端"></a>

`AGH_TIMING=1 node agnes.mjs -p "hello"` adds `agh-timing PHASE MILLISECONDS` startup marks to stderr. Times are measured from the launcher/process origin, not per-phase durations. Stdout keeps its selected text/JSON format; without `AGH_TIMING=1` no marks are written.

## Interactive terminal

```sh
node agnes.mjs
```

The input box's top edge shows the model, the directory with its Git worktree and branch, and how full the context is; `┊` marks where automatic compaction starts.

Type `/` to see the current menu. Common actions:

| Action | Usage |
| --- | --- |
| New task / history | `/new [DIR]`, `/sessions`, `/resume [id\|all]` (`all` lists every workspace; in the picker Tab switches between this workspace and all, keeping what you typed, PgUp/PgDn page, and rows are ordered by last activity in local time), `/search QUERY` (admin connection), `/import [FILE [--from claude-code\|codex\|pi\|auto]]` |
| Session housekeeping | `/pin`, `/unpin`, `/rename TITLE`, `/archive` |
| Approval grants | `/grants` lists what lets tools run unasked in this session ("this session" and "always"); `/grants revoke N\|ID` withdraws one (admin connection) |
| Deliverables | `/deliverables` lists the files this session delivered; `/deliverables save N\|ID [PATH]` downloads one after checking size and sha256 |
| Subagents | `/agents` lists the subagents this session can control; `/agents stop N\|ID` interrupts one and `/agents resume N\|ID MESSAGE` sends it more work. The daemon decides what is allowed and its refusal is shown |
| Background jobs | `/jobs` lists this session's background jobs; `/jobs stop N\|ID` kills one (the daemon refuses jobs an agent owns) |
| Queued messages | While a turn runs, Enter queues the message in the daemon and it is sent automatically when the turn ends; Alt+Enter inserts it into the running turn instead (it is queued when the turn takes no guidance). Nothing is held by the TUI, so the queue survives exiting it and every client of the session sees it. `/queue` lists the queued messages and manages them by number: `/queue edit N` takes one back into the editor (its attachments are sent with the next message), `/queue drop N` discards it, `/queue now N` stops the running turn and sends it first, and `/queue steer N` turns it into guidance for the running turn. Alt+Up takes the newest queued message back into an empty editor. An action on a message that was already sent or removed says so |
| Model / preset | `/model`, `/model main ROUTE/MODEL`, `/preset NAME` |
| Context / usage | `/context`, `/usage`, `/cost` |
| Status | `/status` shows the session, preset, model, workspace, `AGH_HOME`, connection (local daemon or `--connect`), context use, cost, queued inputs and YOLO on one screen; a value that cannot be read shows `-` |
| Copy | `/copy` copies the last reply to the clipboard, `/copy N` the Nth from the end, `/copy code` the last code block of the last reply |
| Clipboard image | Ctrl-V, or `/paste`, attaches the image on the system clipboard (a terminal forwards pasted text, never an image). It is read with `osascript` on macOS, `wl-paste` or `xclip` on Linux and PowerShell on Windows, with a 5-second timeout and a 20 MB cap, written to a file only you can read under `<AGH_HOME>/tmp/`, uploaded like `/attach` (also over `--connect`) and deleted. An `[Image #N]` chip appears in the draft and the image goes out with the next message only while that chip is still in the text; Backspace removes the chip whole. With no image, no tool or a timeout, the status bar says why and nothing is attached. Only PNG clipboard images are read |
| Scheduled prompts | `/loop 30m check the build` sends that prompt to this session every 30 minutes (an interval such as `90s`, `30m`, `2h` or `1d`, from 60 seconds to 366 days, as in `agh schedules add --every`). `/schedule every INTERVAL PROMPT` is the same, `/schedule daily HH:MM PROMPT` runs once a day in your local time zone, `/schedule` lists this session's tasks and `/schedule delete N|ID` archives one. Creating shows a card with the interval, the prompt and the target session first, and nothing is created until `/schedule confirm` (or `/loop confirm`); `/schedule cancel` drops the card. The tasks are the ones `agh schedules` and the Web automation page show, created through the same `schedules.upsert` call with this session as the target. A refusal from the daemon is shown with its code |
| Workspace changes | `/diff` lists the files this session changed (`+added -removed path`) and shows the diffs of the first three; `/diff turn` covers only the last turn and `/diff [turn] PATH` shows one file in full. A list that was cut off, a file with no diff (binary, too large) and a session record that does not cover every change are each stated |
| Review | `/review [scope]` asks the agent to review the uncommitted changes, or only the path or range you name. It lists problems by severity with file and line and edits nothing |
| Side question | `/btw <question>` answers a question about the conversation so far in a panel above the input, while the current turn keeps running. It is read-only: the question and the answer are not added to the conversation, the transcript or `/copy`, and the model cannot call tools. It is billed as a side call (a `side-call` cost row) and obeys the per-request and tree budgets. During a running turn it sees only the turns completed before it; one side question runs at a time per session and times out after 60 seconds. Esc or Enter closes the panel and discards a pending answer, but the cost is still charged. An older daemon reports that it does not support `/btw` |
| Project setup | `/init` asks the agent to write `AGENTS.md`, or to check and complete the one that exists. It only sends a message and writes nothing itself; the write goes through the usual approval |
| Custom commands | A `.md` file is a slash command named after the file (`[a-z0-9][a-z0-9-]{0,31}`): `<workspace>/.agh/commands/NAME.md` (project) and `<AGH_HOME>/commands/NAME.md` (personal). Optional frontmatter sets `description` and `argument-hint`; in the body `$1`..`$9` are the arguments and `$@` all of them. The expanded body is sent as an ordinary user message. A built-in command always wins, then a project command, then a personal one; Each directory scans its first 200 `.md` filenames in sorted order. Skipped files within that window (name taken or not allowed, over 32 KiB, not a regular file) are listed at the bottom of `/help`. Project commands come from the repository and may be written by someone else: they are marked with their path, and the first run of each shows that path and the first 200 characters of what it would send, then waits for a second Enter. Project command bodies containing hidden characters (including zero-width, bidi, private-use or unassigned characters, braille blank and four consecutive combining marks) are refused even after confirmation; ordinary emoji presentation selectors are accepted. If the 200-character preview is truncated, inspect the full file before confirming: the whole expansion is sent. Personal commands run at once. Over `--connect` only personal commands are read. Files are read again whenever the menu opens or a command runs |
| Compaction | `/compact [instructions]`; inspect the receipt for execution, skip, or failure |
| Fork | `/rewind` opens a picker of completed turns; `/rewind SEQ` forks at a sequence number. Either creates a new session and puts that turn's prompt back in the editor to change and resend; it does not roll back the filesystem |
| Undo file changes | `/undo` previews the last turn that wrote files: each file is restored, or deleted if the turn created it, and anything that cannot be undone is listed with its reason. `/undo N` previews turn N, `/undo confirm` applies the preview and `/undo cancel` drops it. Only the owner can undo, not while a turn runs and not in a read-only session. If any file changed after the turn, the whole turn is refused and nothing is touched (there is no force). Later turns are undone first, one turn at a time. Files changed by shell commands are only flagged, never restored. A turn recorded before this feature, or whose snapshot was cleaned up, cannot be undone. Snapshots are kept per workspace: each session's last 20 turns that changed files are always kept, and a workspace holds at most 500 MB of snapshots; above that the oldest unprotected snapshots go first, then those of the session idle the longest, oldest turn first. Known limitation: cleaning removes the snapshot reference but not the underlying git objects, so disk use does not shrink. An older daemon answers "this daemon does not support undo" |
| Plugins | `/packages`, `/install SOURCE`, `/package ...` |
| Resources | `/skills`, `/skill refresh ...`, `/mcp ...` |
| Display / exit | `/theme [auto\|light\|dark\|mono]`, `/notify [on\|bell\|off]` (see the notifications paragraph below), `/keys`, `/mouse`, `/thinking`, `/help`, `/quit`. `/keys` lists the key bindings in force by scope, marking any you overrode. `/thinking` switches, for this run only, between folding the model's thinking once its answer starts (the default: while it thinks, the last three rows show above the reply, then they become one line saying how much it thought) and keeping it open. `/mouse` turns mouse reporting off or on for this run (it starts on; `AGH_MOUSE=0`, `off`, `false` or `no` in the environment starts it off, and `/mouse` then turns it on): off, your terminal selects and copies text itself, but the wheel sends arrow keys that walk the prompt history. A copy reports Copied, Sent to clipboard (only the terminal was asked, as over SSH) or Copy failed. The status bar shows the preset in use once it is known (named on the command line or set with `/preset`), and a bold `⚠ full access` instead while `/yolo` is on. It does not show a count of background jobs or sub-agents: the TUI is not told one, so `/jobs` remains the way to see them. Shift+Tab moves the model to its next thinking level (`off`, `low`, `medium`, `high`, or the levels the model lists), wrapping round, through the same call as `/model`; the footer shows the new level and the notice says from which seq it applies. A model without thinking levels says so and nothing changes. The binding is `thinking-cycle` in the global scope of `/keys` and can be changed in `keybindings.json` |

Choose what a new session may do when you start it, for example `node agnes.mjs --permission read-only`; `--preset NAME` picks the recipe independently (see [permissions and presets](security.md#permissions-and-presets)). `/preset NAME` switches the open session's preset and keeps its permission; a different permission needs a new session.

Messages you send, slash commands included, are kept in `<AGH_HOME>/tui-history.jsonl` (readable only by you, the newest 500, immediate repeats skipped), so ↑ still finds them after a restart. Ctrl-R opens a reverse search: type to narrow, press Ctrl-R again for an older match, Enter puts the match in the input box without sending it, and Esc leaves the search and brings back the draft. If the file cannot be read or written, history lasts only for the current run.

Editing keys follow readline. Ctrl-A and Ctrl-E go to the start and end of the line, Ctrl-B and Ctrl-F move one character, and Alt-B, Alt-F or Ctrl-Left, Ctrl-Right move by word (Chinese text is cut into words). Ctrl-K cuts to the end of the line, Ctrl-U to its start, Ctrl-W or Alt-Backspace the word before the cursor and Alt-D the word after it; Ctrl-Y pastes the last cut back. The running TUI keeps a kill ring of the last 16 cuts: cuts in a row merge into one entry (backward cuts are prepended, forward cuts appended), any other key ends the run, and Alt-Y straight after Ctrl-Y or Alt-Y swaps the pasted text for the previous entry, cycling through the ring. The paste and each swap are one undo step. The ring is memory only and never touches the system clipboard.

Ctrl-Z undoes the last edit in the input box and Ctrl-Shift-Z redoes it (redo needs a terminal that reports Shift, such as kitty). A run of typed characters is one step; each delete and each paste is a step of its own. The last 100 steps are kept, and sending the message or switching sessions clears them.

In a draft of several lines, ↑ and ↓ first move the cursor between the lines and keep its column; history is walked only when ↑ is pressed on the first line or ↓ on the last.

Ctrl-G edits the draft in your own editor: `$VISUAL`, else `$EDITOR` (the command may carry arguments, such as `code -w`; it is started directly, not through a shell). On Windows, select a native `.exe`, for example `"C:\Program Files\Microsoft VS Code\Code.exe" -w`; double-quote paths with spaces. Windows backslashes stay literal and `.cmd`/`.bat` wrappers are not supported as editors. macOS/Linux retain POSIX quoting. The draft goes to a file only you can read under `<AGH_HOME>/tmp/`, the TUI gives the terminal to the editor, and when the editor exits with status 0 the file replaces the draft. A non-zero status keeps the draft and shows a Cancelled notice. The file is deleted afterwards. With neither variable set, Ctrl-G says how to set one and does not guess an editor. This also works over `--connect`, since the editor runs on your machine and only your local draft changes.

The default theme is `auto`: it follows the terminal background. The CLI asks the terminal for its background colour (OSC 11, waiting at most 100 ms), falls back to the last field of `COLORFGBG` (7 or 15 is a light background), and otherwise uses dark. Nothing is asked when output is not a terminal, in `-p` mode or with `NO_COLOR`. `/theme auto` saves `auto`, not the detected result; a saved `dark`, `light` or `mono` is kept as it was.

Key bindings can be changed in `<AGH_HOME>/keybindings.json`, read once when the CLI starts: `{ "cut-to-end": ["ctrl-o"] }` gives an action new keys, replacing its old ones. Action ids and their scopes (global, prompt editor, history search) are listed by `/keys`, which also shows the key names a binding may use (`ctrl-k`, `alt-enter`, `pgup`, `f2` and so on; plain letters cannot be bound). A bad file, an unknown action or key name, or a key another action in the same scope already uses is skipped with a notice on the status line and listed at the end of `/keys`; the rest of the file still applies and startup is never blocked. Ctrl-C and Ctrl-D (interrupt and quit), the approval dialog, pickers, report panels and the secret prompts are fixed. On-screen hints such as the way back to the bottom of the conversation keep naming the default keys.

The session, model and theme pickers filter as you type, ignoring case, over each row's title, id and time. The top line reads `Filter: xx (3/20)`: matches out of all rows. Backspace deletes a character, Esc clears the filter first and closes the picker only when it is already empty, and the number keys pick a row only while the filter is empty (otherwise a digit is part of the filter).

After you scroll up with PageUp or the wheel, a line above the function-key row reads `↓ New output below · End to jump back` once something new has arrived. End (or Ctrl-End) returns to the newest rows and follows new output again. While the input box holds a draft, End keeps moving the cursor to the end of its line, so only Ctrl-End jumps back and the line says so.

TUI `/package` and shell `package` have different subcommand sets. Updates can be started from TUI/Web, but shell `package update` is not implemented. Follow the [lifecycle guide](packages.md).

Leaving the TUI gives the terminal back exactly as it was before; the conversation is not printed again. If this run sent at least one message in the current session and the output is a terminal, a few lines are left behind: how long this run lasted and, when the whole history is loaded, how many messages the session holds (`This run lasted 12m 3s · messages: 14`); a second line only when something is still waiting, namely approvals not yet answered and messages queued behind a turn (they do not run until you resume); and `agh --resume ID`, to return to that session. A figure the daemon cannot report is left out.

Ctrl-O expands the latest tool card and reads the whole call and result from the daemon; while it loads, or if it cannot be read, the card keeps its preview and says why. Consecutive `read`, `grep`, `find` and `ls` calls collapse into one card such as `Read 4 files · Searched 2 times`; opening it lists each call's title row, and any other call ends the group. With mouse reporting on, clicking a card's title row opens or closes that card; Ctrl-O still toggles the latest. A collapsed card previews up to three screen rows of the result and `… N more lines`; `edit` and `write` show `+a -b` after their name instead, and open to a line diff of the change. Plan, subagent, job and workflow tool calls get cards of their own: a plan shows one row per step with its state, the others show their name, state, run time when the timeline has it, and a one-line summary.

Pasting works as in any terminal editor. The TUI asks the terminal for bracketed paste, so a pasted block arrives in one piece, line breaks included: `\r` and `\r\n` become newlines, tabs become two spaces and other control bytes are dropped. A paste of more than 10 lines or 1000 characters shows in the input box as one chip such as `[Pasted #1 · 42 lines]`; Backspace removes the whole chip and Enter sends the full original text. Chips exist only in the running TUI.

When an approval card appears, inspect the tool, arguments, and scope, then choose an available allow/deny/abort option. The dialog and the card show the same body: the tool, a risk label, and for `edit` and `write` a line diff of the change; the dialog keeps the raw input below it (PgUp/PgDn scroll). Option labels state their scope, for example "Always allow in this session". For a shell command the card can also offer "Allow commands starting with `git push` for this session"; the words come from the daemon and the grant is listed by `/grants` as `prefix: git push` (see [Security](security.md#command-prefix-approvals)). For prefixes that can run project code, the card also states that project scripts, git hooks and build code are included. `agh approvals suggest` proposes prefixes from commands you approved repeatedly in past sessions; it only reads, and you adopt a prefix on the approval card. Commands that could cause unrecoverable damage are refused before any approval is requested, even under The one-call rule for AGH configuration and instruction files applies to tools with declared write paths; shell commands declare no targets, so `echo ... > AGENTS.md` under full access is not gated by it. Strong isolation is the sandbox’s job. `/yolo` (see [Security](security.md#hard-blocked-commands)). Enter still starts on Reject. Single keys are shortcuts for the same decisions: `y` allows once, `a` allows for this session (nothing happens when the card does not offer that; a profile-wide grant always takes its number) and `n` rejects. On the card in the conversation they work only while your prompt is empty, since otherwise they are text you are typing; the numbers work either way. They are listed under the approval scope in `/keys` and cannot be rebound. A card must sit untouched for 600 ms before they work: the wait starts when the card appears or is replaced by another, and every key you press restarts it, so typing that is already under way never lands on an approval. During the wait `y`, `a`, `n`, the numbers, `r` and Enter decide nothing, text goes to your draft, the key hints on the card are dim, and Esc still denies at once. Press `r` to reject with a reason: type one line (up to 500 characters), Enter rejects and the model reads it as the user's words, Esc goes back to the options, and a blank reason is a plain rejection. Under the title the card says who asked (the package that owns the tool, the agent role of a delegated session, the MCP server a tool came from), and when "Always allow for this profile" is offered it lists the scopes that choice would store. Both come from the daemon, are length-limited and shown as plain text. When the call writes an agh configuration or instruction file (see [Security](security.md#approvals)), the card offers only "Allow once" and reject, with a note saying so. `/yolo` enables full access for the current session: it skips tool approvals and allows file reads and writes inside and outside the workspace. Explicit policy denies, operating-system permissions, and configured command sandbox limits still apply. New sessions inherit the saved permission selection. `/yolo off` asks for routine approvals again.

While the terminal reports focus, the TUI rings the bell once when a turn ends and once for each approval that starts waiting, but only when the window is in the background. The window title reads `agh · DIRECTORY`, with `… ` in front while a turn runs and `! ` while an approval waits, and the previous title comes back on exit. A terminal that does not report focus never gets the bell. The same goes for an error and for a delegated sub-agent that finishes, and a repeat of one event within three seconds counts once. On iTerm2, Ghostty, WezTerm, kitty and Warp (recognised by `TERM_PROGRAM`, `TERM` or the variables they export, which also works inside tmux, where the notification is wrapped for passthrough and needs `allow-passthrough on`), these become desktop notifications through OSC 9; any other terminal still gets the bell. Windows Terminal and ConEmu read OSC 9 as a progress command, so they only ever get the bell. A notification reads `agh · EVENT · DIRECTORY`: it never carries your prompt, a command or tool arguments. `/notify on|bell|off` chooses between that (`on`, the default), the bell only, and silence; the choice is saved in `<AGH_HOME>/tui-notify.json` like the theme, and `AGH_NOTIFY=on|bell|off` in the environment overrides it.

`/plan`, `/plan on`, `/plan off`, and `/plan <instruction>` use the selected backend plan service in both TUI and Web. `/plan status` reports the mode; `/plan pending` shows the last submitted plan. If the backend is disabled or unavailable, the UI reports plan mode off. Existing `.agh/plan-mode.json` files are read without migration. Plan mode blocks write and execution tools even with full access; leaving through `exit_plan_mode` still requires human approval of the exact plan revision. An explicit human `/plan off` remains available.

Esc during a turn interrupts it and keeps the message you were writing. With no turn running, Esc clears the draft, and pressing Esc twice within half a second on an empty editor opens the `/rewind` picker, and choosing a turn puts its prompt back in the editor; while the `@` file menu is open it only closes that menu. Ctrl-C still interrupts a turn, and pressing it twice within a second quits. Both keys interrupt any turn the session is running, including one another client started: the daemon lets the session owner stop it and refuses anyone else.

`agh --no-alt-screen` keeps the terminal's own scrollback. The TUI then runs on the normal screen instead of the alternate screen and redraws only the bottom rows (the reply that is still streaming, the input box and the status line). Each finished turn is written once into the terminal's scrollback, so the terminal's search, selection, copy and scrollbar (and tmux copy mode) work on the conversation, and it stays on screen after you quit. The mouse belongs to the terminal: the wheel and text selection are its own, `/mouse` has nothing to switch, and PgUp/PgDn, End and the "new output below" hint of the fullscreen view do not exist. A long reply goes out block by block (a paragraph, list or code block is written once the next one starts) while its last block streams in the footer. Whatever was written is never rewritten and the scrollback is never cleared: Ctrl-O only changes cards still in the footer, a later change to an entry that was already written (for example a review attached afterwards) is not shown, and a resize redraws the footer only, so older text keeps the width it was written at and the terminal wraps it as it wraps any output. `/new` and `/resume` write a divider with the new session id; after a reconnect only entries not yet written are added, with one note if earlier output could not be replayed. The default stays the fullscreen view. Type once the footer is on screen: the early input box that fullscreen draws while the daemon connects does not exist in this mode.

Known terminal limits of `--no-alt-screen`:

- The footer starts under the shell prompt by asking the terminal for the cursor position (`ESC [ 6 n`, answered within a quarter second). Without an answer it starts at the bottom of the screen, and after a resize it assumes the footer stayed on the bottom rows.
- Settled text scrolls in with scroll margins (DECSTBM) and each frame is wrapped in synchronized output (mode 2026); a terminal without mode 2026 may flicker. Under Zellij (`ZELLIJ` is set) the footer scrolls the whole screen instead of using margins; `AGH_SPLIT_FOOTER_SCROLL=region` or `=full` chooses the way yourself.
- After a window gets narrower, tmux and xterm.js wrap the old footer rows, while Zellij cuts them off, and the footer is erased accordingly; terminals not yet verified are treated like tmux. A terminal that behaves differently can leave a few stale footer rows above the redrawn footer. They are cosmetic and scroll away; the conversation is never erased.
- The footer is pinned to the last rows. When it gets shorter (a reply ends, a menu closes), the freed rows stay blank between the conversation and the footer until new output fills them.
- Verified with headless xterm.js, tmux 3.8 and Zellij 0.45.1. macOS Terminal, iTerm2, Windows Terminal and IDE terminals follow the same escape sequences but have not been verified.

## Schedules and triggers

`agh schedules` and `agh triggers` manage the same scheduled tasks and webhook rules as the Web automation page, and need an admin connection. A task that repeats every minute: `agh schedules add --prompt "Summarise new issues" --every 1m --cwd .`; `agh schedules run ID` runs it now, `pause` and `resume` stop and restart it, `archive` removes it, and `show ID` lists its recent runs. Webhook rules are written as JSON (`agh triggers add --file rule.json`); the JSON is checked against the protocol schema before anything is sent, and `agh triggers test RULE` runs a synthetic delivery. A refusal prints its code and exits 1; `--json` prints what the daemon returned.

## Plugin configuration, tree and applications

These commands mirror the Web admin pages and need an admin connection. `agh plugins config get ID` lists a plugin's configuration rows with their value, schema summary and whether the value is valid; fields the schema marks `x-secret`, `writeOnly` or `credential-reference`, and keys that look like credentials, are printed as `[redacted]` in text and `--json`. Values are written from a JSON file, never from the command line: `agh plugins config validate ID [ROW] --file value.json` only checks, `set` checks first and saves nothing (exit 1) when the value is invalid. `agh plugins tree` and `generations` show the plugin tree and runtime generations; `tree apply --file artifact.json` and `tree rollback` change the runtime and print what they would do unless `--yes` is given. `agh app show` and `preview PACKAGE#APP` read the application state and the consent preview; `app adopt` also needs `--yes`. `agh package source-policy` prints the allowed package sources. A refusal from the daemon is printed as is and exits 1.

## Settings and credentials

`agh settings` changes the same settings as the Web settings pages and needs an admin connection. Without a section it lists them: `model-slots`, `child-engines`, `auto-review`, `system-prompt`, `memory`, `observability`, `search` and `session-defaults`. `agh settings SECTION` (or `get`) prints one line per value, `--json` prints what the daemon returned. `agh settings SECTION set --file settings.json` saves JSON (`-` reads stdin) after checking it against the protocol schema; for most sections a `get --json` document, edited, is a valid input. `agh settings system-prompt set --text "..."` replaces the whole system prompt (it needs `--yes`; an empty text removes the replacement). `memory` works on the directory given by `--cwd`. `agh settings search test --text "query" [PROVIDER]` runs one search. This is separate from `agh config`, which signs in accounts and dumps the effective run configuration.

`agh credentials` lists the generic API-key credentials (id, name, creation time, what uses them), renames one (`rename ID NAME...`) and deletes one (`delete ID --yes`; without `--yes` it only shows what would be deleted, and a credential that is still in use also needs `--force`). A secret value is never shown. Adding or replacing a value is done with `agh config`, not on the command line.

## Sessions at a glance

`agh agents` lists the daemon's sessions with their state and queue: key, title, loop (or preset), state, queued inputs and last activity. By default it shows the 50 most recent unarchived sessions; `--all` lifts the limit and `--json` prints stable fields for scripts. The state comes from one read-only `session.controls` call per session (at most 8 at a time): `paused`, `queued` (inputs wait behind the current turn), `open` (live in the daemon, nothing queued; a turn may still be running, because the daemon gives clients no busy flag), `closed` (not live in the daemon) or `unknown` (that session could not be read; the others are unaffected). `agh sessions list` is the archive and grouping view; `agh agents` is the run and queue view.

`agh sessions list` prints one page of 50 sessions by default and says on stderr when more exist. `--limit N` (1 to 500) sets the page size; `--all` follows every page, and with `--limit` the limit caps the total; `--last` prints only the most recently active session (last message, else creation time), for example `agh --resume "$(agh sessions list --last --json | jq -r '.items[0].sessionId')"`. The text rows are id, last sequence, preset, `pinned` or `-`, last activity, cwd and title: the cwd column was added before the title, so scripts should read `--json`, whose shape is unchanged (with `--all` or `--last`, `items` holds the merged result and `next` is omitted).

`agh queue KEY [--steer] [--json] TEXT...|-` sends one message into an existing session from another shell. By default it is a follow-up: it waits for the current turn to end and then runs. `--steer` guides the turn in flight instead. `-` reads the message from stdin; put `--` before a message that starts with a dash. It uses the same command path as the TUI and Web (command id and pending journal) and prints `queued followUp (seq N)`. A daemon refusal (not your session, session closed, unsupported) is printed as `refused: CODE: message` and exits 1. If the daemon cannot confirm the outcome, the command says `unconfirmed`, exits 1 and does not send again; check with `agh sessions show KEY` before retrying.

`agh api METHOD [--params JSON|-] [--json]` calls one protocol method with the connection the CLI already has; it adds no permission. `METHOD` is a name from the protocol table, with or without the `_agnes/v1/` prefix; `agh api --help` lists every callable method with its tier (`client` or `admin`), generated from that table. `--params` is the JSON params object (`-` reads stdin, default `{}`) and is checked against the protocol schema locally: invalid parameters print the schema diagnostic and nothing is sent. An unknown method is refused with the closest names. The result is printed as JSON on stdout (`--json` for one line); a daemon refusal, including an admin method without an admin connection, goes to stderr as `error: CODE: message` and exits 1. Streaming and attach methods (`session.attach`, `participant.join`, ...) and command-class methods (`submit`, `session.control`, `session.fork`, ...) are refused because they need a command id and the pending journal: use `agh queue` or the matching subcommand. The ACP session calls (`session/prompt`, ...) are not offered either.

`/import FILE [--from claude-code|codex|pi|auto]` brings one Claude Code, codex or pi session file into agh, through the same conversion and writing as `agh import FILE`, and prints the new session key; continue it with `/resume KEY`. Without a file, `/import` opens a picker of the 50 most recent external sessions of the current workspace, newest first: Claude Code files under `~/.claude/projects/<encoded cwd>/*.jsonl` and codex files under `~/.codex/sessions/**/rollout-*.jsonl` whose header names this directory. Only file metadata and the first lines are read, nothing is uploaded or cached; files that cannot be read are skipped and counted. It needs the shared local daemon connection: with `--connect`, `--standalone` or `--ephemeral` it says so and does nothing, and the file is never uploaded to a remote daemon.

## Shell completion

`agh completion bash|zsh|fish` prints a completion script to stdout and changes nothing else; you load it yourself. Commands, subcommand verbs, global flags and the values of enumerated flags (`--mode`, `--permission`, ...) are completed from a fixed table. Session keys (after `--resume`, `agh resume`, and `agh sessions show|pin|archive|...`) are completed from the running local daemon through a hidden helper, `agh __complete sessions [PREFIX]`, which prints `KEY<TAB>TITLE` lines. The helper never starts a daemon, gives up after 300 ms, prints nothing when no daemon is running or anything fails, and strips control characters from titles. PowerShell is not supported yet.

```sh
# bash (add to ~/.bashrc); eval works on macOS's bash 3.2, where source <(...) does not
eval "$(agh completion bash)"
# zsh (add to ~/.zshrc, after compinit)
eval "$(agh completion zsh)"
# fish (save once)
agh completion fish > ~/.config/fish/completions/agh.fish
```

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Completed |
| 1 | Execution failure or unknown error |
| 2 | Argument or startup error |
| 3 | Parked and waiting |
| 4 | Budget limit / blocked |
| 5 | Maximum steps reached |
| 6 | `--output-schema`: the turn completed but its final reply did not match the schema |
| 124 | `--timeout`: the deadline passed and the turn was cancelled |
| 130 / 143 / 129 | SIGINT / SIGTERM / SIGHUP |

`agh -p --max-budget CREDITS` caps the credits one run may spend. `CREDITS` is a number greater than 0, in the same unit as a preset's per-request credit cap. It is sent with the one prompt as a hard per-turn limit and can only lower the preset's own cap, never raise it. When the turn runs out the run ends with `budget` and exit code 4. With `--continue` or `--resume` it applies to this prompt only. A value that is not a positive number, use without `-p`, or a daemon that does not advertise hard turn budgets exits 2 before the prompt is sent.

`agh -p --max-turns N` caps the model steps of one run. `N` is an integer from 1 to 1000. It is sent with the one prompt as a per-turn step cap and can only lower the preset's own `budget.max_steps`, never raise it. When the run reaches the cap the turn ends with `max_steps` and exit code 5 (see [configuration](../reference/configuration.md) for the preset ceiling). With `--continue` or `--resume` it applies to this prompt only. A value outside the range, use without `-p`, or a daemon that does not advertise `turnMaxSteps` exits 2 before the prompt is sent; nothing is silently ignored.

`agh -p --timeout SECONDS` stops a run that takes too long. `SECONDS` is a number from just above 0 to 86400 (fractions allowed). The deadline starts when the prompt is sent. When it passes, the CLI cancels the turn the same way Ctrl-C does, writes `agh: timeout after SECONDSs; turn cancelled (exit 124)` to stderr and exits 124, the code `timeout(1)` uses. A turn that finished before the cancel landed keeps its own exit code, and a signal still decides the code when one arrived. A value outside the range, or use without `-p`, exits 2 before the prompt is sent.

`agh -p --output-file FILE` also writes the final text to `FILE` (relative to `--cwd`, replaced if it exists); stdout is unchanged. With `--output-schema` the file holds the compact JSON value. The file is written for every ending, empty when the turn produced no text, so a script never reads a stale answer. A file that cannot be written exits 1. There is no `-o` short form: `-o` already means `--out` for `export`, `computer-use` and `diagnostics export`. Use without `-p` exits 2.

Implementation: [arguments and usage](../../packages/cli/src/args.ts), [exit codes](../../packages/cli/src/errors.ts), [TUI commands](../../packages/cli-tui/src/commands.ts).

Use `/attach <path>` in the TUI to upload an original in bounded chunks and submit its receipt as a prompt. Paths may contain spaces. Common image, document, archive and media extensions carry their own MIME type; any other extension uploads as `application/octet-stream`, and a daemon allow-list refusal is shown as returned. Errors preserve the backend attachment reason. The current session owns the receipt; switching sessions before the upload completes refuses submission.
