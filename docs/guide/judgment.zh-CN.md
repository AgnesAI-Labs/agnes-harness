# 检测说了要做却提前结束的回复

[English](judgment.md) | 简体中文

[文档](../README.zh-CN.md) · [插件](packages.zh-CN.md) · [TypeSafe Jev](typesafe-jev.zh-CN.md) · [本地模型](local-model.zh-CN.md)

可选的「**判断**」插件（`@agnes/judgment`）检查助手最后的文字回复是否承诺接着做事，却就此结束。例如，一条以“我现在去检查失败的测试”结尾的回复，可能得到一次在当前回合继续工作的提醒。

意外收工检测**默认关闭**，真实会话效果评测尚未完成。安装插件、选择判断模型、开启检测是三个独立步骤；安装和选模型不会自动打开检测。

## 从市场安装

1. 打开 **插件 → 市场**，找到「**判断**」，点击 **安装**。这个包随 AGH 发行版附带，默认没有安装。
2. 在审阅页查看来源、旁路模型调用能力（`sideCall`）、读取对话消息的权限，以及会发送给判断模型的内容。
3. 完成安装并启用插件，再打开插件设置。

没有安装插件时，不会执行检测。安装后，如果检测未开启，或没有选定可用的判断模型，也不会发送判断请求。

## 配置判断模型，再打开检测

使用 Jev 时，在 **设置 → 模型与账户 → 高级：旁路模型与任务模型 → 旁路模型** 中添加 Jev 条目，通过凭据控件保存 key。路由和模型的配置步骤见 [Jev 设置指南](typesafe-jev.zh-CN.md)。

只有一条原生 Jev 路由、且其中只剩一个模型条目时，插件才会自动选中；同一路由有多个模型时，必须明确指定模型。有多条路由时，需要在插件设置中指定路由和模型，插件不会按目录顺序猜选。原生判断模型可以另配一个原生后备。调用失败后，不会自动改用对话模型。

你也可以明确把对话模型选为主判断模型。插件会发送文字判断题，把回答解析成“是”或“否”；这是一种二选一判断，不代表经过校准的概率。如果希望这次判断请求留在本机，可以选择完全在本机提供服务的模型。

选好模型后，手动打开**意外收工检测**（`uses.stop.enabled`）。模型和插件配置的更改对新会话生效，保存后请新建会话使用。

## 回复结束时会发生什么

当最后一条助手回复包含文字且没有工具调用时，插件会结合最近一条用户请求进行判断。原生模型返回的“是”概率达到 0.5，或明确选定的对话模型回答“是”，就会触发一次在当前回合继续工作的提醒。会话中会显示运行时上下文附注，说明检测到回复说了要做却结束，已提醒继续。后续行动仍由主模型决定，并遵守原有的权限、审批、步数和预算限制。

同一用户请求最多触发一次续写。会话历史中保存“已续写”的标记，重启后重新打开会话也不会因此对同一请求再续一次。命中缓存的提醒会带上“（缓存）”。

一次判断最多等待 5 秒；配置了原生后备时，最多再尝试一次。整个收工钩子的上限是 15 秒。模型缺失、答案无效、判断预算不足或最终调用失败时，回合照常结束。预算拒绝不会触发重试。你取消操作或发来新消息时，正在等待的检测会放弃，迟到的判断结果不会让旧回合继续。

## 会发出去哪些内容

这项检测会向选定的判断模型发送：

| 内容 | 最多发送的摘录 |
| --- | --- |
| 最近一条用户请求 | 前 2,000 字符 |
| 最后一条助手回复 | 后 8,000 字符 |
| 判断题 | 固定的意外收工问题和判定标准 |

发送前，插件会对摘录执行凭据遮蔽。远程模型会收到遮蔽后的文字，其中仍可能包含个人信息或业务机密；请求由所选服务商及配置的网关处理。本地判断模型只保证这次判断请求在本地执行，不改变主对话模型的运行位置。

插件不会附上整段对话，也不会额外收集文件或工具结果。但如果这些内容已经被引用在上述摘录中，它们会在字数限制内一同发送。

原生判断答案可能命中本地内存缓存。缓存最多保存 2,000 条，30 天后过期，满额时淘汰最久没有使用的条目。键是哈希，值只有答案和时间戳，不保存原始摘录。插件实例释放或进程重启后，缓存消失；对话模型的判断答案不进入这个缓存。用于防止重复续写的持久标记与答案缓存是两回事。

## 哪些情况不会检测

- 子智能体会话，以及宿主标记为 unattended（无人值守）的回合。
- 最后一条回复带有工具调用、没有符合条件的用户请求，或同一请求已触发过续写。
- 插件运行在无法获得旁路调用能力的隔离模式下。
- 目标驱动的工作：人的 `/goal` 命令触发暂停后，只有来自同一操作者及来源的真实 `/goal clear` 命令清除目标才会恢复检测；暂停或完成目标不会恢复。插件采取保守判断，非法目标命令也可能导致暂停；单独输入 `/goal` 或 `/goal show` 不会触发这种暂停。

检测可能漏掉没做完的工作，也可能误判承诺。它不负责证明任务已经完成，也不会授予任何操作权限。需要停用时，关闭 `uses.stop.enabled`，或者禁用、卸载整个插件。本版本只提供意外收工检测。
