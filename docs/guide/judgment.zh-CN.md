# 检测说了要做却提前结束的回复

[English](judgment.md) | 简体中文

[文档](../README.zh-CN.md) · [插件](packages.zh-CN.md) · [TypeSafe Jev](typesafe-jev.zh-CN.md) · [本地模型](local-model.zh-CN.md)

可选的「**判断**」插件（`@agnes/judgment`）检查助手最后的文字回复是否承诺接着做事，却就此结束。例如，一条以“我现在去检查失败的测试”结尾的回复，可能得到一次在当前回合继续工作的提醒。

意外收工检测**默认关闭**，真实会话效果评测尚未完成。安装插件、选择判断模型、开启检测是三个独立步骤；安装和选模型不会自动打开检测。

## 从市场安装

1. 打开 **插件 → 市场**，找到「**判断**」，点击 **安装**。这个包随 AGH 发行版附带，默认没有安装。
2. 在审阅页查看来源、旁路模型调用能力（`sideCall`）、读取对话消息的权限，以及会发送给判断模型的内容。
3. 完成安装并启用插件，再打开插件设置。

没有安装插件时，不会执行检测。安装后，如果检测未开启，或没有选定可用的判断模型，也不会发送判断请求。

## 配置判断模型，再打开检测

使用 Jev 时，在 **设置 → 模型与账户 → 高级：旁路模型与任务模型 → 旁路模型** 中添加 Jev 条目，通过凭据控件保存 key。路由和模型的配置步骤见 [Jev 设置指南](typesafe-jev.zh-CN.md)。

只有一条原生 Jev 路由、且其中只剩一个模型条目时，插件才会自动选中；同一路由有多个模型时，必须明确指定模型。有多条路由时，需要在插件设置中指定路由和模型，插件不会按目录顺序猜选。原生判断模型可以另配一个原生后备。调用失败后，不会自动改用对话模型。

你也可以明确把对话模型选为主判断模型。插件会发送文字判断题，把回答解析成“是”或“否”；这是一种二选一判断，不代表经过校准的概率。如果希望这次判断请求留在本机，可以选择完全在本机提供服务的模型。

选好模型后，手动打开**意外收工检测**（`uses.stop.enabled`）。模型和插件配置的更改对新会话生效，保存后请新建会话使用。

## 回复结束时会发生什么

当最后一条助手回复包含文字且没有工具调用时，插件会结合最近一条用户请求进行判断。原生模型返回的“是”概率达到 0.5，或明确选定的对话模型回答“是”，就会触发一次在当前回合继续工作的提醒。会话中会显示运行时上下文附注，说明检测到回复说了要做却结束，已提醒继续。后续行动仍由主模型决定，并遵守原有的权限、审批、步数和预算限制。

同一用户请求最多触发一次续写。会话历史中保存“已续写”的标记，重启后重新打开会话也不会因此对同一请求再续一次。命中缓存的提醒会带上“（缓存）”。

一次判断最多等待 5 秒；配置了原生后备时，最多再尝试一次。整个收工钩子的上限是 15 秒。模型缺失、答案无效、判断预算不足或最终调用失败时，回合照常结束。预算拒绝不会触发重试。你取消操作或发来新消息时，正在等待的检测会放弃，迟到的判断结果不会让旧回合继续。

## 会发出去哪些内容

这项检测会向选定的判断模型发送：

| 内容 | 最多发送的摘录 |
| --- | --- |
| 最近一条用户请求 | 前 2,000 字符 |
| 最后一条助手回复 | 后 8,000 字符 |
| 判断题 | 固定的意外收工问题和判定标准 |

发送前，插件会对摘录执行凭据遮蔽。远程模型会收到遮蔽后的文字，其中仍可能包含个人信息或业务机密；请求由所选服务商及配置的网关处理。本地判断模型只保证这次判断请求在本地执行，不改变主对话模型的运行位置。

插件不会附上整段对话，也不会额外收集文件或工具结果。但如果这些内容已经被引用在上述摘录中，它们会在字数限制内一同发送。

原生判断答案可能命中本地内存缓存。缓存最多保存 2,000 条，30 天后过期，满额时淘汰最久没有使用的条目。键是哈希，值只有答案和时间戳，不保存原始摘录。插件实例释放或进程重启后，缓存消失；对话模型的判断答案不进入这个缓存。用于防止重复续写的持久标记与答案缓存是两回事。

## 哪些情况不会检测

- 子智能体会话，以及宿主标记为 unattended（无人值守）的回合。
- 最后一条回复带有工具调用、没有符合条件的用户请求，或同一请求已触发过续写。
- 插件运行在无法获得旁路调用能力的隔离模式下。
- 目标驱动的工作：人的 `/goal` 命令触发暂停后，只有来自同一操作者及来源的真实 `/goal clear` 命令清除目标才会恢复检测；暂停或完成目标不会恢复。插件采取保守判断，非法目标命令也可能导致暂停；单独输入 `/goal` 或 `/goal show` 不会触发这种暂停。

检测可能漏掉没做完的工作，也可能误判承诺。它不负责证明任务已经完成，也不会授予任何操作权限。需要停用时，关闭 `uses.stop.enabled`，或者禁用、卸载整个插件。

## 语义源码查找与批量判断

`uses.find.enabled` 与 `uses.batch.enabled` 是两个独立开关，均默认关闭。30 道源码查询、200 条批量样本的人工效果评测**尚未执行**，合成集成测试不代表效果过线。选好模型并开启用途后请新建会话。原生主判断模型提供 `find_relevant` 和 `judge_batch`，明确选定的对话主判断模型只提供 `judge_batch`。模型不可用时工具撤销；子会话、会话投影不可用或隔离调用没有获授权的 sideCall 端口时执行拒绝。

`find_relevant({query, path?})` 接受非空且不超过 2,000 字符的查询，以及不超过 2,048 字符的工作区路径。读取请求的子树或文件前，会从可信工作区边界逐级检查祖先，遇到已知符号链接或非目录即拒绝。最多消费 10,000 个目录项，跳过凭据、锁文件、二进制、构建目录及已知符号链接；每个文件只读前 1 MiB，按文件名与内容共同进行本地词法排序后保留 128 个路径。名字每批 64 个判断，再对最多 20 个选中文件各自新读前 1 MiB；选中文件两阶段合计最多读取 2 MiB，本地词法阶段不缓存原文。现有文件系统端口没有原子 no-follow 读取，检测到元数据或 revision 变化时丢弃，工作区授权仍然生效。

模型会收到遮蔽后的查询与候选路径，再收到每段最多 256 个原始字符的摘要（每批 46 段）。每文件最多 24 个源码窗口，每段不超过原始 UTF-8 的 8 KiB；摘要分数达到 0.45 的最多 40 段进入完整复核，复核达到 0.20 的片段按分数与路径稳定排序并合并相邻行。先对完整可用上下文遮蔽，再按原始坐标截窗；秘密缩短不能扩大窗口，超长行可能拆成片段。数量上限、不可读、取消与失败均明确标记 partial。判断失败不代表找不到源码，请使用 grep。

`judge_batch({items, questions})` 接受 1–500 条独立的 `{id, state}` JSON，id 不超过 128 字符且唯一。遮蔽前，每条声明的原始 `{id, state}` 与完整共享题目对象各自按序列化 UTF-8 JSON 限 1 MiB；超限整批拒绝，不截断。校验、克隆、遮蔽和逐题计量均检查同一截止并让出事件循环，取消可在模型外发前生效。整批输入先校验，保留题目和选项顺序，先遮蔽凭据字段的任意 JSON 值并对完整序列化状态脱敏。题目说明与判定文本也会遮蔽；若题目 id 或 choice 键会因凭据遮蔽而改变，整批在外发前拒绝，不会静默改名。choice 题必须含固定键 `other` 与 `mixed`。状态加一道题超过估算 24,000 token 时拒绝；可容纳的请求按题目以 48,000 token 为总界拆分，不拆单条状态。服务商会收到剩余 JSON 内容及输入题目，遮蔽不能移除全部机密。

原生答案的最大概率小于 0.7，或 choice 落在 `other`/`mixed`，会进入人工复核；恰好 0.7 不因低置信度进入。对话答案全部需要复核，不展示伪校准概率。结果保留逐 id 完成答案或失败、pending、partial 和原始 accounting；缺少美元 billing 时明确为未知，credits 不当成美元。

find 整体 20 秒、单次尝试 10 秒；batch 整体 60 秒，校验、准备与排队也计入。两工具共享 16 个实际请求槽，只对已终止且可重试的失败最多重试一次；取消尽可能返回已完成项。Core 既有预算继续生效，插件不另加美元上限或价格未知拒绝。工具声明只读、非破坏、open-world 与幂等。关闭相应用途或禁用、卸载插件后，新会话不再提供对应工具。

## 规则提醒与设置页

规则提醒默认关闭，须另行开启，并要求判断主模型为原生模型。例如：

```json
{"uses":{"rules":{"enabled":true,"items":[{"id":"review","text":"处理记录前先复核。","tools":["read"]}]}}}
```

最多 32 条规则，每条正文最多 1,000 字符、最多 16 个精确工具名。匹配的工具结果返回后，同一次原生请求检查所有尚未提醒的匹配规则。外发内容包括配置的规则正文、序列化工具参数的原始前 2,000 字符和文本结果的原始后 8,000 字符；先按完整上下文遮蔽凭据，再取原窗口。工具 details 和 structured 数据保持原样，不进入判断输入。

违反概率至少 0.7 时，在完整保留已有结果字段和内容块的基础上附加一个不可信文本提醒。持久记录仅含哈希与工具去重身份，同会话、单条规则版本和工具只提醒一次；修改某条规则后可重新检查。子会话、未知身份或投影不可用时不发送请求。从排队、模型目录读取到持久标记确认，整个过程最多 1,500 ms；不重试、不拆批、不使用后备模型。预算拒绝、异常、取消、标记饱和或无法确认写入时，原结果照常放行；宿主预算继续有效。

同一个已安装插件在“设置 → 插件”中提供“判断”页，只查询自己的只读状态服务，显示当前实例的有限缓存和用途计数、模型可用性及当前配置指纹。没有实际授权证据时，获批 hook 时限仍显示未知。通过既有配置编辑器修改后，新会话生效。停用、撤销信任或卸载会清理页面与旧统计。

费用明细只在 side-call 的 caller 精确匹配判断插件身份时归类为“判断”；用途来自同 effectId 的已提交审计，无证据或未知标签显示用途未知，不改变实际金额或 credits 总额。合成集成验证只证明接线和生命周期行为，不代表真实会话判断效果已经达标。
