# 业务配方

[English](business-recipes.md) | 简体中文

按业务任务、输入、权限和产出样例发现工作流。可选插件 `@agnes/business-recipes` 复用内置目录和 Agent FDE 启动路径，默认关闭，不给普通会话增加工具。

## 启用发现入口

在**插件**中找到**业务配方**，检查权限并安装、信任、启用，再从 Agent FDE 或侧边栏打开。访问页面只读取元数据，不安装配方、上传数据或启动模型。

首批仅使用随包合成数据：客服初筛（`ticket-104`）、发票审查（`invoice-207`）、会议简报（`meeting-309`）。每个配方都是独立可选插件包；阅读版本、完整性和能力声明后，再确认安装、信任并启用。未安装、未信任、未启用、可启动状态分别显示；旧后台无法提供信任事实时必须审查。

## 审查并运行

通过共享、支持键盘的控件选择列出的 fixture 和产出语言。这些有限参数只选择后台声明的启动项，不插值任意路径或提示词。点击**审查启动**，核对 bundle、预设和 JSON 输入，再点击**启动此审查后的运行**。

请先在**模型与账户**配置 `standard` 主模型路由。三个 bundle 继承该路由，不会偷偷选择替代模型；各自增加一个只读样例工具和 Skill。产出为会话内的客服分流/回复草稿、发票差额（120 − 100 = 20），或保留明确负责人与日期的会议简报。不会发消息、写文件、建任务或连接真实业务系统。明确启动的模型请求适用通常授权，并可能产生模型费用。

打开返回的会话检查草稿与执行证据。配方预览不枚举其他会话。权限来自已认证后台、审查后的父子插件启用状态和所选 bundle，不来自页面或 fixture 文本。

## 失败与生命周期

- 模型、预设、bundle 缺失：在模型与账户或插件页面修复，刷新后重新审查。
- 插件、信任或依赖启用状态变化：刷新并重新审查当前内容。停用依赖会立即撤销启动权限。
- 回执丢失：先查询操作回执；相同 ticket/operationId 通过现有启动日志只产生一个会话与耐久输入。未知外部结果不会自动重放。
- 停用或卸载：主页入口和 FDE 链接消失，注册被释放。已准入会话按自身生命周期继续；历史会话固定原后台快照，升级仅影响新会话。

不需要新市场、连接器凭据、网络上传、全局会话读取或 G0 新接口。参见[包 README](../../packages/package-manager/bundled-plugins/business-recipes/README.zh-CN.md)与[插件生命周期](packages.zh-CN.md)。
