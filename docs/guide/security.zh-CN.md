# 安全与信任：让执行有边界

[English](security.md) | 简体中文

[文档导航](../README.zh-CN.md) · [恢复](sessions.zh-CN.md) · [报告漏洞](../../SECURITY.md)

**以可信为根基**，落在具体选择上：信任哪一版代码、允许什么操作、执行到哪里、结果如何检查。本页帮助你理解这些选择及其边界，适用于首次试用、插件开发和 FDE 集成。

AGH 可以执行工具、写文件和连接外部系统。模型文本、网页、MCP 结果、Skill 与插件配置都不是用户授权本身。先选择工作目录和可接受的能力，再批准具体操作。

## 三类不同的信任

| 边界 | 含义 | 不代表什么 |
| --- | --- | --- |
| 包信任 | 接受指定内容摘要与能力声明的代码 | 不是对所有未来版本的授权 |
| 工具审批 | 允许本次或当前选项所述范围的行为 | 不是操作系统沙箱已成功建立 |
| 沙箱/执行约束 | 由实际平台探测与策略限制执行 | 不是恶意进程内插件的隔离保证 |

普通第三方 Cordis 插件默认是进程内受信代码，信任它可能允许其使用进程能访问的 Node 能力。插件 facet 约束的是注册行为，不隔离任意 Node 代码。安装第三方包前，应同时审核代码来源和声明的能力。

## 审批

默认交互流程在有需要时显示工具和可选决定。一次允许、会话允许、持久授权和拒绝的范围不同；后台根据当前凭据和策略作最终裁决。审批过期、断线或多客户端竞争时，以后台保存的决定为准。

回答者绑定到已认证连接，或由后端配置的 verifier 核验来源凭据。答案中的 actor 或未核验凭据不能冒充其他审批人。会话记录用 `answeredBy` 单独保存回答者，不覆盖请求者。后端只接受实际提供的选项：记忆文件变更与退出 Plan 只提供单次批准和拒绝。发送失败（`transport`）、界面断开（`detached`）、到期（`deadline`）、SDK 无处理器（`no-handler`）和停止任务（`stopped`）都不会记成人工拒绝（`user-rejected`）。刷新后的合格连接可以重新收到尚未回答的工具或管理问题。停止会话或 worker 会撤销其 offer，晚到答案不能触发执行。 声明的路径参数解析后落在配置或指示 agh 的文件上的调用只能逐次批准：审批只提供“允许一次”和“拒绝”，并附一行说明原因，此前给的会话授权或持久授权也不适用于它。这些文件包括 Agnes 主目录下的任何文件、任何 `.agh` 目录，以及名为 `AGENTS.md`、`CLAUDE.md`、`AGENTS.local.md` 或 `CLAUDE.local.md` 的文件（为 context-rules 扩展额外配置的指令文件名不在其内）。宿主先解析符号链接（名为 `AGENTS.md` 的链接算，指向主目录的链接也算），在卷不区分大小写时忽略大小写，无法解析的路径一律按受保护处理。这对每个声明了路径参数的工具生效，内置的和插件的都一样，写入时即使选定工具策略原本允许也生效；读取保留通常的审批策略。全权限模式为每次调用分别记录自动单次决定。shell 命令不声明写入目标，因此全权限下的 `echo ... > AGENTS.md` 不受此逐次审批规则约束。强写入隔离由命令沙箱负责。

退出 Plan 必须由人对当前精确 revision 作单次确认，即使使用完全权限、`off`、自动 review 或已有 grants。清除状态使用工作区文件的比较并交换；旧答案不能清除已改写的计划。损坏或不可读的计划文件会保持阻塞，直到人修复文件或明确执行 `/plan off`。

Web 审批卡先显示路径、命令等定位字段，超长的内容会注明已显示的字符数。“本会话允许”的范围是该会话内同一工具的全部后续调用，按钮上会写明工具名。调用的内容无法在卡片上完整显示时，卡片会提示，并且不提供“本会话允许”，只能“仅允许这次”或“拒绝”。

未获批准的调用会说明原因，会话记录和模型都能看到：用户拒绝、无人在期限内答复、没有客户端可询问、等待期间任务被停止、被命令策略拦截，或委派的子代理请求了其固定范围之外的操作。没有人可询问的调用记为“无法审批”而不是“已拒绝”，且不会执行。客户端可以在拒绝时附一段自由文字。模型会在固定的拒绝文字之后读到 `The user said: "…"`：文字截断到 500 字符，控制字符换成空格，引号和反斜杠被转义，因此它始终是标明为用户原话的引用，不是指令通道。只有用户拒绝才带这段文字；会话记录按原样保留客户端发送的内容（最多 4000 字符）。

`approvals.mode` 接受 `manual`、`auto-review`、`off`。`off` 跳过普通工具审批，不等于 `full-access` 权限，不会扩大文件范围或取消命令隔离。TUI `/yolo` 与 Web 完全访问开关选择当前会话的同一后端权限，包括使用包内审批表的应用角色智能体。用户显式选择优先于包内审批表；运行摘要显示实际权限和选择者身份。切回标准会立即撤销未完成的自动授权及其子会话授权。委派会话受活跃父会话的权限约束；缺少父会话时重开历史子会话，不恢复自动授权。父会话权限变化会使已打开的后代会话投影和运行摘要失效并重新读取 Core；通知本身不携带授权。启动时已固定为完全访问的会话，仍须另起会话才能收窄文件和隔离范围。只读会话须另起会话才能更改隔离。旧版仅用于跳过普通审批的切换记录，不自动获得扩展后的授权；升级后须重新选择完全访问。开关不改写配方、来源固定记录或后续新会话的默认权限。`manual` 是“策略要求时问人”，不是每次调用都问。

完全权限下，Agnes 主目录的私有状态——包括 `secrets/`、`auth/`、`profiles/` 以及显式指定的 secrets 目录——普通文件工具仍不可读取或写入。即使这些路径位于所选工作区内，硬拒绝也继续生效。授权管理应通过对应的设置与凭据服务；会话不能读取密钥，也不能改写 `profile.yaml` 将更弱的审批带到之后的会话。命令访问范围独立遵循所选权限：macOS/Linux 的 `workspace-write` 下，shell 写入受 OS 沙箱允许目录约束，Windows 命令没有系统隔离；显式选择 `full-access` 后，shell 可写工作区外。macOS/Linux 有可用 OS 边界时，已安装的记忆 provider 仍对命令拒绝整个记忆树；没有可用边界时（例如 Docker 容器或未装 bubblewrap 的服务器），命令不经 OS 隔离执行，记忆保持启用，记忆文件对 shell 而言是普通文件，与其他 Agent 工具的完全访问模式一致。`sandbox.required: true` 仍会拒绝，见[记忆](memory.zh-CN.md)。应用权限不能代替系统隔离：获准的 Windows 命令以当前系统账户执行，可以访问该账户有权访问的文件和网络。

Web「工作区内修改」将文件访问限制在所选工作区内，执行命令仍遵循审批策略。访问工作区外路径时会拒绝操作，并提示切换「完全权限」或将目标目录选为工作区，不额外弹出审批。

默认验证器根据每次调用已记录的策略区分重复写入和只读调用。只读轮询不会触发 `repeated_write`；策略缺失或无法校验时仍保守处理，独立的无进展检查继续生效。MCP 工具须声明 `readOnlyHint: true` 才会被识别为只读。完成校验不再提供人工接受未校验完成的入口。内容未通过时最多自动修正一次；校验或修复服务不可用时结束本轮并标记未能校验。修复策略明确返回 complete 时结束本轮并保留原始校验结果。业务操作审批和未知副作用核对仍独立保留。

不要把“用户请求编辑文件”当成插件可任意执行的授权。插件应准确声明只读/破坏性、开放网络、可重放性及审批需求；这些元数据应与实际执行一致。

### 自动审查

自动审查是在“每个风险调用都手动批准”和“跳过批准”之间的选择。在 Web **设置 → 权限与安全** 中启用策略卡，选择已配置的 `fast`（默认低成本档位）或 `verifier` 模型。它只审查默认策略原本会询问人工的调用；自定义和只读策略继续独立裁决。完全权限与 `off` 保持原有语义，缺少审查模型不会偷偷改用主模型。可信用户 profile 也可配置 `approvals.mode: auto-review`，工作区配置不能启用它。

无需编写代码：打开 **设置 → 模型 → 辅助模型**，或点击自动审查卡的 **配置辅助模型**。从已有目录选择 `fast` 和／或 `verifier` 的路由与模型，然后保存。区域显示当前选择或 **未设置**，不可用的旧选择仍可见。这些 profile 默认值适用于 **新会话**。在 **设置 → 权限与安全** 选择同一审查档位，卡片会显示该 profile 默认值是否可用。

已有会话可从输入区的模型选择器打开 **辅助模型（高级）**，显式选择路由与模型，再为当前会话保存对应档位。此操作复用会话模型接口，重新打开会话后仍保留，不改变主模型或 profile 默认值。清除 profile 档位只影响新会话；已有会话保留已保存的选择。切换会话预设仍按既有行为重置模型覆盖。未设置或不可用的审查模型会转交人工，绝不静默借用付费主模型。配置本身不调用模型，后续实际审查可能产生供应商费用。

模型返回决定、风险和理由。默认只自动允许低风险；可显式选择允许中风险。高风险放行、低风险拒绝属于无效模型输出。格式错误、矛盾输出、异常、超时、不可信上下文、工具或类别不在范围内，以及预算耗尽，都交回人工批准。默认每会话最多 20 次审查尝试（包括失败和恢复前的尝试），超时 10 秒；设为 0 则使用人工审批。设置不可读时也使用零预算，直到修复。身份授权拒绝、命令拒绝规则、计划/只读限制、私有文件边界与沙箱始终有效，并先于审查执行。

每次审查在工具执行前写入账本，包含模型、策略提示词哈希、决定、风险、理由、延迟、成本和成本来源。工具卡、Trace 和**执行依据**均可查看。失败流拿不到实际用量时保留成本估算。审查放行不替代独立的身份授权审批。

执行依据可以显式设定未来同工具、参数、工作区、操作者、定义与策略的调用为允许、拒绝或人工审批；高风险审查不能创建自动放行规则。上下文受不可信内容污染时，即使命中「以后完全相同的调用」人工允许规则，也须交回人工；匹配规则仅作为上下文展示。未污染调用继续按规则执行。历史事实不改写，不会从批准回复中静默学习。策略卡显示规则数量并支持清除；设置按 profile 保存，只能由拥有配置权限的用户修改。插件端口见[工具运行时与策略](../extend/tool-runtime.zh-CN.md)。

## 平台与进程

在 `workspace-write`、`read-only` 权限下，随附的预设请求 L1，使用 `required: false` 和 `on_unavailable: allow-if-unimplemented`。可信本机后端声明系统隔离是否已实现。macOS/Linux 已实现，必须实际通过 Seatbelt/bubblewrap 探测；缺少程序、namespace 禁用或策略拒绝仍以 `E_SANDBOX_WORKSPACE` 拒绝初始化，不能当作“未实现”。Windows 本机后端声明尚未实现，所以允许原生命令，不探测 POSIX 后端。未知能力、远程目标不能借此自动放行。`required: true` 始终要求真正隔离。

Windows 保留工具审批、只读限制、文件工具的工作区与保护路径检查，以及用户明确设置的审批模式。获准命令使用当前系统账户执行，应用检查不能隔离任意 shell 的文件或网络操作。设置页、会话运行信息和输入框分别显示权限与实际隔离状态。

### 权限与预设

会话有两项相互独立的选择。**权限**决定会话能做什么：文件范围、普通审批和命令隔离。**预设**（preset）是会话怎样工作的配方：模型能看到的工具、提示词、模型槽位和预算。任何允许的预设都可以搭配任何允许的权限，例如 `agh --preset ptc --permission full-access`，例外见下文。权限不改变预设的工具。

| 权限 | 文件范围 | 普通审批 | 持久能力 | OS 隔离 |
| --- | --- | --- | --- | --- |
| **只读**（`read-only`） | 查看允许范围的文件和公开网页 | 修改与命令执行会被拒绝 | Agent 不写入；管理信任独立 | macOS/Linux 需通过 L1 探测；Windows 此平台命令未隔离 |
| **可修改工作区**（`workspace-write`，默认） | 文件工具可改工作区和明确授权的额外目录；官方记忆经受控提供方访问 | 命令需审批；范围内文件修改预批准，仍服从明确拒绝 | 记忆 off 拒绝，ask 精确 diff 确认，auto 保留归属、大小和 CAS 校验；其他工作区及用户记忆对 Agent 只读 | 命令隔离取决于平台：macOS/Linux 实测 L1；Windows 此平台命令未隔离 |
| **完全访问**（`full-access`） | 工作区内外普通文件；保护目录仍拒绝 | 权限裁决自动允许 | 候选发布与询问模式记忆保留精确授权及硬拒绝，见[例外](#full-access-exceptions) | 配置 L0；macOS/Linux 注册记忆提供方时，有 L1 就用它拒绝记忆树，否则命令不经隔离执行；Windows 无 OS 隔离 |

| 预设 | 设定内容 |
| --- | --- |
| `standard`（默认） | 标准工具集，模型直接调用工具 |
| `minimal` | 只向模型展示 `read`、`grep`、`find`、`ls`，其他工具（包括扩展和 MCP 工具）都不可见。这只限制模型能看到什么，这些工具能做什么仍由权限决定 |
| `ptc` | 程序化工具调用：模型编写代码，通过 `run_code` 调用工具，见[程序化工具调用与工作流](code-workflows.zh-CN.md) |
| `channel` | 聊天频道的部署配方：回复适合聊天场景，审批以卡片形式在会话中等待 |
| `claw` | 无人值守的部署配方：无人能回答的审批会停等。它要求 L1 隔离，因此 `claw` 搭配 `full-access` 会被拒绝 |

创建会话时分别选择：CLI 与无头运行使用 `--preset NAME` 和 `--permission LEVEL`，SDK 使用 `createSession({ cwd, preset, permission })`，Web 输入区提供预设菜单（「默认」项跟随管理员设置的默认预设，以及「最小工具集」「编程工具集」）和独立的权限选择。管理员在 **设置 → 权限与安全** 设置新会话的默认权限和默认预设。profile 的 `presets` 与 `permissions` 列出可选项：

```yaml
presets: { default: standard, allowed: [standard, minimal, ptc] }
permissions: { default: workspace-write, allowed: [read-only, workspace-write, full-access] }
```

本地与企业模板都带这两项（企业模板允许 `standard` 和 `ptc`）。配方与权限各自授权：收窄 `presets` 不改变 `permissions`；没有配置权限块时，内置默认值是 `workspace-write`。省略权限、`--permission default` 与 `permission: 'default'` 均跟随部署默认值，包括明确指定配方的请求。

旧的配方别名 `read-only`、`workspace-write`、`full-access` 已拒绝，`presets.allowed` 中也不能使用。请将 `agh --preset read-only` 改为 `agh --preset standard --permission read-only`。已退役 profile 须使用新的空 `AGH_HOME`，不会转换旧字节或沿用旧信任摘要。SQLite 格式拒绝另按[数据目录恢复](install.zh-CN.md#数据格式与升级)处理，保留 profiles。`--agent` 不能与 `--permission` 组合，由智能体自己的 launch 决定。

已打开的会话保持原有权限。`/preset NAME` 切换预设并保留权限；会改变沙箱约束的切换（包括任何权限变化）会被拒绝，须新建会话。自定义预设若自行写入沙箱或命令审批设置，就固定了自己的权限，会拒绝 `--permission` 选择。

### 无人值守审批

计划任务和 Webhook 触发器使用明确的无人值守策略，不切换完全访问，也不关闭审批。**遇到审批时 → 转人工并通知（默认）**：无人可回答时，运行停为 `waiting_approval`，自动化历史标记“需要处理”。通过 Web 通知及审批收件箱通知 owner；属于已绑定频道会话的运行也向该频道通知。人可以稍后通过正常审批界面回答，运行随后继续。待决期间不派发副作用。

沿用现有 pending TTL。过期后本次为“失败 / 需要处理”，不能显示“已运行”；下次仍可执行，并保留“上次审批已过期”的需处理提示，即使本次成功也可见。上次仍待审批时，下次会在历史明确标记，不静默堆积新的停等会话。每个计划任务/触发器也可选择 **直接拒绝**：无人回答时以 `unattended-refused` 结束该步骤，不伪造人为拒绝或授权；这类运行的轮次也按无人值守处理，不提供需要等待在场用户的工具（见[无人值守的轮次](headless.zh-CN.md#无人值守的轮次)）。缺失 handler、断线都不代表允许执行。

完全访问会话在无人值守交接策略之前自动允许权限裁决，不会因审批停为 `waiting_approval`；其他会话继续遵循转人工或拒绝策略。

### 完全相同的后续调用规则

自动审核的 **以后完全相同的调用（同身份/目录/工具定义）** 绑定全部参数、cwd、actor 身份、工具策略和定义指纹。卡片预览参数（可能截断）、目录和审批模式；绑定值变化后需重新决定，同身份同目录的不同会话可复用。这与会话级工具授权不同。上下文受污染时，即使命中精确人工允许规则也返回人工处理；未污染调用仍可复用该规则。人工规则和模型放行都不能跳过这项检查。

### 硬封锁命令

少数 shell 命令在所有权限模式下都会被直接拒绝，且不产生审批请求：完全访问、`/yolo`、`approvals.mode: off`、已保存的允许规则和任何 grant 都不能改变这一点。该清单内置于代码，不来自 preset，所以清空命令策略的 preset（完全访问就是如此）也无法移除它。拒绝时的错误码为 `POLICY_HARD_BLOCKED`。

| 规则 | 拒绝的命令 |
| --- | --- |
| `rm-root-or-home` | 带 `-r`、`-R`、`--recursive` 且目标为 `/`、`/*`、`~`、`~/`、`$HOME` 的 `rm`，以及任何带 `--no-preserve-root` 的 `rm` |
| `fork-bomb` | `:(){ :\|:& };:` 及改名变体 |
| `block-device-write` | 作用于 `/dev/*` 的 `mkfs*`；`dd of=/dev/(sd\|nvme\|disk\|rdisk\|hd\|mmcblk)*`；`> /dev/sd*` 等 |
| `disk-erase` | `diskutil eraseDisk\|zeroDisk\|secureErase`；`format c:` |

命令前的 `sudo`、`env`、`command`、`exec`、`nohup`、`timeout`、`nice` 会被穿透；`&&`、`||`、`;`、`|` 连接的每一段都会检查；`bash|sh|zsh -c` 的载荷最多递归检查三层。无法解析的命令不会仅因解析失败被拒绝：会对整串文本和能抽出的字面片段做匹配，其余照常走审批。这是命令文本策略，不是解释器，也不是沙箱，足够混淆的命令可以绕过；真正的边界仍是沙箱和路径硬拒绝。

### 命令前缀审批

shell 命令需要审批时，审批卡可以多给一个选择：本会话内，以所给词开头的命令不再询问（例如「以 `git push` 开头的命令」）。前缀由 daemon 计算，客户端原样展示，自己不会拼前缀。只有当命令的每个部分（按 `&&`、`||`、`;`、`|` 切分）在授予后都会被覆盖、前缀词能放进 256 字符的授权范围、且前缀本身允许时才会提供。前缀按白名单提供。只凭程序名提供的，仅限参数无法运行或写入任何东西的只读命令（`ls`、`cat`、`head`、`tail`、`wc`、`grep`、`pwd`、`echo`、`which`、`stat`、`du`、`df`、`date`）。程序加子命令只提供以下组合：`git` 的 `status`、`diff`、`log`、`show`、`branch`、`fetch`、`add`、`commit`、`push`、`pull`、`switch`、`checkout`、`restore`、`blame`、`tag`、`remote`、`rev-parse`、`ls-files`；`npm`/`pnpm` 的 `test`、`ls`、`outdated`；`yarn`/`bun` 的 `test`；`cargo` 的 `build`、`test`、`check`、`clippy`、`fmt`、`doc`、`tree`；`go` 的 `build`、`test`、`vet`、`fmt`、`list`；`uv` 的 `sync`、`lock`；`pip` 的 `list`、`show`、`freeze`。程序必须直接写名字，不能带路径。组合后面的选项同样按每个组合各自的白名单（例如 `git status -s`、`git commit -m`、`git push -u`、`cargo test -p`、`go test -run`）：被覆盖的命令带有其他选项、缩写或合并的选项、或 `--` 之后的选项时照常询问；`git fetch`、`git pull`、`git push` 的 refspec 含 `+` 或 `:`（强制更新或删除）时总是询问。看起来像凭据的词永远不进前缀。授权命令从项目本身运行的内容（测试脚本、git hooks）属于授权范围。

对于能运行项目代码的前缀，TUI 和 Web 审批卡会明确说明授权也涵盖项目脚本、git hooks 和构建代码；`agh approvals suggest` 显示同样的提示。

前缀授权只在本会话有效，按整词比较而不是文本前缀：`git status` 覆盖 `git status -s`，不覆盖 `git statusx`。只有检查器完全理解的命令才会被覆盖：重定向、替换、变量、通配符、分组、后台 `&`、注释、行首的 `NAME=value` 或保留字、换行都会让命令变成不透明，不透明命令照常询问。前缀审批只适用于普通的一次性 POSIX shell 调用：后台或持久 shell、已有 shell 会话、PowerShell 等其他解释器（即 Windows 上的所有 shell 调用）、含非 ASCII 字符的命令、工作区之外的工作目录，都不会提供或认可前缀授权。前缀授权不会越过「始终要求审批」的工具、污染上下文、要求审批或拒绝的规则以及硬封锁。`agh approvals grants` 与 `/grants` 把它显示为 `prefix: git push`，`agh approvals revoke` 可撤销。不认识前缀审批的客户端仍然看到并回答原有选项。

<a id="full-access-exceptions"></a>

### 完全访问不改变什么

会话已解析的权限为 `full-access` 时，全部权限裁决在所有平台自动允许，不再弹出审批。包括候选测试与发布（安装、信任、启用及能力变更）、Skill 导入、MCP 注册／启动、询问模式的记忆写入、工具请求的凭据管理、主体审批。每项决定保留执行者、精确操作绑定和 `full-access` 原因；Trace 与执行证据显示 **自动允许（完全访问）**。其他权限级别保持原有人工审阅流程。预算超额报价属于权限裁决；配置中的预算硬拒绝仍会阻止请求。Skill 安装在整个后台任务期间保留精确、可撤销的授权及取消信号，在回执持久化后、原子发布文件前及每项资源操作前重新校验。MCP 注册、信任、本地启动批准及启用分别重新核对已消费、绑定精确配置的授权与有效期。收窄权限、关闭会话、取消、过期或执行者改变会阻止剩余操作。 Skill 资源日志在排队写入、发现刷新与状态协调期间携带同一私有租约，在取得队列中的当前状态及文件刷盘后、原子发布前重新核验当前授权与期限。尚未完成的自动操作在重启后需要新的授权才能继续；人工管理保留原有恢复路径。

插件安装、更新、信任和启用将同一私有授权租约传入 profile 锁事务，在获得锁和异步工作后、临时文件刷盘后及原子发布前复核。运行时目标发布在串行队列和持久事务内复核；运行时应用后发生拒绝时恢复上一运行时。询问模式记忆写入将已消费的精确决定传入 SQLite 提交锁，在文件 rename 前再次检查当前会话 epoch 和期限。拒绝时清除未发布的临时文件；人工管理保持原有路径。

自动权限结果绑定后端会话身份和授权 epoch。切换预设会撤销待处理的自动授权与未消费结果；已消费的副作用回执保留为历史。后端在日志持久化后和副作用准入前再次校验 epoch。候选自动发布还要求候选来源会话与当前会话一致。私有 `permission-decisions.jsonl` 授权日志保留精确的非秘密会话、调用、范围、哈希、操作者、时间与消费状态，省略自由文本摘要；通用审计脱敏规则不变。扩展的普通问题（`decisions.request`）和未知用途不会因按钮形状而成为权限；业务确认遵循下述明确合同。ask_user、计划退出、事实核对及作者自由提问仍需人工内容。

私有效果准入统一使用后端证明载体（`@agnes/protocol` 的 `permissionEffectAdmission`）。异步验证与最终同步提交或 CAS 内的 `assertActive()` 保持分离；载体保留取消、过期、会话 epoch 和上游准入检查，任一检查失败后永久失效。各业务模块继续核对自己的对象、版本与持久消费状态：memory 文件摘要、候选及包摘要、凭据引用、Skill 行及业务决策。一次发布可以包含多个获准提交；该载体不替代持久重放检查，也不承诺外部效果恰好发生一次。

由 App Server 持有的效果，其自动权限租约还会在最终提交时同步检查 supervisor 持有的 epoch 撤权屏障。full-access 和 preset 切换会先等待撤权确认，再记录切换；会话关闭在报告成功前等待确认，包含继承的子会话授权。请求返回后，后台任务仍受该屏障约束。延迟到达的 worker 快照或取消通知不能恢复已撤销的租约。运行中会话的工作区隔离策略保持固定；更改策略需要关闭旧会话并新建会话。仅有异步快照验证器不能签发自动效果租约。


候选作者测试在 macOS/Linux 保留 Host OS 沙箱，只运行独立候选副本；POSIX 沙箱缺失时仍拒绝执行。Windows 仍无隔离。完全访问下所有平台自动允许精确哈希的测试决定；`workspace-write` 权限 仍展示包名、哈希、执行方式、风险和范围，要求一次确认。哈希变化后拒绝旧授权。决定保存在 `candidate-test-audit.jsonl`；测试本身不发布。完全访问下提交通过测试的候选，会自动完成现有安装、信任、启用和运行时激活事务。

受监管电子签名属于业务行为，独立于工具权限。示范应用通过公开决策端口以 `business.confirm` 请求质量记录、GMP 放行、MRB 处置、技术状态更改、规则启用与归零关闭签名，绑定审阅参数、修订与签名含义。完全访问包含这些业务确认：宿主代表选择该权限的会话真人提交声明的精确 `presentation.responseValue`，明确记录 **完全访问下自动确认**，不得冒充人工点击或模型／系统签名。Core 授权日志（`decision/state`）、业务回执、审计与放行证书／关闭记录均保留该身份、模式及原决策绑定。只有明确的单次 `allowed-once`／`rejected` 合同及声明的签名值可自动确认（优先 en，其余语言键按码点排序）；缺失、歧义或不符合响应 schema 的合同保留人工请求并记录原因。其他权限仍须真人回答。单次消费和私有写入凭证在事务提交前保留原 sessionId、epoch、取消及有效期校验，提交前收窄权限会阻止写入。嵌套业务写入会把全部准入凭证保留到最外层事务，真实提交前逐一复核，包括已成功返回的内层调用凭证。拒绝、取消、过期及旧修订仍不能签署。

`ask_user` 等用户问题、用户明确选择的计划／只读模式、对 AGH 私有 `secrets/`、`auth/`、`profiles/` 的普通文件工具硬拒绝，以及 edit/write 的先读后改和过期读取检查保持有效。选择完全访问本身可以保留一次授权确认。未知外部效果的事实核对不是权限授权，不能自动断言已经发生。

需要允许工作区外文件时，显式使用 `agh --permission full-access`。macOS/Linux 没有可用 L1 时，命令不经隔离执行，已安装的记忆 provider 保持启用；记忆文件在 provider 之外被改动时，下一轮会显示提示。Windows 使用可信本机后端的“未实现”例外，保留记忆 API 权限。可在 profile 中设为新会话默认：

```yaml
permissions:
  default: full-access
  allowed: [read-only, workspace-write, full-access]
```

若要保留审批，可在自定义配方明确覆盖 `sandbox: { level: L0, required: false, on_unavailable: allow }`，这样的配方固定自己的权限设置；没有已安装 provider 要求私有文件隔离，或可信 Windows 本机后端声明未实现时，才可执行未隔离命令。L0 不允许搭配新条件值。仅修改 `on_unavailable` 不会覆盖 `required: true`。Web「完全权限」和 `/yolo` 不会取消所选预设的 OS 沙箱。当前 L1 后端拒绝非空命令网络主机白名单；`web_fetch` 使用独立的公网访问策略。Profile 可以在启动时选择另一个沙箱提供者，见[沙箱提供者](sandbox-providers.zh-CN.md)。当前进程会保持这个选择，直到再次启动。

经审阅的自定义 preset 可声明 `sandbox: { level: L1, on_unavailable: deny, loopback_serve: true }` 来运行本地网页。目前仅支持本机 macOS Seatbelt。命令批准后，Host 独占绑定到数值地址 `127.0.0.1` 的 TCP listener，将连接转发至通过继承的文件描述符交给命令的私有 Unix listener。应用获得 `AGH_LOOPBACK_FD` 与真实的 `AGH_LOOPBACK_URL`。Node 应使用 `server.listen({ fd: Number(process.env.AGH_LOOPBACK_FD) })` 并在监听后打印该 URL；无 socket activation 的部署仍走原有端口分支。不支持继承 listener 的程序不能使用此能力。应使用普通前台或后台 shell 命令；持久 shell 会话和 PTY 的进程寿命超出单条已批准命令，因此明确拒绝。沙箱拒绝一切新建 IP 监听（含回环和通配地址）、UDP 和主动连接。Seatbelt 的 `localhost` 过滤也覆盖本机其他地址，不能用它证明仅回环绑定，因此由 Host 预先提供已经绑定的 socket。该描述符是私有传输，公开地址必须使用 `AGH_LOOPBACK_URL`，不要从 `server.address()` 推导。已批准的命令结束、取消、超时或沙箱实例释放时，Host 关闭公开 listener 和所有转发连接。即使后代进程复制该描述符并脱离进程组或转为 daemon，也无法保留公开服务能力。Unix 主动连接与新建 Unix bind 仍被拒绝。所有受限 macOS 命令 profile 都保护保留的 `/private/tmp/agh-loopback-*` 传输命名空间及其祖先，阻止路径替换；没有回环服务授权的命令和允许网络访问的 profile 也适用。普通已授权临时文件写入保持可用。Host 固定传输目录及 socket 的 device/inode；路径缺失或被替换时拒绝转发，并在连接建立后、转发任何字节前再次核验。

此声明不能与 `network_allow`、完全访问或无沙箱降级组合。Linux、Windows、远端和外部 provider 明确拒绝；macOS native helper 缺失或过旧也会拒绝。preset 的命令策略仍应要求每条 shell 命令人审；批准仅授权在此边界内运行命令，不开放出站网络。沙箱外浏览器可打开真实监听地址，沙箱内 `curl` 无法主动连接自己的服务。Host 在调用期间保留撤权入口，启动失败也会回收入口。job 取消和工作区释放会先撤销服务能力，再等待进程清理。

本轮工具输出含不可信内容时，后续修改可能需要确认。审批卡保留工具声明的动作标题/说明、目标标识及审批原因；作者应使用用户语言填写 `meta.presentation`。工具参数和输出不能为后续动作授予权限。

本地 Web 的安全边界是回环监听及精确 Origin/Host 校验，不是互联网用户认证。不要直接把它暴露到公网。手动 `--connect` 必须明确指定目标；Windows 命名管道还核对所属进程与发现记录。

Computer Use 是另一个高权限面：本地 profile 有启用配置，但仍需要运行组件、可用模型和操作系统授权。`computer-use permissions grant` 会触发授权流程，`install/restart` 会改变运行组件；只读排查先用 `computer-use status` 和 `doctor computer-use`，不要为文档自动授予系统权限。

## Skill 管理的删除边界

永久删除和优先级变更需要服务端 admin authority 与 `resources.skills.write`，通过 Web 管理 BFF 或 Node SDK 执行。用户优先级覆盖不授予信任或启用，不改变普通插件 API 权限。

磁盘 Skill 的永久删除覆盖所选目录的全部文件；用户级来源可能被其他应用共用。package/runtime 来源不能通过这个接口删文件。删除先核对登记来源、修订及文件身份，受理后不支持取消；部分失败仍保留删除标记、阻止重新启用，允许显式受限重试。同名候选可能接替，仍以其自己的授权状态判断是否可用。完整操作及限制见[Skills](skills.zh-CN.md#永久删除一个磁盘-skill)。

## 密钥和持久数据

本地模型账户使用 `AGH_HOME/secrets` 下的私有文件（macOS 也一样），会话模型适配器读取同一存储。写入凭据时，AGH 会将当前用户拥有、所有者可写且组和其他用户不可写的 home（例如 0755）收紧至 0700；不会修复现有凭据目录或文件，目录须为 0700、文件须为 0600。存储失败会拒绝账户操作，并在 `AGH_HOME/data/audit/configuration.jsonl` 记录错误类别、原因、受控系统错误码和具体路径，不记录凭据内容。设置界面会区分权限错误、只读文件系统与不安全或无效的存储。

Provider 密钥经配置服务存入凭据后端；公开配置只保留 `secret://...` 引用。MCP CLI 拒绝明文 `--token`/`--env` 等参数，只接受受限引用。引用也不是任意读取密钥的权限。

`AGH_HOME` 包含会话、配置、授权、审计和缓存。日志经过限缩不代表会话正文没有敏感信息；导出、截图或公开错误时仍要检查用户输入、工具参数与路径。不要提交 `secrets/`、`auth/`、完整 home、真实 trace 或凭据文件。`publicConfig` 会到浏览器，绝不能装入密钥或 secret 引用。

文件工具与沙箱保护工作区 `.agh/secrets`。Linux 上 Host 在编译命令沙箱前准备祖先 `.agh`：缺失时只以普通权限创建这个 AGH 自有空目录，不跟随符号链接；若已是链接或非目录，以 `E_SANDBOX_WORKSPACE`（`workspace-ancestor-not-directory`）精确拒绝。祖先保留真实挂载锚点，命令不能通过重命名它暴露凭据。`.agnes/secrets` 属于其他产品，不再享有 AGH 隐式防护，也不自动迁移。不要把 AGH 的 home 指到其他产品的数据目录；`AGNES_HOME` 已移除：取消该变量，用 `AGH_HOME` 指向干净的 home。

恢复未知副作用前先核对目标系统，再决定重试。后台数据库恢复并不能撤销已发出的邮件、网络写入或物理设备动作。

持久化合同分别声明账本、metadata/KV、耐久子任务控制、reclaim 和 integrity。完整 Host 要求这五项能力，接受完整非 SQL 提供器，包括 [JSONL 示例](../../examples/persistence/)。同步 SQL 通过可选 `sqlite` 端口（`dialect: sqlite`）提供，依赖 SQL 的第三方扩展须选择支持它的后端。默认包域及 Host 授权/回执存储使用所有者隔离的 metadata。切换需要重启，不自动迁移文件，参见[提供器合同与导出/导入迁移](../extend/persistence.zh-CN.md)。

作者声明 `capabilities: { ledger: true, ... }`，并显式提供 `metadata`、`childControl`、`reclaim` 和 `scanIntegrity`。SQLite 账本和子任务文件保持兼容。授权和回执只存放在 metadata 中；旧授权及回执 SQL 表既不读取也不复制，版本不同的 metadata 命名空间会被拒绝并需要重置。撤权先持久化后通知。

## 包来源记录与来源策略

新安装保存解析后的来源和版本、打包文件树 SHA256、可用的发布者证据、安装时间、安装者及信任决定。`agh plugins provenance <id> --json` 读取记录；App Server 的 `_agnes/v1/packages.provenance` 和 `_agnes/v1/packages.sourcePolicy` 是管理只读方法。审阅对话框和插件详情展示相同摘要。验证发布者不等于隔离插件代码：进程内插件仍需审阅其声明的权限。

安装时验证下载内容；加载安装包和不可变代际快照时重新计算文件树摘要。摘要不一致拒绝加载（`E_PACKAGE_INTEGRITY`）；无效来源证据使用 `E_PACKAGE_PROVENANCE`。旧锁记录继续可读，但不会自动获得已验证发布者身份。npm 有 attestation 时通过 Sigstore 验证，并核对精确包名、版本及实际下载档案摘要；证据缺失显示未验证，证据无效则拒绝安装。

管理端来源记录包含已声明来源的解析位置。诊断消息仍使用固定的安全摘要，不暴露无关本地路径。

官方 Host 能力还要求经过验证的加载器绑定。文件型包恢复时，该所有者的每条保留扩展行都必须携带受支持的 SHA256 修订，且与当前代码树一致；缺失或自定义修订无法证明保留代码，不会获得授权。正常发行升级会为新会话建立新的 pin，旧 pin 不会授权变化后的代码树。打包可执行代码使用 Host 加载器的代码映像身份，不依赖可变的数据目录。

管理员配置 `<AGH_HOME>/profiles/<profile>/package-sources.json`：

```json
{ "allowedSources": "any-with-confirmation" }
```

默认 `any-with-confirmation` 保留绑定摘要的信任确认。`official-only` 只允许签名官方目录中的精确包；`official+npm-with-provenance` 另外允许已验证发布者证据的 npm 包。获取包及加载安装清单时检查策略。策略变化不会悄悄替换运行会话已经固定的代码。

官方目录预留维护者管理的 Ed25519 公钥槽：`officialKeys` 将密钥 ID 映射到 PEM 公钥；`officialCatalog` 保存 `{ "statement": { "keyId", "issuedAt", "entries" }, "signature" }`。每个签名条目绑定 `id`、`version`、解析后的 `source`、`treeIntegrity` 和 `publisher`。签名是 statement 按键排序的规范 JSON 的 UTF-8 字节上的 Ed25519 签名，以 base64 保存。可选签名字段 `mcpDefinitions` 保存完整 MCP 定义经 JCS 序列化后的 `sha256-<hex>` 摘要，只有精确匹配的已验证定义才能取得官方 stdio 默认配置。管理员配置公钥，不接受下载包自带的公钥。测试动态生成开发密钥；生产官方签名密钥及目录由维护者配置。

仓库 `.agh/plugins` 初次发现时禁用且未信任。设置 → 运行详情 → 本地插件 提供含数量的确认，绑定当前插件快照与 `.agh/hooks.json` 摘要。信任记录存于用户 profile，不在仓库。执行输入编辑后须再次审核。Skill 是指令文本，附带代码、仓库 package 脚本与 MCP 配置不会仅因启动会话而执行。命令 hooks 除沙箱检查外，还要求精确内容信任。

Windows 使用 PowerShell 时，没有进程隔离的命令 Hook 还须取得 `commandHooks.trustedUnconfined` 授权，精确匹配配置来源、内容摘要和规范化工作区。Hook 使用当前工作区绑定的 Host 执行接口，由 Host 判断能否执行，包括 `allow-if-unimplemented`、显式拒绝和 `required: true`；授权按每次调用的规范化工作区核对，覆盖其他工作区中的会话。Hook 信任不能覆盖这项判断。未受信任的工作区 Hook 不会进入本次调用；受信任但执行被拒的 Hook 仍按对应事件原有的失败规则处理。macOS/Linux 的隔离要求、工具审批，以及前述 Windows 记忆保护限制均不改变。

完全访问会话会在无人值守策略交接前自动允许权限决定，因此不会因等待审批进入 `waiting_approval`；其他会话继续遵循交接或拒绝设置。
