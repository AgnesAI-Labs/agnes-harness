This is the public contract inventory and readiness assessment for the first **product v0.1** tag. It describes source revision `cbb0eefa99e0218e5c6fac6e87ab50c9a7f71eae`; documentation changes do not change runtime behavior. Extension API remains **1.4.0**. This candidate does not declare a release or an unconditional provider freeze: the open items below still require acceptance.

## Stability and compatibility policy

**stable** identifies an established author contract selected for compatibility protection in v0.1. **experimental** identifies an evolving contract that must be used with matching source, examples and testkit revisions. Neither label certifies production readiness, platform support, arbitrary plugin isolation or npm availability. The candidate policy takes effect when maintainers accept the product freeze; existing preview revisions remain subject to the [preview policy](../maintainers/versioning.md).

For accepted stable contracts, published packages follow semver: incompatible signatures, removals, narrower accepted inputs or changed observable guarantees require a major package version; compatible additions require a minor version; compatible fixes require a patch. Product `v0.1` does not renumber extension API `1.4.0`. Experimental changes require explicit change and migration notes, even while preview versions stay unchanged. The repository's published-package semver rules also apply to experimental exports; this candidate introduces no published-package exception. A published stable interface cannot evade its major-version rule by being relabeled experimental.

Deprecations identify the old name, replacement, compatibility window and migration in the API changelog and both language guides. Stable aliases remain supported for at least one subsequent minor release and may be removed only in a major release. Security-driven exceptions require explicit release notes and recovery instructions. No removal date is assigned here to `ModelAdapter.api` (use `wireApi`), catalog `api`, or the `defineProviderKind` input `restartRequired` (use `scope`; restart is derived). Existing top-level configuration spellings remain supported. Plugin-defined checkpoint and data migrations require their own compatibility decisions; a package upgrade or generation migration does not migrate schemas automatically.

| Identity | Meaning and admission |
| --- | --- |
| Package name/version | Distribution identity and dependency compatibility; independent of provider identity |
| Provider `id` / `version` | Algorithm identity; version must parse as semver; loops support multiple `id@version` registrations |
| `apiRange` / `API_VERSION` | Author contract compatibility, checked from static filesystem package metadata before importing ordinary plugin code |
| `codecVersion` | Loop-owned JSON state format, decoded before resumed work; unsupported versions refuse resume |
| Integrity/code digest, generation id, composition hash | Verified content and session binding, not semver or a permission grant |
| `wireApi` | Model transport format; `Route.api` selects the adapter registration id, not extension API compatibility |

`satisfiesApiRange` supports exact semver, comparators joined by whitespace (intersection), `^`, `~`, `*`, and numeric `x`/`*` wildcards. It does not implement npm's complete range grammar: unions, hyphen ranges and prerelease admission are unsupported. Use a tested range such as `^1.4.0`. See [the implementation](../../packages/extension-api/src/api-range.ts).

## Loop operations and recovery

`LoopFactory` has `id`, `version`, `capabilities`, `codec`, optional `checkpointMode: 'driver' | 'ledger'`, and **synchronous** `create(ctx)` / `resume(ctx, checkpoint)`. Drivers implement `step(signal)`, `cancel()`, `dispose()` and `checkpoint()`. Creation has no separate abort signal: do I/O during signal-bearing operations, not untracked asynchronous construction. Legacy ledgers resolve `agnes.default@1.0.0`; a missing exact pin or unsupported codec refuses execution. Versionless selection must resolve to exactly one loop version.

High-level recoverable operations are `turn.continuation/checkpoint/finishCancelled/finishFailure`, `model.respond`, `tools.drain`, `compaction.run` and `wait.poll`. The driver chooses the next edge; these operations keep the Core-owned ledger continuation. `@agnes/loop-default` uses these same public ports, with `checkpointMode: 'ledger'`; its stateless codec accepts the historical version-1 checkpoint without exposing private program-counter shapes.

Low-level authors use `input.accept/claim('next-turn' | 'next-step')`, `turn.view/endStep`, `prepareRequest/estimateRequest`, `model.stream/complete`, `tools.execute/batch/resume`, `events.assistant/finish/emit`, `effects.status`, `checkpoints.read/write`, `wait.park/wake/delay`, `jobs.status/join` and optional `children`. `next-turn` re-enters the accepted input until finished; `next-step` claims steering inside that turn. The frozen turn view includes post-compaction history, tool schemas, effective model capabilities, prompt/runtime sections and budget. Prepared requests are bound to the current turn and original object; cloning a request or supplying hand-built request stamps is refused. Estimates are advisory, can be unknown, and neither send nor reserve budget.

Scheduling follows `outcome: 'running' | 'idle' | 'turn-ended' | 'parked'`, never display `phase` or reason alone. `loopShouldStop(result, until)` is shared by production and testkit. `until: 'turn-end'` stops at any ended turn; `until: 'idle'` may continue a completed turn to consume queued inputs, but stops on other end reasons, idle or parked. `events.finish` closes the observable turn. Approval parking closes the turn after siblings drain; reopen with `input.resumeParked`, then resume the **original** invocation with `tools.resume`. Waiting on another approval reports `E_LANE_BUSY`; uncertain execution refuses replay.

Core applies step/credit admission, principal authorization, approval bindings and media/request validation through the public effect paths. Batch results retain input order; only declared concurrency-safe calls may overlap under the runtime policy. A low-level model response is not automatically an assistant history row: commit it with `events.assistant(message, checkpoint)`, which atomically persists both. `events.emit(type, data)` remains a broad ledger append port; it is experimental and is not a substitute for request derivation or authorization.

Use explicit stable `invocationId`s for recovery. Status is `not-sent`, `may-have-sent`, or `responded` (which may be an error result). Reusing an identity for a different operation refuses; recorded responses may be returned without redispatch. The uncertainty fence precedes external dispatch. `checkpoints.write(checkpoint, {invocationIds})` records associations, not an atomic external-effect commit. A crash after a tool response but before its loop receipt can recover the original response; a model crash without a durable complete receipt stays uncertain. No exactly-once external effect or managed network send fence is promised.

Child start status/adoption reconnects only the original parent-scoped creation. Unsupported or missing adoption refuses a new start under the old identity. Job status/join requires an original durable deferred-job marker; join atomically publishes that tool result and never advances a scheduler edge. Cancelling join does not cancel the external job. `await wait.wake()` commits a lane-local, coalescing wake; cancellation consumes none, and checkpoint acknowledgement prevents restart redelivery. `wait.delay` is a cooperative delay, not a persisted timer schedule.

### Event waterfall

Core operation paths trigger `before_model_request`, `after_model_response`, `before_tool_call`, `after_tool_result` and `turn_end`. Existing corresponding request/tool hooks run once before registered Loop listeners; listeners run in registration order over detached payloads. Before-model patches merge (sampling/metadata by field); before-tool denial is terminal; valid after-tool result transforms feed the next listener. Observer failures/timeouts are skipped; before-request/before-tool failures abort the operation. The current listener timeout is 2000 ms. See [dispatch](../../packages/core/src/loop/events.ts).

Dispatch is per operation/attempt, not globally once across retries or crashes. `events.dispatch` remains optional in the structural port, and manual author dispatch can duplicate notifications. Do not claim durable exactly-once events or mix manual dispatch with Core-managed operation notifications.

| `loop` | Factory/driver/codec and public ports above; exact persisted identity and codec validation precede resume |

Credentialed community adapters must implement `bindCredential`, called at the route boundary. Stream options include signal, session key, tool names, timeouts, optional `retry: false` and `reportSent`; adapters do not mint Core sent stamps. | `tool-runtime` | Async-capable `create({maxParallel}, signal?)`; `execute/batch` schedule only through `execution.dispatch`. | `tool-policy` | `decide(input, signal)` returns `allow/ask/deny` plus reason; refusal/failure cannot widen principal permissions, preset policy or sandbox constraints. | `persistence` | Async-capable `open({dataDir, clock?})`, then `open/commit/renew/release/scan/registers/close`. Commit checks writer lease/CAS and atomically assigns seqs, materializes registers, integrity and optional op state. Scans must be bounded: pages cap at 500; an oversized full read refuses instead of truncating silently. Metadata transactions are synchronous atomic callbacks, never promises. | `sandbox` | Async-capable `create({workspaceRoot?, options?})`, optional measured `probe`; instance `exec`, `capabilities`, `dispose`, optional `openProcess`. Host passes workspace/digest, read/write allow/deny, network mode/hosts and required enforcement per call; denies win. Local and third-party execution use the selected instance. Missing policy, capability, platform or enforcement refuses before spawning; result reports actual enforcement. Backend id is fixed at startup; instance reuse is keyed by workspace/options. Constructor has no abort signal. Process `close` kills the tree and joins exit; PTY/JSON bridge support must be explicit. |
| `child-agent` | `start(task, options)` and optional `adopt/list`; handle `events/sendMessage/interrupt/result/dispose`. Follow-up receipt means accepted, not answered. Parent-bound facade fixes session/cwd/generation, applies provider/model allowlists, tool deny/allow and credit ceiling; child options may only narrow constraints. Empty allowlists forbid all; unsupported capabilities refuse. Parent abort requests cancellation; facade/unregister drain creating children and handles, report cleanup failures and are idempotent. Provider creation, instances and calls belong to their registration owner. Stop admission, abort where supported, join admitted work, dispose instances, then clean registration resources; await unregister before releasing dependencies. Session close requests cancellation and drains producers before shutting hooks, ledger and workspace lease; cleanup failures are retained/aggregated. Cancellation is cooperative: non-settling provider work can keep unload pending. Persistence and sandbox constructors, and synchronous Loop factories, do not satisfy a universal signal-bearing async-construction contract.

## Registration, selection and restart scopes

`ctx.providers.register(kind, sourcePackage, provider)` / `resolve(kind, selection)` infer built-in kinds through `KindMap`; custom kinds require the exact `defineProviderKind<T>()` token installed by their service. A token with the same spelling and different identity refuses. The verified plugin owner supplies source identity; conflicting claims refuse. Catalogs are immutable and expose kind/id/version/source/capabilities/scope/restartRequired/active/selectedFor without factories or credentials. Active means selected configuration, not live session count. Named service facades remain available.

`ProviderError` codes are `E_PROVIDER_DUPLICATE`, `E_PROVIDER_UNKNOWN`, `E_PROVIDER_INVALID`, `E_PROVIDER_INCOMPATIBLE`, `E_PROVIDER_UNAVAILABLE`; fields are `kind`, optional `provider`, `operation`, `retryable` (default false), optional `hint` and original `cause`. Branch on codes, not text. Host/package/Core facades can still translate failures (for example loop resolution becomes `E_LOOP_MISSING`, package admission becomes `E_API_RANGE`, and sandbox validation retains some Host errors); universal provider-error normalization is an open item.

Canonical provider config in an enabled package's `config` is `<kind>: {provider, version?}`. Existing root `loop: {id, version}`, `compaction: {engine}`, `persistence/sandbox: {provider}`, model `provider.adapters`, preset `tools.runtime` and `approval.policy` stay supported. Explicit top-level selections override package config; conflicting package selections, missing identities/versions or ambiguous loop versions refuse instead of fallback. The composition patch has its own typed field names below; canonical package blocks are not arbitrary new root keys. Other current provider kinds refuse duplicate ids even with different versions.

| Kind | Scope | Effective change boundary |
| --- | --- | --- |
| loop, tool-runtime, child-agent | session | New sessions use the selected code generation; existing sessions retain their binding |
| model-adapter, compaction, tool-policy | generation | Rebuild generation-owned registry/runner; existing sessions retain code, with live model configuration exceptions below |
| persistence, sandbox | process | Restart process/worker with compatible backend; do not move open stores/processes |
| Custom workspace kinds | workspace | Restart/recreate the owning workspace deployment; catalog derives restart required |

`providerRestartRequired(scope)` is true for workspace/process. That metadata does not override generation publisher restrictions: fitted backend/platform changes and incompatible bundled implementation replacement can still be restart-required. A browser refresh only reloads client assets; it cannot replace backend code pinned to a session. Changing startup API surfaces, saved admin bundle selection or non-model backend configuration needs restart.

## Pinned code, live resources

Sessions persist both code generation and composition. Packages, Loop identity, provider implementations, tool implementations and generation-routed client modules remain bound across close, hibernation and cold restart, provided the exact snapshot and compatible deployment remain available. New sessions use the current published generation. Disabling code stops new bindings; retained code drains after durable pins release. Disabling code and revoking current resource/authorization access are different operations; a pin grants no continuing permission.

MCP definitions and Skills are live, filtered by the session's composition and trust. Changes become visible at the **next turn**, with the current turn retaining its snapshot. Disabling/removing an MCP server removes it from subsequent turns of retained sessions. Unchanged effective MCP transport configurations share reference-counted connections within a worker and opener/policy/credential boundary; no sharing across workers or credential scopes is promised. Cold resume uses pinned code plus current resources and waits for initial MCP catalog synchronization with a bounded timeout (currently 20 seconds). Historical resource archives are evidence, not the live read source.

Model routes, catalogs and credential-store configuration are live through `Host.applyModelProfile`, broadcast to retained code containers with their own pinned adapter registries. Newly reconstructed containers start with current configuration. This does not hot-replace adapter implementations or non-model backends.

Composition publication is **independent convergence**, not a global atomic transaction. Runtime-target/row updates return a `publication` report; composition `refreshSkillRow/applyModelProfile` return `HostPublicationReport` (ordinary Hosts retain their void results). Reports include operation, per-composition `applied/failed`, `ok` and `recovery: 'retry-same-input'`; all containers are attempted. Successes retain new state, failures may retain old or partially applied state, new containers use the latest desired input. Inspect `ok` and retry the same complete input. `compositionPublicationStatus()` reads the last report; `assertHostPublication` throws `HostPublicationError` carrying it. Worker commands use that assertion before acknowledging success.

Durable historical pins have no time expiry. Closing or hibernating does not collect code. Deletion releases composition and generation pins; explicit migration applies only to a closed session of its existing composition, preserves ledger and exact loop identity, checks both snapshots/deployment compatibility, fences admission and is idempotent. An open/opening session, missing snapshot or incompatible pinned loop refuses before pin replacement. No plugin-state migration is implied. After the last pin releases, the old container/snapshot can be collected; other live worker owners remain conservatively protected. See [generation implementation](../../packages/host/src/runtime-generation-host.ts), [composition publication](../../packages/host/src/profile/composition-runtime.ts) and [MCP pool](../../packages/worker-runtime/src/mcp-connection-pool.ts).

## Package manifests and composition

Ordinary packages declare `package.json` name/version/exports, dependency and license metadata, and `agnes` fields validated by [inspection](../../packages/package-manager/src/inspect.ts). Installation does not execute or enable a plugin. Every filesystem `agnes.plugins` row requires `apiRange`, independently of `hostProvidedExternals`; embedding-created legacy rows can still omit it in the TypeScript shape.

| Manifest field | Accepted meaning/default |
| --- | --- |
| `agnes.plugins[].export`, `apiRange` | Required module export name and tested contract range; incompatibility refuses before code import |
| `id`, `runtime`, `default`, `config` | Optional row id (default `ext:<package-id>/<export>`; `web:` reserved), runtime default `in-process`, default-enabled declaration true, detached JSON config; this declaration does not bypass package enablement |
| `provide`, `inject`, `services` | Optional bounded unique service-name lists; provided/injected metadata must match the export; Surface service names are checked again at dispatch |
| `agnes.kinds` | Optional unique values `tool`, `loop`, `model-adapter`, `mcp`, `skills`, `ui`, `bundle`; package categories are not the eight provider kind names |
| `agnes.capabilities` | Optional network/exec/secrets/credentials scope arrays, filesystem read/write arrays, model/childAgents/ui/device booleans; capability atoms are reviewed and checked against allow/deny ceilings, deny wins; omission is undeclared, not proof of no effects |
| `agnes.hostProvidedExternals` | Controlled external dependency compatibility declarations; not a replacement for row `apiRange` |
| `agnes.bundles` | Static named documents with `extends/profile/presets`; requires kind `bundle`; references do not install companion packages |
| `agnes.contributions`, `surfaces`, `clientDescriptors` | Declared assets/API surfaces/browser contributions; loader validates paths, schema, containment and allowed services; immutable public client config must contain no credentials |
| `agnes.extensions` / `agnes.extension.json` | Retired for filesystem third-party backend admission; migrate to ordinary plugin rows; existing builtin/embedding extension types remain exported |

The exported `ExtensionManifest` schema still contains required `id/version/apiRange/entry/capabilities`, optional `contributes/provides/lease/runtime.supports`. Its capability vocabulary is tools prefix/names, `tools.invoke`, hooks, slots, events, UI skin/client, resources, network/publicRead, artifacts, subagent, services and projections. Skin contributions have `id/name/css/tokens`; client contributions have `id/entry/styles/slots/slotCatalogVersion/services/projections/legacyRowIds/publicConfig` (projections are reserved and grant nothing). This is distinct from ordinary package permission declarations. See [schema](../../packages/protocol/schema/extension-manifest.json), [skins](skins.md) and [client modules](frontend.md).

Bundles resolve parent-before-child once, reject cycles/unknown ids, and apply later selected bundles last. Precedence is profile bundles → direct profile composition → legacy top-level provider choices → preset bundles/composition → saved admin bundles → explicit session patch. Row layering retains deployment → composition → explicit user/workspace overrides. Patches accept `loop`, `modelAdapters`, `compaction` (null disables), `persistence`, `sandbox`, `packages`, `plugins`, `toolPolicy`, `tools`, `mcp`, `skills`, `uiModules`, `surfaces`, `shell`. Arrays replace, package refs merge by id, tool policy/plugin rows merge by field, row config replaces whole. Empty tools/MCP/Skills lists preserve defaults; empty surfaces means headless; explicit empty shell modules/slots loads none. Deny wins and choices cannot enable untrusted/disabled packages. Catalog validation occurs before executable admission; static `agh config dump` alone does not prove runtime availability. Sessions/children retain their composition; changing generation-owned choices through a live preset switch refuses. Full field semantics: [bundles and profiles](../extend/bundles-and-profiles.md), [compiler](../../packages/host/src/profile/composition.ts).

## Author helpers, testkit and surface audit

`@agnes/plugin-runtime` exports `defineProvider`, `defineLoop`, `defineModelAdapter`, `defineToolRuntime`, `defineToolPolicy`, `defineCompactionEngine`, `defineSandboxProvider`, `definePersistenceProvider`, `defineChildAgentProvider` and tool/plugin helpers. Early definition checks preserve inferred types; Host performs admission again.

### Remaining open items

## Known limits and verification scope

Recorded local development is macOS with Node 24; this documentation task used Node **24.20.0**, pnpm **10.34.5**. Linux and Windows need independent native build, sandbox, process, restart and installation acceptance. Seatbelt/bubblewrap/Windows capability reports must be measured in the deployment; a provider declaration is not proof of enforcement. Remote workspaces cannot select an alternative local sandbox provider. No running process/open file/store migration or arbitrary in-process plugin sandbox is promised.

The persistence ports now separate optional SQL from required Host capabilities. The [JSONL example](../../examples/persistence/README.md) implements the full Host ports and has [contract tests](../../examples/persistence/test/contract.test.ts) and [process recovery cases](../../examples/persistence/test/recovery.e2e.test.ts); these were not run here. Its in-memory journal index targets small local deployments, without compression/compaction or network-filesystem/Windows durability acceptance. No complete production non-SQL backend is qualified by this task. Strict managed model egress, credential provenance and send-fence guarantees are outside this freeze. MCP prompts, resource-image mapping and session OAuth, plus configurable Skill roots/slash compatibility, remain bounded by the [MCP/Skills support matrix](../guide/mcp-skills-support.md). Generic ports and examples do not establish external engine, SSH/PTY, device or workflow product support. MHS/device integration remains unverified.

The source remains a developer preview: package publication, public registry startup, third-party dependency resolution from release artifacts, real remote model credentials, full daemon/browser acceptance, platform isolation and heavy crash/restart suites were **not verified by this documentation task**. Existing source tests are evidence of intended coverage only. Documentation verification, targeted lint and direct runtime snapshot comparison are the checks for this change; final release owners must record actual broader results against the candidate revision. No version was bumped, tag created or package published.
