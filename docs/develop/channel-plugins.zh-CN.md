# 渠道插件

[English](channel-plugins.md) | 简体中文

统一渠道桥接由后端持有。每个平台通过公开的 `@agnes/plugin-runtime/channel-contract`
提供一个可独立安装的适配器，不复制通用 runner，不自行发现 daemon，也不读取凭据文件。
Harness 不内置任何 IM 平台适配器。

底座复用现有渠道 runner 和 daemon 当前 profile 的受管资源。
`profileRuntime.registerChannel` 同时登记 `channelKind` 提供者和名为 `channel` 的受管资源。
标准 profile 服务 `channel.configuration/configure/status/check/retry/reconcile`
保留原生效果审批、包信任、激活检查和关闭确认。daemon 负责装配桥接工厂；未提供工厂的嵌入式 Host
会拒绝登记渠道，插件不能自行指定另一条后端连接。

配置中的 `instances` 为实例数组。每个实例有唯一 ID、绝对工作区路径、智能体引用及凭据引用。
凭据只接受 `secret://` 引用，由后端连接时解析，同时受插件声明的 `secrets` 授权范围限制。
适配器额外配置须为非敏感数据。每个实例独立持有 SDK 日志和出站回执；实例 ID 参与会话命名空间，
因此同平台的不同企业不会混用会话。既有会话授权、参与者绑定和审批防重放仍由 runner 与 daemon 持有。

该可选作者 API 随 Extension API 5.5 增加，既有插件和通用 runner 保持兼容。
旧钉钉 YAML 不自动导入：管理员须创建 AGH 凭据并配置引用；升级不删除旧文件或会话数据。

首版复用 daemon 内的 profile 受管资源生命周期，不新增系统服务或另一套进程监督器。
将来可在同一合同后替换为进程隔离实现。无状态的适配器工厂按 generation 发布，支持插件启停和更新；
运行中的连接始终由当前 profile 资源持有，不属于某个会话或其旧代码快照。

Extension API 5.6 增加统一的“插件 → 渠道”配置页及输入框旁的“渠道绑定”入口。
配置通过原生 `channel.configure` 审批保存。提供者可声明非敏感 `configSchema`，凭据仍只使用引用。
插件额外声明 `channelServiceCapabilities()` 后，Host 注册当前会话的查询、绑定、解绑服务。
绑定只能选择本实例已接收过消息的聊天目标，且实例工作区必须与后端授权会话相同。
未绑定的聊天不会自动创建会话。绑定只从当前投影序号之后转发，不导出历史；重新连接后须收到目标消息确认。
每实例每会话最多一个目标，每目标最多一个会话。解绑先暂停并排空转发；不确定的切换持久化为待核对状态，不能自动恢复。
原生审批仍在 AGH 界面处理；绑定不会把既有审批转发到聊天。更多 IM 适配器可以复用相同界面和桥接。

浏览器 SDK 对控制面的限制保持不变。页面通过本地固定渠道 BFF 调用，BFF 校验同源、方法和参数，
并从当前渠道目录核对提供者；会话所有权、工作区与原生命令回执仍由后端校验。

会话绑定弹窗和连接总览复用插件声明，不内置渠道品牌列表。固定同源 BFF 根据授权会话读取工作区及智能体、生成实例标识，并合并当前受管配置；配置摘要用于拒绝过期页面覆盖其他连接。原生审批、操作回执和绑定版本检查仍是最终权限边界。总览的会话名称只取自当前连接可读取的会话，其他绑定不暴露身份并禁止换绑。移除或替换实例时清理不再使用的绑定元数据，恢复旧配置也不会恢复旧路由。

绑定会话支持双向文本同步：AGH 用户提交的新消息会以“来自 AGH 的用户消息”发送到聊天目标，智能体回复继续走同一出站队列。渠道入站使用 `channel:<sha256>` 命令关联编号；编号由原生 inbox 保留到 `user/message.commandId` 和用户投影节点，统一出站据此抑制所有渠道输入，避免回环。该编号只用于展示关联与去重，不参与授权。只导出绑定基线后的消息；升级前没有关联编号的旧用户节点不补发。系统输入和引用材料不导出；用户附件只显示“在 AGH 中查看”的提示。旧日志无须迁移，适配器接口及插件权限保持不变。

已激活的绑定每 5 秒通过权威会话投影补充核对，作为实时事件缺失时的恢复路径；每条路由最多保留一次待核对任务，解绑、退役和关闭时取消定时器。核对继续使用绑定基线和持久化出站回执，不重发已送达内容。
