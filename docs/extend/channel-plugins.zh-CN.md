# 编写 IM 渠道插件

[English](channel-plugins.md) | 简体中文

[完整接入开发手册](channel-bridge-integration.zh-CN.md) · 代码示例、附件、绑定与验收。

后端提供统一渠道桥接，各个平台分别发布独立插件。仅安装 Harness 不会连接任何 IM 账号。

从 `@agnes/plugin-runtime/channel-contract` 导入适配器合同、`channelKind` 和
`CHANNEL_CONFIG_SCHEMA`。在包清单中将此模块声明为宿主提供的 external，保持 kind token
唯一。Extension API 5.5 增加可选入口
`ctx.profileRuntime.registerChannel(provider, { instances: [] })`。

提供者包含 `id`、`version`、通过校验的协议 `ChannelManifest`，以及返回 `ChannelAdapter` 的
`create({ config })`。适配器只处理平台协议与呈现，必须响应取消并在 `disconnect` 释放连接。
底座登记时保存清单及能力上限的不可变快照，不接受实例返回不同清单或超出声明的能力。

声明 `inject: ['profileRuntime', 'services', 'providers']`、`store: true`、审核过的网络范围、
明确的 `secrets` 范围（精确引用或 `secret://namespace/*`），以及 ID 为 `channel`、scope 为
`profile`、artifact 为 in-process 且启停超时有限的 `managedServices`。
同时声明 `managedServiceCapabilities('channel', CHANNEL_CONFIG_SCHEMA)` 返回的服务。
单独登记目录中的提供者不会创建连接，应使用 `registerChannel` 取得受管生命周期。
未装配 daemon 渠道桥接的嵌入式 Host 会拒绝登记。

每个实例须指定唯一 ID、存在的绝对工作区、可用智能体引用（或 `default` 表示通用助手）、`allowFrom`、`requireMention`，
以及凭据名到 `secret://` 的映射。只有平台清单声明的凭据名和插件审核范围内的引用才能解析。
适配器的 `config` 只存非敏感参数，密钥须放入凭据系统。
包配置是初值；通过原生 `channel.configure` 提交的受管覆盖值优先，应继续从同一入口维护。
标准插件配置界面和 `agh plugins config` 命令都可提交初始配置。

后端持有会话命名空间、智能体启动授权、SDK 发现及日志、持久化出站回执、排队重连、
身份及审批转发和关闭确认。退役时立即停止接收，并拒绝退役后调用适配器。
无法确认关闭时进入原生受管资源恢复流程，不能盲目重放结果未知的外部操作。

先使用假网关验证生命周期和拒绝路径，再分别完成真实平台核验。
参见[架构及兼容性](../develop/channel-plugins.zh-CN.md)。
Extension API 5.6 提供“插件 → 渠道”连接总览，按渠道展示多个机器人连接、会话名称、聊天对象及连接状态。
总览按渠道折叠分组，每组默认预览 3 个连接；可查看其余连接或全部展开、收起。
实例行优先展示会话与状态，展开“详情”可查看工作区、实例标识并解绑或换绑。
搜索会话、聊天对象、实例标识或工作区会展开所有匹配连接，不受预览数量限制。
输入框旁的“渠道绑定”打开紧凑弹窗，动态列出已启用的渠道插件；新增插件无需改动前端。
入口仅在已有会话加载完成、可编辑且连接就绪后显示，并等待首次渠道状态读取完成；加载中、只读、断线及新会话草稿不显示。已绑定时显示渠道图标、名称和同步状态，点击直接编辑该连接。
在弹窗中选择渠道、填写凭据与平台参数、完成原生审批，再确认聊天对象，即可绑定。
实例标识、工作区和智能体由后端根据所选会话自动生成，不需要用户填写。
已有连接可在总览中配置、解绑、换绑到其他会话；换绑会替换旧连接，原聊天目标须重新确认。
提供者可声明 `configSchema` 展示非敏感的平台参数；额外审核并声明 `channelServiceCapabilities()`
提供的三个 session 服务后，Host 自动注册当前会话绑定入口。新会话草稿须先发送消息创建会话。
先向机器人发送消息（群聊需 @），再刷新目标列表。绑定只允许相同工作区与已确认目标，
只同步绑定后的新消息。未绑定聊天不会自动创建会话，原生审批保留在 AGH 中处理。
通用助手会话可直接绑定，无需安装角色智能体插件。绑定始终沿用所选会话的智能体；如需官方默认智能体，先用通用助手创建会话再绑定。
重连后目标显示“等待确认”，收到机器人消息后恢复；待核对状态须显式解绑，不自动重放未知操作。

卸载渠道插件会在停止运行并提交卸载后，清理该插件在当前 profile 的渠道实例覆盖配置、聊天目标和绑定记录。
重新安装使用插件的初始配置（钉钉插件为空实例列表）。禁用、更新与重启保留配置；凭据及其他插件存储不会被清理。
已有会话的渠道绑定管理使用当前启用插件的服务，继续校验原会话身份与工作区，不切换会话的智能体或插件快照。

删除单个连接：在 **插件 → 渠道** 展开实例的 **详情**，点击 **删除实例**，确认影响并完成原生配置审批，再继续同一次删除。
删除会断开该实例并清理它的聊天目标和绑定；其他实例、已有会话历史和保存的凭据会保留。
配置或绑定版本变化、存在不可访问绑定时会拒绝删除，需刷新后重新审阅；响应未确认时应核对原操作，不宣称删除成功。
资源启动失败但已确认停止时，后端可只读恢复持久化绑定摘要，不启动连接、不解析凭据，也不恢复消息转发。
因此失效连接也能通过同一原生审批删除；停止状态不确定或绑定元数据无法读取时仍拒绝删除。
界面会区分“运行状态不可用”和确实存在不可访问的绑定，不把两者混为一谈。

绑定会话支持双向文本同步：AGH 用户提交的新消息会以“来自 AGH 的用户消息”发送到聊天目标，智能体回复继续走同一出站队列。渠道入站使用 `channel:<sha256>` 命令关联编号；编号由原生 inbox 保留到 `user/message.commandId` 和用户投影节点，统一出站据此抑制所有渠道输入，避免回环。该编号只用于展示关联与去重，不参与授权。只导出绑定基线后的消息；升级前没有关联编号的旧用户节点不补发。系统输入和引用材料不导出；用户附件只显示“在 AGH 中查看”的提示。旧日志无须迁移，适配器接口及插件权限保持不变。

已绑定会话的输入框入口显示实际渠道名称及同步、待确认、断开等状态。每个绑定连接各有入口，点击直接编辑该连接的已保存配置；未绑定会话仍显示“渠道绑定”。配置尚未完成绑定的实例不计入已绑定状态。

## 渠道图标

从 Extension API 5.11.0 起，插件可以通过 `manifest.icon` 提供 PNG/JPEG 数据 URL，例如 `icon: "data:image/png;base64,..."`（将省略号替换为标准带填充的 base64）。建议在构建时嵌入插件图片，provider 和 adapter 使用同一份 manifest。声明此字段的插件应使用 `^5.11.0` API 范围。

完整字符串不得超过 32768 个字符。Harness 校验图片结构，并限制解码后不超过 24 KiB、总像素不超过 1048576，建议使用不超过 512 × 512 的方形图片。不接受 SVG、远程 URL 或文件系统路径。渠道总览、渠道选择和连接编辑统一展示该图标；未提供、图片无效或加载失败时使用默认渠道图标。已有无图标插件无需迁移，也无需新增权限。

渠道入站附件应通过受支持的会话 API 提交真实 `file`/`image` 内容，由原生附件准入保存并授权原件。仅生成 `attachment://hash` 不代表文件已保存。下载必须有大小限制，部分失败应明确提示且不得暴露凭据或临时下载 URL。只有原生图片准入明确返回数据、MIME 或像素拒绝时，统一桥才会使用独立且稳定的命令标识降级为普通文件并附带说明；结果不确定、授权、存储及配额错误均不触发此重试。音视频原件作为文件保存，不承诺模型具备原生音视频理解能力。

从 Extension API 5.11.0 起，渠道 manifest 可提供 `displayNames: { "en": "Example", "zh-CN": "示例" }`；界面按当前语言显示，缺少翻译时回退到 `displayName`，再到 `id`。每个名称 1–64 字符且不能全为空白。使用此字段请声明 `^5.11.0`，不改变渠道或绑定身份。详见[渠道桥接入手册](channel-bridge-integration.zh-CN.md)。

绑定窗口在尚未收到消息时也保留聊天目标下拉框。目标为空与运行时启动失败是不同状态；刷新只读取状态，不会重启资源。启动失败时，应返回连接配置、重新保存并完成原生审批来重新连接。固定的 `channel-*` 启动错误码区分状态目录、工作区、绑定存储、凭据、适配器、后台连接及平台连接阶段，不暴露平台异常原文或密钥。

从 Extension API 5.12.0 起，主人可以把任一渠道实例的一个私聊配对给插件的托管服务，渠道插件无需改动。渠道桥把已配对主人的文字交给该服务而不是会话；私聊配对期间不能再绑定到会话。详见[让插件服务接收渠道私聊](channel-targets.zh-CN.md)。

从 Extension API 5.13.0 起，平台报告用户回复或引用了哪条消息时，请在 `MessageEvent` 上填 `quotedMessageId`，取值与你的 `send` 为那条消息返回的编号相同。已配对的服务可以发带按钮的卡片。点击请报告为 `cardAction`：`cardBizId` 是被点消息的编号（或你的 `send` 返回的 `cardBizId`），`value` 是按钮的 `id`。声明 `capabilities.card: false` 的渠道会收到带编号文字形式的卡片。
