# Session workbench panels

English | [简体中文](workbench-panels.zh-CN.md)

A workbench panel is a presentation contribution. Import the shared `workbenchPanels` singleton from `@agnes/web-client`; do not bundle another copy. Register translations with the host locale service before rendering.

```tsx
import { workbenchPanels } from '@agnes/web-client'
const dispose = workbenchPanels.register({
  id: 'example.notes', order: 40, edge: 'right',
  titleKey: 'example.notes.title', component: NotesPanel,
})
```

The component receives `{ context, headerId? }`. The optional `headerId` identifies a presentation-only dock header action host; panels may portal their icon buttons there. `context` supplies a translator, optional session/resources and host-specific `data`. Bind the identity-bound disposer to the module lifetime. IDs must be unique and order finite. `edge` is `right` or `bottom`. The shell owns tabs, keyboard navigation, collapse and size memory. Removing the selected registration falls back to the first remaining panel. Use `@agnes/web-ui` primitives and both English and Chinese catalogs.

Registration grants no filesystem, process or goal permissions. Use supported session APIs on the authenticated host client. The built-in file panel uses `Session.workspaceList(path?)` and `Session.workspaceRead(path)`; paths are workspace-relative. Listing is lazy and honors `.gitignore`/`.aghignore` (wildcards, directory rules and negation). Preview is read-only, capped at 1 MiB and refuses binary files, symlinks and the installation home. Git status badges are best effort. Mention adds a quoted relative path to the composer without submitting it.

The existing `workbench.panel` slot remains mounted inside the right dock for compatibility. A fresh browser starts with closed docks. Desktop widths are 240–480 pixels; smaller screens use a sheet. Resize separators support arrow keys, tabs support arrow/Home/End keys and Escape closes a dock.

On phones, only one dock sheet is open at a time, including after resizing. Overlay Tab navigation stays within visible enabled controls; closing returns focus to its opener. Mention and record navigation dismiss the overlay before focusing their destination. The in-flow tablet terminal does not trap Tab.

The worker runs list/read inside the session workspace invocation using the same filesystem policy as tools. Native reads open canonical paths one component at a time without following links, retaining the verified descriptor for the bounded read. Missing native support refuses the operation. POSIX uses `openat`; Windows holds real directory handles against replacement and rejects reparse points (local drive paths only). List revisions describe the visible listing. Read revisions are SHA-256 of returned bytes, or explicitly `weak:mtime:size` for oversized files. `observedAt` is the server read time, not a promise that a later preview is current. Git timeout/overflow returns `gitStatus: unavailable` rather than a clean badge.

Git badges use a controlled Host-side `git status --porcelain=v1 -z` in the authorized canonical workspace root (500 ms, 256 KiB). Fixed argv disables optional index writes, fsmonitor hooks and submodule traversal; the environment ignores system/global Git config. Only badges for visible entries reach the client. List/read still deny `.git`, linked or non-directory `.git` metadata is refused, and no Git config, index, objects or stderr is returned.

Ignore matching supports comments, `*`, `?`, `**`, directory rules and ordered negation. Escapes, bracket classes, Git global excludes and re-including a hidden parent are unsupported. The viewer states this subset too.

Register optional `fileViewerActions` from `@agnes/web-client` using `{ id, order, component }`. The component receives `{ context, path, revision }`; it can link a file to an independently registered diff/review panel and actual ledger provenance without granting write or restore authority. Bind its disposer to the module scope.

## Session terminals

Use `Session.jobsRead(jobId?)` to list session jobs or retrieve capped output. `Session.jobsControl(input)` supports open, send, resize, signal and kill; effects use a durable `commandId` (generated by the SDK unless supplied for a retry). The daemon authenticates the session owner and grants only the fixed jobs service. Backend records disclose `owner`, `ownerSessionId`, `id`, `status`, exit code and truncation. UI control is restricted to human terminals; agent jobs can only be followed or detached. Interrupt sends SIGINT; kill ends the process. Explicitly closing a running human tab ends that process. Closing the dock, disposing a panel, switching session or disconnecting only detaches the UI. Processes end on explicit termination or owning Host/session shutdown, and do not survive a daemon restart.

Open and input obey the active session tool policy, including read-only and plan-mode refusal. An authenticated human action supplies the human approval; it cannot bypass preset denial. Open uses the same fitted workspace sandbox as tool execution, with no caller-selected cwd or raw-spawn fallback. Changing sandbox permissions requires a new session; the Host refuses a preset switch that would change the existing workspace sandbox. Errors remain backend facts; output is bounded to 64 Ki characters per stream, and overflow is visibly marked. `terminalScreen` and `terminalKey` from `@agnes/web-ui` share the plain-text VT rendering and keyboard mapping used by settings; terminal bytes never become HTML.

If the OS backend cannot enforce the preset, `session/new` and `session/load` refuse with JSON-RPC `SEMANTIC_REJECTED` (-32011), `data.code: E_SANDBOX_WORKSPACE`, the same fixed cause code and `messageKey: appServer.errors.unavailable`. Later execution refusals retain `SANDBOX_UNAVAILABLE`. Exception messages, paths and backend output are not returned. Explicit full-access retains its existing behavior; unrecognized failures remain errors.

The built-in terminal serializes and batches keyboard/paste input per session and job, with at most 64 Ki characters waiting to send. A full buffer refuses the new input and reports it. A failed send discards the unsent remainder without retrying uncertain bytes. Detaching or switching tabs/sessions discards only unsent UI input; accepted bytes and processes remain owned by the backend.

## Live goal panel

The registered right-edge goal panel reads the existing `agnes/goal` status slot from the live timeline. It shows the objective, phase, automatic rounds, credits and localized blocking reason, with record ID/revision behind a disclosure. The goal snapshot has no ordered step list; round counts describe automatic continuation, not a completion percentage. The popover remains the quick create/edit/control surface. Both surfaces send existing human `/goal` commands through the composer; registration grants no goal authority. Pause, resume, complete and clear follow the backend's state transitions. Closing or removing the panel has no effect on the persistent goal.

## Changed files review

`Session.workspaceChanges({ scope?, path?, expectedRevision? })` returns a read-only review for the current session or latest turn. The built-in panel lists files with added/removed line counts and a per-file diff. Mention inserts a quoted path without sending a prompt. The file viewer's registered review action passes its read revision, so the panel can report changes since that preview. Each request uses current workspace authority and descriptor-bound native reads, including cached ledger projections; symlinks and the installation home remain refused.

Review uses confirmed `write`/`edit` tool effects from this session's ledger. The tools-core extension appends a version-1 `x/agnes/tools-core/file-change` receipt after a successful mutation, containing relative identity, hashes and bounded before/after text. The reader verifies extension origin, owning session, actual tool call/result coordinates, successful result and authorization metadata. A failed receipt append does not undo a completed write; missing evidence is reported as incomplete coverage. Old ledgers and other writers, including shell commands and third-party tools, do not acquire invented diffs. This additive extension event leaves tool parameters and result text compatible.

The window is capped at 500 relevant ledger rows, 100 effects, 50 files and 750 KiB of response data. Each snapshot is at most 16 KiB of UTF-8 per side; a receipt is capped at 60,000 JSON bytes. A diff is capped at 64 KiB and 200,000 line comparisons. Binary, oversized or costly diffs show an unavailable state instead of fabricated counts. An uninterrupted hash chain aggregates the session/turn; discontinuity or a truncated history limits attribution to the latest confirmed effect and is labeled explicitly. Freshness compares the recorded after-hash with the current file revision; oversized current files report unavailable freshness. External edits never enter the agent's historical diff.

Optional `context.openPanel(id, selection)` navigates a registered panel without granting backend authority. Optional `context.openRecord(sessionId, callSeq, resultSeq?)` selects an actual loaded tool record in the existing execution view and returns whether it was found. Cross-session navigation is refused. A record outside loaded history opens that view with a load-earlier notice; it is not replaced with a synthetic trace entry. Neither hook grants write, restore or process control.

Changed-file paths display as plain text, including spaces and Unicode. Diff headers escape control characters to keep newline names from forging header lines. Execution evidence opens `factChainLinks.open({ sessionId, laneId, anchor: { kind: 'tool', toolUseId } })`. The optional evidence `laneId` comes only from matching call, receipt and result ledger lanes. Missing or mismatched lanes and unavailable navigation show an unlinked state; paths never infer request or artifact provenance.
